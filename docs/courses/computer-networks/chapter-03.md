| PCI | 协议控制信息，本层加在 SDU 上的控制信息，通常作为首部 | 填空 |
| SAP | 服务访问点，相邻层间接口面上供上层访问本层服务的位置，有唯一地址号码 | 填空 |
| 请求 | 用户实体请求服务做某种工作 | 填空 |
| 指示 | 用户实体被告知某件事发生 | 填空 |
| 响应 | 用户实体表示对某件事的响应 | 填空 |
| 确认 | 用户实体收到关于它的请求的答复 | 填空 |
| 面向连接服务 | 先建立连接、再按序传送并确认、最后拆除链路，又称虚电路服务 | 单项选择 |
| 无连接服务 | 没有建立和拆除链路的过程，每个分组带全称地址、独立选路，又称数据报服务 | 单项选择 |
| 端口 | 传输层用来标识服务或应用进程的 16 位协议端口号 | 填空 |
| 熟知端口 | 0～1023 之间、固定分配给常见服务的端口 | 单项选择 |
| 登记端口 | 1024～49151 之间、须在 IANA 登记以防止重复的端口 | 单项选择 |
| 客户端口 | 49152～65535 之间、留给客户进程暂时使用的端口 | 单项选择 |
| UDP | 无连接、尽最大努力交付、面向报文并保留报文边界的传输层协议 | 简答 |
| TCP | 面向连接、可靠、基于字节流的传输层协议 | 简答 |
| 累积确认 | 确认序号是期望从对方接收的下一个字节序号，该序号之前已全部正确收到 | 填空、综合应用 |
| 三次握手 | 建立连接时交换 SYN、SYN+ACK、ACK 三个报文段的过程 | 简答 |
| 流量控制 | 让发送端速率不超过接收端缓存承受能力，靠通告接收窗口实现 | 简答、综合应用 |
| 拥塞控制 | 从端到端推测网络是否拥塞，用拥塞窗口调节注入网络的速率 | 简答、综合应用 |
| 慢启动 | 拥塞窗口从 1 个 MSS 开始，每经过一个 RTT 加倍增长 | 填空、综合应用 |

| 快速重传 | 收到同一报文段的 3 个重复确认就立即重传，不等重传计时器到时 | 填空 |
| 快速恢复 | 配合快速重传，把阈值和拥塞窗口都减半后执行拥塞避免 | 填空 |
| AIMD | 加性增加与乘性减小合称，是拥塞控制的基本策略 | 简答 |

### 必背清单

**第 1 节**

1. 【考纲 1.1】协议的三要素是语法、语义和时序关系：语法管“如何讲”，语义管“讲什么”，时序关系管事件执行的顺序。
2. 【考纲 1.2】分层的好处有三条：各层次之间可相互独立，高层不必了解低层的工作机制；有较强的灵活性，便于实现和维护，某层技术变化不影响其他层次；有利于标准化。
3. 【考纲 1.3】实体是每层中产生和接受数据的元素；不同结点上同一层次的实体称为对等实体，它们之间的通信遵从本层协议，除最底层物理介质外都要逐层下传才能实现。
4. 【考纲 1.4】层次和协议的集合构成网络的体系结构，完整的体系结构应包含整个网络的逻辑组成和功能分配；典型的分层体系结构有 OSI 参考模型和 TCP/IP 参考模型。

**第 2 节**

5. 【考纲 2.1】1984 年 ISO 提出开放系统互联参考模型，由低到高分为物理层、数据链路层、网络层、传输层、会话层、表示层和应用层 7 层。
6. 【考纲 2.2】物理层在传输介质上实现无结构比特流传输，并规定数据终端设备与数据通信设备之间接口的机械、电气、功能和规程 4 个方面特性。
7. 【考纲 2.3】数据链路层的功能是成帧、差错控制、流量控制、链路管理和寻址；网络层的功能是数据转发与路由，并进行通信量控制和寻址。
8. 【考纲 2.4】传输层是第一个端到端的层次、也是进程到进程的层次，功能包括复用与解复用、端到端的可靠数据传输、连接控制、流量控制和拥塞控制；会话层负责建立、管理和终止会话；表示层处理数据表示的差别，还可做压缩、加密和字符编码转换；应用层为用户提供应用网络通信的接口。
9. 【考纲 2.5】第 1 至 3 层主要完成数据交换和数据传输，称网络低层即通信子网；第 5 至 7 层主要完成信息处理服务，称网络高层；低层与高层之间由第 4 层衔接。终端设备实现全部 7 层，路由器这类中间系统通常只实现下 3 层。
10. 【考纲 2.6】PDU 是对等层之间按本层协议传送的数据单元，SDU 是上层交下来的数据，PCI 是本层加入的控制信息；PDU 在各层的叫法不同：物理层为位流，数据链路层为帧，网络层为分组，传输层为数据段，应用层为报文。
11. 【考纲 2.7】SAP 是相邻层接口面上供上层访问本层服务的位置，每个 SAP 有唯一的地址号码；N 层 SAP 就是 N+1 层可以访问 N 层的地方。
12. 【考纲 2.8】服务原语有四类：请求是请求服务做某种工作，指示是被告知某件事发生，响应表示对某件事的响应，确认是收到关于请求的答复。
13. 【考纲 2.9】面向连接服务类似打电话，先给出对方全称地址并建立连接，再按序传送并确认，最后拆除链路，又称虚电路服务；无连接服务没有建立和拆除过程，每个分组带全称地址、独立选路、到达顺序不定，又称数据报服务。

**第 3 节**

14. 【考纲 3.1】TCP/IP 的产生：Cerf 与 Kahn 于 1970 年开发出网络控制协议 NCP，1974 年发表第一份 TCP 详细说明，1978 年把路径选择功能分离出来形成 IP，1983 年 1 月 1 日 NCP 停止使用、TCP/IP 正式运行。
15. 【考纲 3.2】TCP/IP 分四层：应用层把 OSI 会话层和表示层的功能合并进来；传输层为不同主机上的进程提供逻辑通信，含 TCP 与 UDP；网络互联层是核心，负责路由选择、分组转发和 IP 寻址；网络接口层只要求向上提供访问接口，具体实现随网络类型不同。
16. 【考纲 3.3】与 OSI 的三点区别：层次划分为 7 层对 4 层，TCP/IP 没有表示层和会话层，把物理层与数据链路层合并为网络接口层；OSI 网络层支持两种连接方式、传输层只面向连接，TCP/IP 网络层只无连接、传输层两种都给；OSI 产生在具体协议之前通用性好但功能归属不清，TCP/IP 先有协议再建模型，与协议配合得好。
17. 【考纲 3.4】网络互联层除 IP 外还包括 ARP、ICMP、IGMP 以及 BGP、OSPF、RIP 等路由协议。

**第 4 节**

18. 【考纲 4.1】传输层用“IP 地址＋端口号”唯一标识通信端点，端口号是 16 位二进制整数；0～1023 为熟知端口，如 21 给 FTP、25 给 SMTP、80 给 HTTP、135 给 RPC；1024～49151 为登记端口；49152～65535 为客户端口。
19. 【考纲 4.2】UDP 首部由源端口号、目的端口号、长度和检验和 4 个字段构成，各占 2 B，共 8 B；长度字段包括首部和数据部分，首部固定故它主要用于计算可变长的数据部分。
20. 【考纲 4.3】UDP 的工作机制：传输前不建立连接、不维护连接状态，一台服务器可同时向多个客户机传相同消息；首部只有 8 B，额外开销小；吞吐量不受拥塞控制调节；尽最大努力交付；面向报文，既不拆分也不合并，保留报文边界。
21. 【考纲 4.4】UDP 适合速率要求高、精确度要求相对较低的应用，如视频会议、视频点播和网络电话。
22. 【考纲 4.5】TCP 面向连接、可靠、基于字节流；它为每个字节编号，段的序号是该段所封装应用数据的第一个字节的序号，确认序号是期望收到的下一个字节序号，即采用累积确认。
23. 【考纲 4.6】TCP 首部：源与目的端口各 16 位，序号与确认序号各 32 位，首部长度 4 位且以 4 B 为单位，保留 6 位，URG、ACK、PSH、RST、SYN、FIN 各 1 位，窗口 16 位，检验和 16 位，紧急指针 16 位，另有选项和填充；选项中的 MSS 只计应用层数据字节数，不含首部。
24. 【考纲 4.7】三次握手：A 发 SYN=1、seq=x；B 回 SYN=1、ACK=1、seq=y、ack=x+1；A 再回 ACK=1、SYN=0、seq=x+1、ack=y+1。前两次不携带数据，第三次可携带数据；SYN 占一个序号，双方数据首字节分别为 x+1 和 y+1。
25. 【考纲 4.8】连接拆除需 4 次握手：A 发 FIN、seq=u；B 回 ACK、ack=u+1、seq=v；B 数据发完后再发 FIN、seq=w、ack 仍为 u+1；A 回 ACK、seq=u+1、ack=w+1。B 收到确认即可释放，A 延迟一段时间后释放；FIN 也占一个序号。
26. 【考纲 4.9】TCP 实现可靠传输的机制：把应用数据分成合适的报文段；每发一段启动定时器，超时未确认就重传；用检验和检测差错，出错则丢弃且不确认；对失序的数据重新排序；丢弃重复的报文段；用接收窗口实现流量控制。
27. 【考纲 4.10】流量控制靠接收端通告剩余接收缓存空间作为接收窗口，发送端控制未确认的应用层数据总量不超过最近一次通告的窗口值，从而防止接收端缓存溢出。
28. 【考纲 4.11】拥塞窗口 cwnd 表示未收到确认时可以连续发送的数据字节数，其大小取决于网络拥塞程度；发送端用重传计时器 RTO 到时未收到确认来判定网络发生拥塞。
29. 【考纲 4.12】慢启动在开始阶段把 cwnd 置为 1 个 MSS，每收到一个确认加 1 个 MSS，每经过一个 RTT 加倍；达到慢启动阈值 ssthresh 后转入拥塞避免，每经过一个 RTT 只加 1 个 MSS。
30. 【考纲 4.13】超时的处理：ssthresh 变为当前 cwnd 的一半，cwnd 置为 1，重新执行慢启动；收到 3 个重复确认的处理：ssthresh 与 cwnd 都减半，然后执行拥塞避免。加性增加与乘性减小合称 AIMD。

### 必背数字与公式

| 项目 | 必背内容 |
| --- | --- |
| 端口号长度 | 16 位，取值 0～65535 |
| 端口号分段 | 熟知 0～1023、登记 1024～49151、客户端 49152～65535 |
| 常见熟知端口 | FTP 21、SMTP 25、HTTP 80、RPC 135 |
| UDP 首部 | 8 B，源端口、目的端口、长度、检验和各 2 B |
| UDP 长度字段 | 含首部与数据；长度 108 B 时应用数据为 100 B；理论最大 65535 B |
| TCP 首部 | 至少 20 B；首部长度字段以 4 B 为单位；序号与确认序号各 32 位；窗口 16 位 |
| MSS | 只计应用层数据字节数，不含段首部 |
| 序号换算 | 首字节序号为 x 的段发 300 B，下一期望字节为 x+300；SYN 占 1 个序号 |
| 三次握手序号 | SYN 的 seq=x，回 SYN 兼 ACK 的 seq=y、ack=x+1，第三次的 seq=x+1、ack=y+1 |
| 可发送量 | 通告窗口 $-$ 已发出未确认字节数，如 2400 B 与 900 B 得 1500 B |
| 慢启动 | cwnd 初值 1 个 MSS，每 RTT 加倍，1、2、4、8…… |
| 拥塞避免 | 到阈值后每 RTT 加 1 个 MSS |
| 超时 | ssthresh $=$ 当前 cwnd 的一半，cwnd $=1$，转慢启动 |
| 三个重复确认 | ssthresh 与 cwnd 都减半，转拥塞避免 |
| 教材初始取值 | cwnd 初值为 1 个 MSS、ssthresh 初值教材取 16；练习题另设阈值属题设条件，按题设代入 |

### 易混对照

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 协议与接口 | 协议约束不同结点的对等实体，接口规定本机相邻层如何调用 | 约束的是横向对等层还是纵向相邻层 |
| 服务与协议 | 服务是本层向上层提供的能力，协议是决定该能力的规则 | 问的是“能做什么”还是“怎么做” |
| SDU 与 PDU | SDU 是上层交下来的数据，PDU 是加上本层 PCI 之后的单元 | 有没有加上本层控制信息 |
| SAP 与端口 | SAP 是相邻层访问服务的位置，端口是传输层标识进程的编号 | 出现在层间接口还是传输层首部 |
| 面向连接与无连接 | 前者先建立再按序传并确认，后者逐包独立提交、顺序不定 | 是否先建立逻辑连接 |
| OSI 与 TCP/IP | 七层对四层；连接方式的支持位置不同；产生顺序不同 | 层次数与网络层、传输层的连接类型 |
| UDP 与 TCP | UDP 无连接、开销小、保留报文边界；TCP 面向连接、可靠、按字节流 | 是否需要连接与重传 |
| 首部长度与总长度 | IPv4 中前者以 4 B 为单位、只管首部，后者以字节计、含数据；TCP 首部长度同样以 4 B 为单位 | 单位与统计范围 |
| 序号与确认号 | 序号是本段首字节的编号，确认号是期望收到的下一个字节 | 一个指已发，一个指待收 |
| 流量控制与拥塞控制 | 前者防止超过接收端缓存，后者防止压垮网络 | 保护对象是接收端还是网络 |
| 接收窗口与拥塞窗口 | 接收窗口由对方通告，拥塞窗口由发送端按拥塞程度维护 | 由谁维护、约束什么 |
| 超时与三个重复确认 | 超时是没收到确认，三个重复确认是收不到缺失段却收到后续段 | 反馈信号不同，处理后窗口轨迹不同 |

### 简答答题模板

**网络协议的三要素**

语法规定“如何讲”，即数据格式、数据码型和信号电平；语义规定“讲什么”，即协议元素类型、要发出什么控制信息、执行什么动作和返回什么应答；时序关系规定事件执行的顺序，即通信状态的变化和应答关系。

**在计算机网络中使用分层思想的好处**

三条各一句：各层次相互独立，高层只需知道低层通过接口提供哪些服务；灵活性强、便于实现和维护，某层技术变化不影响其他层次；某层的功能和服务界定清楚后便于制定标准。

**OSI 参考模型各层的主要功能**

物理层传无结构比特流并规定接口的机械、电气、功能、规程特性；数据链路层成帧、差错控制、流量控制、链路管理和寻址；网络层负责转发与路由；传输层做进程间端到端通信、复用解复用与控制；会话层建立管理终止会话；表示层处理表示差别并可压缩加密；应用层提供应用通信接口。

**服务原语的类型与功能**

四类：请求是用户实体请求服务做某种工作；指示是用户实体被告知某件事发生；响应是用户实体对某件事作出响应；确认是用户实体收到关于它请求的答复。通信过程的三个阶段都可能用到其中一部分或全部。

**TCP/IP 参考模型与 OSI 参考模型的区别**

三点：层次划分不同，7 层对 4 层，无表示层与会话层，物理层与数据链路层合并为网络接口层；连接方式不同，OSI 网络层两种、传输层只面向连接，TCP/IP 网络层只无连接、传输层两种都有；与具体协议的配合程度不同，OSI 先于协议产生、通用性好但功能归属不清，TCP/IP 先有协议再建模型、配合得好。

**TCP 建立连接的三次握手过程**

A 发 SYN=1、seq=x；B 同意则回 SYN=1、ACK=1、seq=y、ack=x+1；A 再回 ACK=1、SYN=0、seq=x+1、ack=y+1。前两次不带数据，第三次可带数据；SYN 占一个序号，所以双方数据首字节分别是 x+1 与 y+1。

**TCP 流量控制与拥塞控制的区别**

流量控制防止发送端超过接收端承受能力，靠接收端通告剩余缓存作为接收窗口。拥塞控制从端到端推测网络是否拥塞，靠拥塞窗口调节注入网络的速率，判定依据是重传计时器到时未收到确认。两者都可能限制实际发送量。

**TCP 拥塞控制的四个算法**

慢启动：cwnd 从 1 个 MSS 开始，每 RTT 加倍；拥塞避免：到阈值后每 RTT 加 1；快速重传：收到 3 个重复确认立即重传缺失段，不等定时器；快速恢复：阈值与窗口都减半后执行拥塞避免。超时时阈值减半、窗口置 1 并重新慢启动。

## 1 协议、服务与分层 {#s1}

**必背：** 协议的三要素是语法、语义和时序关系；层次和协议的集合构成网络的体系结构，协议约束不同结点的对等实体，接口规定本机相邻层怎样调用。

网络协议约束通信参与者。语法规定格式与编码，语义说明字段、控制信息和动作的含义，时序规定动作发生的先后关系。格式正确但顺序不对，仍可能违背协议。

分层把任务拆给不同层：本层利用下层服务，并为上层提供服务；接口规定相邻层怎样调用，协议规定不同节点的对等实体怎样协作。上层不必了解下层所有实现细节，但必须遵守接口约定。层次和协议的集合构成体系结构，它描述逻辑职责与关系，不等同于某一份程序代码或设备清单。

## 2 OSI 七层与层间数据 {#s2}

**必背：** OSI 由低到高分物理层、数据链路层、网络层、传输层、会话层、表示层和应用层 7 层，第 1 至 3 层是通信子网、第 5 至 7 层是网络高层、第 4 层衔接；本层 PDU 等于上层 SDU 加本层 PCI，SAP 是上层访问本层服务的位置。

OSI 从下到上分为七层。按数据经过的位置记职责，比只背层名更容易判断问题。

| 层 | 本版教材中的主要职责 |
| --- | --- |
| 物理层 | 比特流传输，约定机械、电气、功能和规程特性 |
| 数据链路层 | 成帧、链路寻址、差错控制及相应链路管理 |
| 网络层 | 分组寻址、路由与转发 |
| 传输层 | 进程间端到端通信、复用/解复用及相应控制 |
| 会话层 | 建立、组织和管理会话 |
| 表示层 | 处理数据表示差异，如编码转换、压缩和加密 |
| 应用层 | 为网络应用提供通信服务 |

PDU 是按本层协议组织的协议数据单元，SDU 是本层从上层接受的服务数据，PCI 是本层加入的协议控制信息。在简化封装模型中，本层给 SDU 加 PCI 形成 PDU；接收侧去掉相应控制信息再交给上层。应用数据经过链路层后称帧，并不是上层对象“改了名字”就不再包含原数据。

服务访问点 SAP 是相邻层访问服务的位置。请求、指示、响应、确认四类服务原语分别描述发起请求、告知对方用户、对方响应、把结果告知请求者，不能把四种原语简单数成线路上必有四个数据报。面向连接服务先建立再传输和释放，无连接服务则逐个提交数据，不先建立该逻辑连接。

## 3 TCP/IP 与 OSI 的对应 {#s3}

**必背：** TCP/IP 分网络接口层、网络互联层、传输层和应用层四层；与 OSI 的三点区别是层次划分、连接方式的支持位置以及与具体协议的配合程度。

TCP/IP 围绕互联与实际协议逐步形成，本书按四层讨论：网络接口层、网络互联层、传输层、应用层。网络接口层承接具体链路技术；网络互联层以 IP 完成跨网络分组传送；传输层提供进程间通信；应用层组织 DNS、FTP、邮件和 WWW 等服务。

与 OSI 比较，TCP/IP 的网络接口层涵盖其物理层和数据链路层相关功能；TCP/IP 应用层还承担 OSI 会话层、表示层中的一些工作。两种模型有共同的分层思路，但不能只把七个名字压缩成四个名字便认为职责一一相等。讨论本课程模型时采用四层口径，不混入其他教材的五层口径。

## 4 UDP 首部、报文边界与能力 {#s4}

**必背：** UDP 首部固定 8 B，源端口、目的端口、长度和检验和各 2 B；它无连接、不维护连接状态、保留报文边界、尽最大努力交付，因此不提供重传、按序交付、流量控制和拥塞控制。

传输层通过端口帮助把数据交给相应应用进程。UDP 首部固定为 8 B，源端口、目的端口、长度和检验和各占 2 B。长度包含首部与数据，不能直接当成应用载荷长度。检验和用于差错检测，不是鉴别发送人身份的密码机制。

UDP 无连接，保留应用报文边界，不自行提供 TCP 式的重传、顺序交付、流量控制与拥塞控制。低首部开销不等于数据必达，也不等于任何业务使用 UDP 都更合适。读取：UDP 长度为 108 B 时，应用数据为 100 B；应用是否需要处理丢失或重复，要结合其自身协议。

## 5 TCP 字节序号与连接管理 {#s5}

**必背：** TCP 按字节编号，段序号是该段首字节的序号，确认序号是期望收到的下一个字节序号即累积确认；SYN 和 FIN 各占一个序号，建立连接用三次握手、拆除连接用四次握手。

TCP 提供面向连接的可靠传输，通过检验、序号、确认、重传与去重等机制组织数据。首部至少 20 B；源/目的端口标识进程，序号和确认号各 32 位，首部长度按 4 B 计。窗口字段通告接收能力，选项用于协商选项；URG、ACK、PSH、RST、SYN、FIN 等控制位各有职责，不能把控制位和确认号混为一个字段。

TCP 按数据字节编号，某段序号是其首字节序号；累积确认给出接下来期望的字节。数据：从 4001 开始收到连续 300 B，则期望 4301。若后面某段未到而更晚的段先到，不能仅按已见的最大序号把缺口也确认过去。

建立连接的基本三次握手：A 发 SYN、seq=x；B 回 SYN+ACK、seq=y、ack=x+1；A 回 ACK、seq=x+1、ack=y+1。SYN 占一个序号，建立后第一字节从初始序号加 1 开始。

![ TCP 建连时序，初始序号为 4000 和 9000](figures/tcp-handshake.svg)

连接的两个发送方向分别结束。本书基本拆除过程为 FIN、对 FIN 的 ACK、另一方向 FIN、最终 ACK；FIN 也占一个序号。收到对方 FIN 表示对方结束那个发送方向，不说明本方向立刻没有待发数据。本节按教材给出的基本过程推演，不以消息次数概括所有实际时序变化。

## 6 接收窗口与流量控制 {#s6}

**必背：** 接收窗口以字节计，可发送量等于通告窗口减去已发出但未确认的数据量；窗口收缩反映接收端的接收能力，不能直接推出整个网络拥塞。

流量控制防止发送端超过接收端的承受能力。接收端在确认等报文中通告可用窗口，发送端控制尚未确认的数据量，不能在每发一个新段时把窗口当成全新额度。窗口以字节计，和段数不是同一个量。

模型：对方通告窗口 2400 B，当前已有 900 B 数据发出但未确认，暂不考虑其他限制，则还可发 1500 B。若接收方应用处理变慢、窗口收缩，这反映接收能力，不能直接推出整个网络拥塞。实际能发多少还可能同时受拥塞窗口等限制。

## 7 拥塞控制的教材模型 {#s7}

**必背：** 慢启动每经过一个 RTT 拥塞窗口加倍，拥塞避免每经过一个 RTT 加 1 个 MSS；超时把阈值减半、窗口置 1 后重新慢启动，收到 3 个重复确认则阈值与窗口都减半后转拥塞避免。

拥塞控制关注网络承载能力，发送端通过丢失、超时和确认等反馈调节拥塞窗口。它与接收窗口约束不同，两者都可能限制发送量。以下按本书的简化窗口模型，单位为 MSS；假定持续有数据、没有接收窗口限制，并按每个 RTT 观察。

慢启动阶段窗口大体成倍增长，到阈值后进入拥塞避免，按 RTT 线性增长。超时与收到三个重复确认是不同的反馈：本书超时模型把阈值设为原窗口一半、窗口置 1，再慢启动；三个重复确认触发快速重传，配合本书简化快速恢复把窗口减半，再拥塞避免。不要把此规则当成所有 TCP 实现的完整状态机。

轨迹：初始窗口 1、阈值 8，理想 RTT 边界上为 1、2、4、8，随后为 9、10。若在窗口 10 时超时，阈值改为 5，窗口回 1；若题设改为三个重复确认，本节模型为窗口降到 5 后线性增长。

## 本章小结

- 协议约束对等实体，接口连接本机相邻层；PDU、SDU 和 PCI 必须带上所处层次理解。本课程 TCP/IP 采用四层口径。
- UDP 长度包含 8 B 首部；TCP 按字节编号，累积确认指向下一期望字节，SYN/FIN 的占号须按过程单独计算。
- 接收窗口保护接收能力，拥塞窗口约束网络负担。计算可再发送量要扣除在途数据；超时与重复确认后的窗口轨迹按本章简化变体解释。

## 练习

**1. 某层规定“第一个字节是消息类型”“该类型要求返回确认”“先建连再发送”。分别对应协议哪个要素？这些规则与本机向下层调用的接口有什么区别？**

考点：第 1、2、3 节；层次：领会。

**答案：** 三项依次对应语法、语义和时序。协议约束不同节点的对等实体，接口描述本机相邻层如何使用服务。OSI 与 TCP/IP 都使用分层，但层次划分不同；不能用某一个接口函数等同整个网络体系结构。

**2. 在简化封装中，第 N 层收到上层 PDU，再加入本层控制信息。指出本层 SDU、PCI 与 PDU，并解释 SAP 的位置。**

考点：第 2 节；层次：领会。

**答案：** 上层交下来的数据成为本层 SDU，本层加入的协议控制信息为 PCI，组合后得到本层 PDU。SAP 位于相邻层服务接口处，是上层访问本层服务的位置，不是对等实体间的一条直接物理线路。

**3. UDP 长度字段为 108 B，应用把它当作 108 B 载荷，并认为检验和能证明消息来自可信用户。分别改正。**

考点：第 4 节；层次：简单应用。

**答案：** 载荷为 108−8=100 B，长度包含 UDP 首部。检验和用于检测传输差错，不是身份认证；UDP 本身也不因有检验和而获得可靠重传和按序交付能力。

**4. A、B 的初始序号分别为 4000、9000。写出基本三次握手的 seq/ack，随后 A 从首字节开始连续发 300 B，B 应确认到哪里？**

考点：第 5 节；层次：简单应用。

**答案：** 第一段 SYN 的 seq=4000；第二段 SYN+ACK 的 seq=9000、ack=4001；第三段 ACK 的 seq=4001、ack=9001。连续数据为字节 4001～4300，下一期望字节为 4301。不要把 SYN 的序号当成第一个应用字节。

**5. 一端已发 FIN，另一端只回 ACK 而尚未发 FIN，能否断言连接两方向都已经停止发送？**

考点：第 5 节；层次：简单应用。

**答案：** 不能。FIN 结束其发送方的数据方向，ACK 确认这一结束。另一方向仍可能有数据要传，待其发送完再用自身 FIN 结束；分析拆除时必须把两个方向分开。

**6. 接收窗口 2400 B，已有 900 B 未确认。只考虑流量控制时还能发多少？若答案因拥塞窗口更小而下降，这两个窗口各在保护什么？**

考点：第 6、7 节；层次：简单应用。

**答案：** 流量控制允许额外 2400−900=1500 B，不是重新获得 2400 B 额度。接收窗口围绕接收缓存，拥塞窗口围绕网络承载能力；最终发送还受这些约束共同限制。不能因接收端还有缓存便忽略拥塞控制。

**7. 按本节理想 RTT 模型，初始窗口 1、阈值 8。列到首次达到 10 的窗口序列，再分别给出此时超时或三个重复确认后的处理。**

考点：第 7 节；层次：简单应用。

**答案：** 序列为 1、2、4、8、9、10。超时后阈值 5、窗口 1，再慢启动；三个重复确认则按本节简化快速恢复模型降到 5，再拥塞避免。题设限定教材模型，这个轨迹不是对任意 TCP 变体的预测。
