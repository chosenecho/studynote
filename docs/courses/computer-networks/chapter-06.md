## 1 应用进程与服务模式 {#s1}

**必背：** 网络应用的基本工作模式是客户/服务器模式，主动发起通信的一端是客户，被动接受通信的一端是服务器；B/S 仍属于客户机/服务器模式，P2P 是它的特例，每个对等方既是客户又是服务器。

网络应用是参与通信的软件，加上它们之间的约定。C/S 里谁先开口、谁等着回答，就分出客户和服务器；这两个名字说的是进程角色，跟机器大小无关，一台笔记本也能当服务器。

B/S 拿浏览器当客户端，客户端不必另装软件，骨子里仍是客户机/服务器。P2P 里每个节点都能发起，也能应答，同一台机器在两次交互中可能换角色。判断一个应用属于哪种模式，先画一遍谁向谁要什么。两台机器地位相近，不等于它们之间没有服务关系。

## 2 DNS 层次、区域与解析 {#s2}

**必背：** DNS 把主机域名转换为 IP 地址；域名按层次树状命名，服务器按区设置，区可以小于或等于域但不能大于域；服务器分根、顶级、权限、本地 4 类，主机到本地用递归、本地到根用迭代。

DNS 把域名换成 IP 地址。域名空间是棵树，名字从具体的标签往上走到更上层的域。服务器按“区”分工，一个区可以小于或等于一个域，但不会大于它。根服务器不存全世界的记录，它只指路。

主机问本地服务器，一般用递归：本地答不出来，就替你去问，问到结果再回给你。本地服务器问根服务器，用迭代：拿回来的是下一站地址，不是最终答案。顺着根、顶级、权限一路问下去，结果落回主机手里。

一条现成的路径：学生查 `notes.lab.example`，本地没缓存，逐层问到权限服务器才拿到记录。同样的查询再来一次，多半被缓存挡掉，不会重走全程。解析成功只说明名字找到了；网页打不打得开，是另一件事。

## 3 FTP 的控制与数据连接 {#s3}

**必背：** FTP 用 TCP 可靠传送，传输文件时建立两条并行连接：控制连接全程保持、用端口 21 传命令与响应，数据连接用服务器端口 20 传文件、传完即关闭。

FTP 传远程文件，走 TCP，要的是可靠。它把命令和文件数据分成两条连接走，这是它跟多数应用不一样的地方。

服务器先等着，客户发起会话，认证、发命令，然后才轮到数据连接搬文件。控制连接整个会话都不关，用熟知端口 21 送命令和响应；数据连接只活到文件传完。书里那个建立方向只是一个例子，别当成所有环境的固定做法。

排障时记住一句：能登录、能发命令，只说明控制这条路通了。文件没动，去查数据连接。一台服务器同时招呼多个客户，也不等于所有客户共用一条数据流。

## 4 电子邮件的发送与读取 {#s4}

**必背：** 邮件系统由用户代理、邮件服务器和发送/读取协议 3 部分构成；SMTP 负责发送、端口 25、分连接建立与邮件传送与连接释放 3 阶段，POP3 与 IMAP 负责读取，POP3 下载后会删除服务器上的邮件。

邮件系统就三块：用户代理、邮件服务器、发送/读取协议。用户代理管写信、显示、归档；邮件服务器收下再转交。地址写成邮箱名@域名。主题、收件人、抄送是邮件自己的语义，别跟 TCP 或 IP 首部搅在一起。

发送走 SMTP，过程是连接、传送、释放。发信服务器把信交给收信服务器时，发信方是客户，收信方是服务器；同一台机器换个交互就可能换角色。POP3 和 IMAP 管读信，IMAP 还能在服务器上整理信箱。它们不是 SMTP 的两个子命令。

浏览器邮箱只是把界面搬到网页上，服务器之间照样用 SMTP 传信。教材写的早期功能问题和安全限制，用来说明协议分工，不是让你照着配今天的邮件服务。

## 5 WWW、URL 与 HTTP 交互 {#s5}

**必背：** WWW 的三个核心内容是 URL、HTTP 和 HTML；URL 格式为协议、主机、端口和路径；请求报文与响应报文都是 4 部分，请求行由方法、URL 和版本组成，状态行由版本、状态码和短语组成，状态码是 3 位十进制数、首位分 5 类。

WWW 由资源、超链接、浏览器、服务器凑在一起。URL 说清用什么方式取、找哪台主机、哪条路径；DNS 只管把名字换成地址，HTTP 管一问一答。按本书的 TCP 模型，一次访问是：解析名字、建连接、发请求、收响应、呈现内容。

请求报文从请求行开头：方法、资源标识、版本，接着首部、空行、实体。响应从状态行开头：版本、状态码、短语，后面同样是首部、空行、实体。空行是分界，别把正文第一行读成首部。

请求片段（换行按协议报文的行结束规则理解）：

```http
GET /notes/start.html HTTP/1.1
Host: notes.lab.example

```

HTTP 无状态，说的是交互本身不留业务状态，不是底层没有 TCP 连接。非持续连接和持续连接讲的是 TCP 复不复用；别把“每个请求都新建 TCP”当成 HTTP 的固定规矩。页面里有图有样式，浏览器就得多发几次请求。一个网页不是一个文件，也不是一个数据包。

## 6 Cookie 与 Session 的状态位置 {#s6}

**必背：** Cookie 把信息存在客户端、服务器用 Set-cookie 下发标识；Session 把信息存在服务器端、以 Session ID 为索引；二者最根本的不同是用户信息文件的保存位置，标识可经 Cookie 或 URL 重写传递。

服务器在响应里用 Set-Cookie 下发一段数据，浏览器存下来，之后符合条件的请求自动带上。服务器靠它认出同一个访问者。Session 反着来：状态留在服务器，浏览器手里只有一个标识。两套能一起用，不是二选一。

购物车的例子：服务器记着“会话甲有资料包 A、B”，浏览器只有甲的标识。下次请求，服务器凭标识翻记录。删浏览器里那个标识，和删服务器上的记录，是两件事。排障时分头看客户端带了什么、服务器存了什么。

Cookie 里那串乱码不代表加密，名字起得再像也不代表安全。能关联访问，也不等于对方身份可信。标识一旦泄露，别人就能接上这段会话。

## 7 用 HTML 组织一个资料页 {#s7}

**必背：** HTML 用标记指示浏览器以何种方式显示文本信息，标记成对出现并忽略大小写；head 是头部、body 是主体实际内容，title 显示在标题栏，hn 有 6 个层次，超链接用 a 标记的 href，图像用 img 标记的 src。

HTML 用标记把结构说清楚：head 放文档信息，title 定标题，body 装正文；标题、段落、链接、图像各有一套标记。浏览器看到的是渲染结果，源文本是另一回事。HTTP 负责送到，HTML 负责说清这是什么。

下面这段练习，页面名和资源名都是编的，只为看清标签怎么套、属性怎么填，路径不用真的存在。

```html
<html>
<head><title>资料目录</title></head>
<body>
  <h1>网络复习</h1>
  <p>先阅读讲解，再核对自己的推导。</p>
  <a href="chapter.html">打开章节</a>
  <img src="topology.png" alt="本组设计的拓扑图">
</body>
</html>
```

链接的地址写在 href，图像的地址写在 src，别拿图片文件名去顶链接文字。标题、段落、文件标题各有各的用处；看着像，不代表含义一样。

## 8 电子商务的业务与平台 {#s8}

**必背：** 电子商务按交易对象分 B2C、B2B、C2C、O2O，按交易内容分间接电子商务与直接电子商务；完整过程分交易前、交易中、交易后 3 阶段。

电子商务把发布、选购、支付、交付、售后搬到网上。按交易对象分 B2B、B2C、C2C，O2O 一头连线上、一头连到店。按内容分两类：有形货物要物流，算间接交易；软件、课程、电子书能在线交付，算直接交易。网页上付了钱，也不代表货已经到手。

交易前查信息、比价、注册；交易中确认买什么、买多少、谁担什么责任，生成订单；交易后跟物流、确认收货、处理售后。系统从网络平台、信息传输平台一路搭到商务平台和应用，数据库、账户、安全服务都会掺进来，技术标准和规则也算运行条件。商城网页只是最外面那层。

## 本章小结

- 客户和服务器看的是这一次交互里谁先开口。DNS 找地址，FTP 把命令和文件分成两条连接，SMTP 送信，POP3 与 IMAP 取信。前面一段通了，后面一段未必通。
- 请求与响应、业务状态、连接复用，是三件事。Session 把状态留在服务器，Cookie 把标识带回服务器，两套能配合用。
- HTML 说清结构、指明资源落在哪。电子商务还有下单、交付和售后。页面打得开、支付成功，都还不算整笔业务做完。

## 练习

**1. 同一台机器先向别人请求资料，再向其他节点提供已有资料。它是否只能固定叫客户机？浏览器作为界面又属于什么模式？**

考点：第 1 节；层次：识记。

**答案：** 角色应按具体交互区分：请求时是客户，提供服务时是服务器；P2P 可同时具有两种能力。浏览器作为客户端与服务器交互属于 B/S，可按 C/S 的请求与响应关系理解。

**2. 本地无缓存，查询 notes.lab.example，根服务器返回下一层位置。这个回答是否失败？请给出后续角色顺序，并区分递归与迭代。**

考点：第 2 节；层次：领会。

**答案：** 给出下一层位置是迭代查询的正常转介，不等于失败。本地继续询问相应顶级、权限服务器，再把结果返回主机；递归强调代为取得最终结果，迭代可逐步返回下一查询位置，后续相同查询还可能命中缓存。

**3. FTP 已能登录并接受传输命令，但文件未开始传送。为什么不能仅凭登录成功排除连接问题？**

考点：第 3 节；层次：领会。

**答案：** FTP 把控制连接与数据连接分开，登录和命令主要走控制路径，实际文件走数据路径。控制正常不能证明数据连接已建立并可传输，应单独检查后者的建立条件与可达性。

**4. 一封邮件从编辑到对方读取，分别何时涉及用户代理、SMTP、POP3 或 IMAP？发信服务器在向收信服务器交付时是什么角色？**

考点：第 4 节；层次：领会。

**答案：** 编辑和阅读由用户代理提供界面，发送到服务器及服务器间交付使用 SMTP，收取或管理已到达邮箱的邮件用 POP3 或 IMAP 等读取机制。发信服务器在这次交付中主动请求，是 SMTP 客户，角色不由机器名称永久固定。

**5. 浏览器取得正文后继续请求图片，记录中写着“HTTP 无状态，所以它只能把每张图片放进一条全新的 TCP 连接”。指出两个概念怎样分开。**

考点：第 5 节；层次：综合应用。

**答案：** 无状态说的是请求交互不自动维持业务会话状态；持续连接说的是多个 HTTP 交互是否复用 TCP。二者不同。图片等独立资源可需要额外请求，但不能由无状态推出每次必新建连接。

**6. 购物车内容在服务器，浏览器只保存会话标识。分别归到 Session 与 Cookie 的哪种职责？把标识编码得不易读能否自动保证保密？**

考点：第 6 节；层次：综合应用。

**答案：** 服务器记录购物车是会话状态，Cookie 可以承担浏览器保存并带回标识的职责，二者可协作。难以直接阅读不等于加密或安全认证，标识泄露仍可能让其他人关联该会话。

**7. 资料页需要标签栏标题“学习入口”、正文标题“网络实验”和一个到 next.html 的链接。给出相应 HTML，并解释它与 HTTP 的分工。**

考点：第 5、7 节；层次：综合应用。

**答案：** 可在 head 内写 `<title>学习入口</title>`，body 内写 `<h1>网络实验</h1>` 和 `<a href="next.html">下一节</a>`。HTML 描述内容结构，HTTP 传送请求和响应；把链接写入文档不等于已向目标请求成功。

**8. 书店在线接单后邮寄纸书，培训机构在线售卖到店服务。按交易内容与 O2O 思路各怎样分析？支付成功为何不能代替交付确认？**

考点：第 8 节；层次：识记。

**答案：** 纸书仍需实体物流，属于有形货物的间接电子商务；线上购买、线下到店使用体现 O2O。交易包含准备、订购和后续交付及售后，支付只是其中环节，不能直接证明用户已取得商品或服务。
