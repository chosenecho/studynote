### 必背名词

| 术语 | 必背一句话 | 常考 |
| --- | --- | --- |
| 网络应用 | 直接面向网络用户、遵循相应网络应用协议、为用户提供特定网络服务或实现特定网络功能的一套完整软件系统 | 填空、简答 |
| 客户机/服务器模式 | 由服务请求方客户机提出请求、由服务提供方服务器提供服务的应用工作模式，主动发起通信的一端是客户，被动接受通信的一端是服务器 | 填空、单选 |
| B/S 模式 | 客户端使用通用浏览器而不是特定客户端软件的客户机/服务器模式 | 单选 |
| P2P 模式 | 通信双方没有明确的客户与服务器之分、任何一方都可主动发起或被动接受通信的模式，每个对等方都是客户与服务器的结合 | 简答 |
| 域名 | 由标号序列组成、各标号之间用点隔开的层次结构主机名称，级别从右向左依次降低 | 填空 |
| 区 | 一个服务器所负责管辖或有权管理的域名范围，可以小于或等于域，但不能大于域 | 填空、单选 |
| 递归查询 | 受询问的本地域名服务器不知道结果时，以 DNS 客户身份继续向其他服务器查询并把最终结果返回主机的查询方式 | 简答 |
| 迭代查询 | 受询问的服务器给出所要查询的 IP 地址，或告诉对方下一步应当向哪一台服务器查询的查询方式 | 简答 |
| 控制连接 | FTP 客户与服务器之间在整个会话期间一直保持打开、用于传送请求与响应的 TCP 连接，使用熟知端口 21 | 填空 |
| 数据连接 | FTP 中实际用于传输文件的 TCP 连接，由服务器用自己传送数据的熟知端口 20 与客户提供的端口建立 | 填空 |
| 用户代理 | 以电子邮件客户端软件形式存在、作为用户与电子邮件系统之间接口的部件，承担编辑、显示、处理和通信功能 | 单选 |
| 邮件服务器 | 相当于邮政系统的邮局，负责发送和接收邮件，并向发信人报告邮件传送情况 | 填空 |
| URL | 为 Internet 上每一个万维网页分配唯一标识符的方法，一般格式为协议、主机、端口和路径四段 | 填空 |
| 请求行 | 请求报文的第一行，由请求方法、URL 和 HTTP 版本三个字段用空格分隔组成 | 填空 |
| 状态行 | 响应报文的第一行，由版本、状态码和短语三个字段组成 | 填空 |
| Cookie | 万维网服务器保存在客户端的一段文本，用于保存用户访问服务器的相关信息，供服务器识别和跟踪用户 | 简答 |
| Session | 服务器端记录用户访问状态的机制，以 Session ID 为索引开辟存储空间保存该用户的访问信息 | 简答 |
| HTML | 描述和表示万维网网页的标准语言，通过各种标记指示浏览器以何种方式显示网页中的文本信息 | 填空 |
| 动态文档 | 由服务器端应用程序在浏览器访问时才动态生成、每次响应内容不一定相同的万维网文档 | 单选 |

### 必背清单

**第 1 节**

1. 【考纲 1.1】网络应用是直接面向用户、遵循相应网络应用协议、为用户提供特定网络服务或实现特定网络功能的一套完整软件系统，其中各种网络应用协议决定功能与工作机制，是最核心的部分。
2. 【考纲 1.1】网络应用的基本工作模式是客户/服务器模式，又分为一般的客户机/服务器模式和 P2P 模式。
3. 【考纲 1.1】一般的 C/S 模式：先运行服务器并被动等待访问，客户在服务器之后运行并主动发起通信；这里的客户与服务器都指通信所涉及的两个应用进程。
4. 【考纲 1.1】B/S 的客户端使用通用浏览器而不是特定客户端软件，本质上仍属于客户机/服务器模式；优点是使用灵活、业务扩展简单、维护方便。
5. 【考纲 1.1】常用 WWW、E-mail 和 FTP 属于一般的客户机/服务器模式；QQ、Skype、BitTorrent、eMule 和 PPLive 属于 P2P 模式。

**第 2 节**

6. 【考纲 2.1】DNS 是提供将主机域名转换为 IP 地址服务的网络应用；用户层面用域名描述地址，数据报实际传输时用 IP 地址进行路由和转发。
7. 【考纲 2.2】域名采用层次树状命名，由标号序列组成、各标号之间用点隔开，级别从右向左依次降低，最右边是顶级域名。
8. 【考纲 2.2】标号由英文字母和数字组成，每个标号不超过 63 个字符，不区分大小写，除连字符外不能使用其他标点，整个域名不超过 255 个字符。
9. 【考纲 2.2】顶级域名分 3 类：国家顶级域名 nTLD、通用顶级域名 gTLD、基础结构域名；基础结构域名只有 arpa 一个，用于反向域名解析。
10. 【考纲 2.2】顶级域名由 ICANN 统一管理，其他级别由上一级管理机构管理；我国国家顶级域名为 cn，其下二级域名分 7 个类别域名与行政区域名。
11. 【考纲 2.3】DNS 服务器按区设置而不是按域设置；区的范围可以小于或等于域，但不能大于域。
12. 【考纲 2.3】域名服务器分 4 类：根域名服务器、顶级域名服务器、权限域名服务器、本地域名服务器。
13. 【考纲 2.3】根域名服务器知道所有顶级域名服务器的域名和 IP 地址，但不直接把待查询域名转换成 IP 地址，而是告诉本地域名服务器应当找哪一台顶级域名服务器。
14. 【考纲 2.3】权限域名服务器负责一个区，保存该区所有主机域名到 IP 地址的映射；本地域名服务器也称默认域名服务器，离主机最近，主机查询请求先发到它。
15. 【考纲 2.4】主机向本地域名服务器的查询一般采用递归查询；本地域名服务器向根域名服务器的查询通常采用迭代查询。
16. 【考纲 2.4】解析步骤（以主机 m.xyz.com 查 y.abc.com 为例）：主机递归查本地服务器，本地服务器迭代查根、顶级、权限域名服务器取得 IP 地址，最后把结果返回主机。
17. 【考纲 2.4】DNS 查询使用 UDP 传送查询和结果报文；各级服务器通常设有高速缓存，存放最近查询过的域名及从何处获得该对应信息。

**第 3 节**

18. 【考纲 3.1】FTP 用于两台主机之间远距离传输文件并保证传输的可靠性，提供交互式访问，允许指明文件类型与格式、允许文件有存取权限，屏蔽各计算机系统细节。
19. 【考纲 3.1】FTP 采用客户机/服务器方式，由 FTP 服务器和 FTP 客户机组成，通过下载和上传实现文件传输，使用 TCP 提供的可靠传输服务。
20. 【考纲 3.1】FTP 服务器进程由主进程和若干从属进程组成：主进程负责接受新的请求，从属进程负责处理单个请求，主进程与从属进程的处理是并发进行的。
21. 【考纲 3.2】FTP 主进程工作步骤：打开熟知端口 21 使客户能连接、等待客户连接请求、启动从属进程处理请求、回到等待状态继续接受其他客户请求。
22. 【考纲 3.2】传输文件时客户端与服务器之间建立两个并行的 TCP 连接：控制连接和数据连接。
23. 【考纲 3.2】控制连接在整个会话期间一直保持打开，客户的传送请求经它发到服务器控制进程的熟知端口 21，但控制连接不用来传送文件。
24. 【考纲 3.2】数据连接实际用于传输文件，服务器用自己传送数据的熟知端口 20 与客户提供的端口建立，传送完毕后关闭数据连接。

**第 4 节**

25. 【考纲 4.1】电子邮件系统由用户代理、邮件服务器和邮件发送/读取协议 3 部分构成。
26. 【考纲 4.1】用户代理以客户端软件形式存在，是用户与电子邮件系统之间的接口，基本功能为编辑、显示、处理和通信。
27. 【考纲 4.1】邮件服务器相当于邮局，负责发送和接收邮件，并向发信人报告已交付、被拒绝或丢失等传送情况；它按客户机/服务器方式工作，既可作客户也可作服务器。
28. 【考纲 4.1】电子邮件地址格式为邮箱名加 at 符号再加邮箱所在服务器的域名；邮件内容由首部和主体组成，首部关键字有 To、Subject、Cc、From、Date 和 Reply-To。
29. 【考纲 4.2】最常用的发送协议是 SMTP，最常用的读取协议是 POP3；发送方邮件服务器与接收方邮件服务器建立 TCP 连接使用熟知端口 25。
30. 【考纲 4.2】SMTP 通信分 3 个阶段：连接建立、邮件传送、连接释放；用户代理向发送方邮件服务器发送邮件时用户代理是 SMTP 客户。
31. 【考纲 4.2】传统 SMTP 的缺陷：只能传送 7 位 ASCII 码、发送邮件不需鉴别可任意填写发信地址、邮件明文传送易被截获。
32. 【考纲 4.2】POP3 把邮件下载到本地后服务器会删除该邮件，换一台计算机不能再读同一封；IMAP 可在服务器上阅读、回复和管理邮箱，缺点是邮件一直保留、占用服务器存储空间。
33. 【考纲 4.2】基于 Web 的电子邮件系统在客户端与邮件服务器之间使用 HTTP 通信，不使用 SMTP、POP3 或 IMAP。

**第 5 节**

34. 【考纲 5.1】WWW 是由成千上万个网站组成的联机信息存储系统，以网页形式存储文档、各网站以链接相连；工作模式为客户机/服务器方式，客户程序是浏览器。
35. 【考纲 5.1】万维网要解决 3 个问题：文档如何标识、文档之间如何链接与交换数据、不同类型文档如何被客户端正确显示；对应技术是 URL、HTTP 和 HTML。
36. 【考纲 5.2】URL 一般格式为协议、主机、端口和路径四段，端口通常可省略，例如 HTTP 使用 80；路径省略时表示该服务器的主页。
37. 【考纲 5.3】HTTP 是应用层协议，使用 TCP 连接进行可靠传送，采用客户机/服务器方式，每次交互由客户端请求和服务器响应构成。
38. 【考纲 5.3】浏览器访问万维网过程：输入 URL 或点击链接、由 DNS 解析出目标网页 IP 地址、与服务器建立 TCP 连接、发送请求报文、接收响应报文、释放 TCP 连接、显示网页内容。
39. 【考纲 5.3】HTTP 是无连接的，它使用面向连接的 TCP 所提供的服务；HTTP 也是无状态的，服务器端不记录客户端访问的时间和次数。
40. 【考纲 5.3】HTTP 1.0 使用非持续连接，每传输一个对象平均用两个往返时间；HTTP 1.1 默认使用持续连接，利用同一个 TCP 连接传输多个对象。
41. 【考纲 5.3】请求报文由请求行、请求头部行、空行和请求数据 4 部分构成；请求行由请求方法、URL 和版本 3 个字段用空格分隔组成。
42. 【考纲 5.3】响应报文由状态行、消息头部、空行和响应正文 4 部分构成；状态行由版本、状态码和短语组成，状态码是 3 位十进制数，首位定义类别。
43. 【考纲 5.3】状态码 5 类：1xx 指示信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务器端错误；404 表示请求资源不存在。
44. 【考纲 5.3】GET 要求服务器把 URL 定位的资源放在响应报文数据部分回送，不适合传送私密数据和大量数据；HEAD 只返回响应头，用于只查看页面状态。
45. 【考纲 5.4】Cookie 是服务器保存在客户端的一段文本，通过响应报文的 Set-cookie 首部下发标识，客户端在后续请求的 Cookie 首部把它带回。
46. 【考纲 5.4】Session 在服务器端保存用户信息，以 Session ID 为索引开辟数据存储空间；Session ID 可通过 Cookie 传递，也可用 URL 重写技术附在 URL 路径后面。
47. 【考纲 5.4】Cookie 与 Session 最根本的不同是用户信息文件的保存位置：Cookie 存在客户端，Session 存在服务器端。
48. 【考纲 5.5】HTML 通过各种标记指示浏览器以何种方式显示网页中的文本信息，标记由小于号和大于号括起，常成对出现并且忽略大小写。
49. 【考纲 5.5】head 之间是网页头部，body 之间是网页主体实际内容；title 之间的文字显示在浏览器标题栏；hn 允许 6 个层次的标题。
50. 【考纲 5.5】超链接用 a 标记的 href 属性写跳转目的地，标记之间的字符串是被设为超链接的文字；图像用 img 标记的 src 属性指定图形文件。

**第 6 节**

51. 【考纲 5.4】Cookie 文件可保存在硬盘成为永久 Cookie，也可保存在内存成为会话 Cookie，会话 Cookie 在关闭浏览器窗口后消失。
52. 【考纲 5.4】Cookie 内容大多经过加密处理，但名称或看似乱码的外观不表示已加密；Cookie 跟踪用户的行为与账户信息一旦泄露会造成损失。

**第 7 节**

53. 【考纲 5.5】HTML 描述文档结构与标记含义，HTTP 负责传送请求和响应；网页源文本与浏览器呈现结果不是同一对象。
54. 【考纲 5.5】XML 是元标记语言，可自行定义标记并表示结构化数据；它是 HTML 的补充而不是替代或升级。

**第 8 节**

55. 【考纲 6.1】电子商务是把网络技术特别是 Internet 技术与传统商务活动相结合、把商家顾客与金融机构联系起来、实现商品展示与选购与在线支付与售后服务并由线下物流配送完成交易的动态商务活动。

### 简答答题模板

**DNS 域名服务器分哪几类，各自作用是什么**

按 4 类写：根域名服务器知道所有顶级域名服务器的域名和 IP 地址，自己不直接给出 IP 地址而是转介；顶级域名服务器管理在该处注册的二级域名；权限域名服务器负责一个区，保存该区主机的域名到 IP 地址映射；本地域名服务器离主机最近，先接收主机查询，同网时可立即给出结果。

**域名解析过程，递归与迭代有何区别**

先答区别：递归是受询者代为取得最终结果，迭代是只告诉下一步该问哪一台。再答过程：主机向本地域名服务器递归查询；本地服务器无缓存时向根服务器迭代查询，根给出顶级域名服务器位置；本地再问顶级，顶级给出权限域名服务器位置；本地问权限服务器取得 IP 地址；最后本地把结果返回主机。DNS 查询用 UDP，各级可设高速缓存。

**FTP 的两条连接与主进程工作步骤**

两条并行 TCP 连接：控制连接传命令与响应、会话期间全程保持、用熟知端口 21；数据连接传文件、由服务器用熟知端口 20 与客户提供的端口建立、传送完毕关闭。主进程 4 步：打开熟知端口 21、等待客户连接请求、启动从属进程处理请求、回到等待状态继续接受其他客户请求，主进程与从属进程并发进行。

**电子邮件系统的组成与 SMTP 的通信阶段**

3 部分：用户代理负责编辑、显示、处理和通信；邮件服务器负责发送与接收并报告传送情况；发送/读取协议中最常用发送协议是 SMTP、读取协议是 POP3。SMTP 通信 3 阶段：连接建立、邮件传送、连接释放。补一句缺陷：只传 7 位 ASCII 码、发送不需鉴别、邮件明文。

**Cookie 与 Session 的最根本不同**

Cookie 的信息文件保存在客户端，服务器通过 Set-cookie 下发标识、客户端在后续请求的 Cookie 首部回传；Session 的信息保存在服务器端，以 Session ID 为索引开辟存储空间，Session ID 可经 Cookie 或 URL 重写传递。二者可配合使用，删除客户端标识与删除服务器记录是两件事。

## 1 应用进程与服务模式 {#s1}

**必背：** 网络应用的基本工作模式是客户/服务器模式，主动发起通信的一端是客户，被动接受通信的一端是服务器；B/S 仍属于客户机/服务器模式，P2P 是它的特例，每个对等方既是客户又是服务器。

网络应用由参与通信的软件及其约定构成。客户机/服务器模式中，客户主动提出请求，服务器等待并提供服务；“客户”和“服务器”首先描述进程角色，不是按计算机大小分级。B/S 用浏览器作为客户端，仍可按 C/S 关系分析。

P2P 模式的参与者可以既请求也提供服务，同一节点在不同交互中承担不同角色。按本书观点，它仍包含具体请求方与提供方，只是不把所有节点固定分成两组。分析一个应用时先画出谁向谁请求什么，不要见到两台机器地位相近便断定没有服务关系。

## 2 DNS 层次、区域与解析 {#s2}

**必背：** DNS 把主机域名转换为 IP 地址；域名按层次树状命名，服务器按区设置，区可以小于或等于域但不能大于域；服务器分根、顶级、权限、本地 4 类，主机到本地用递归、本地到根用迭代。

DNS 把域名与有关地址信息对应起来。域名空间按层次组织，名称从较具体的标签延伸到较上层的域；服务器按“区”承担管理责任，区与域不能简单画等号。根、顶级和权限域名服务器承担不同层次的定位与回答，本地服务器负责接收主机的查询并组织后续解析。

递归查询要求受询者继续取得结果再答复；迭代查询允许给出下一步应询问的服务器。按本书典型流程，主机递归请求本地服务器，本地服务器再逐步向根、顶级、权限服务器迭代询问，取得结果后返回主机。根服务器不是保存所有主机记录的“大通讯录”。

跟踪：学生查询 `notes.lab.example`，假定本地无缓存且各级按层转介。本地先取得下一层位置，再逐层到权限服务器取记录；后续查询可能由缓存回答，不能断言每次都重复整条路径。DNS 完成名字解析，并不负责下载网页文件；解析成功也不代表目标应用必然可访问。

## 3 FTP 的控制与数据连接 {#s3}

**必背：** FTP 用 TCP 可靠传送，传输文件时建立两条并行连接：控制连接全程保持、用端口 21 传命令与响应，数据连接用服务器端口 20 传文件、传完即关闭。

FTP 提供远程文件访问和传送，使用 TCP 的可靠传输能力，并把控制与文件数据分开。教材基本过程先由服务器等待连接，客户发起会话，经认证和命令确定操作，再由数据连接传送文件。

控制连接承载命令和响应，在会话中保持；数据连接用于实际文件传输，完成后可关闭。控制使用教材中的熟知端口 21，但不能把教材某一数据连接示例中的端口与建立方向当成所有 FTP 环境的唯一方式。判断故障时，“可以登录和发命令”只说明控制路径有进展，文件数据路径仍需单独核对。服务器可同时处理多个客户，会话与进程并发不等于所有客户共用一条文件数据流。

## 4 电子邮件的发送与读取 {#s4}

**必背：** 邮件系统由用户代理、邮件服务器和发送/读取协议 3 部分构成；SMTP 负责发送、端口 25、分连接建立与邮件传送与连接释放 3 阶段，POP3 与 IMAP 负责读取，POP3 下载后会删除服务器上的邮件。

邮件系统包含用户代理、邮件服务器和发送/读取协议。用户代理负责编辑、呈现和管理邮件，邮件服务器保存和转交邮件。地址通常写为邮箱名@域名；邮件内容由首部与主体组成，主题、收件人、抄送等属于邮件语义，不要与 TCP 或 IP 首部混淆。

SMTP 用于发送邮件，包含连接、传送和释放的基本过程。发信服务器向收信服务器传送时，前者是该交互的客户，后者是服务器；同一主机在不同交互中可以转换角色。POP3 和 IMAP 用于读取邮件，IMAP 可在服务器侧管理邮件，不能把二者当成 SMTP 的两个发送命令。

浏览器邮箱只是把用户界面放到 Web 上，并不说明服务器间邮件传递也改由网页下载完成。本书对早期 SMTP 的功能和安全限制作了说明；本节只用于辨别协议职责，不将这些描述概括为所有现行邮件服务的配置。

## 5 WWW、URL 与 HTTP 交互 {#s5}

**必背：** WWW 的三个核心内容是 URL、HTTP 和 HTML；URL 格式为协议、主机、端口和路径；请求报文与响应报文都是 4 部分，请求行由方法、URL 和版本组成，状态行由版本、状态码和短语组成，状态码是 3 位十进制数、首位分 5 类。

WWW 由分散的资源、超链接、浏览器和服务器共同组织。URL 指出资源的访问方式、主机及路径等位置要素；域名解析只解决找地址，HTTP 则描述请求与响应。以本书基于 TCP 的 HTTP 模型为范围：解析名称、建立连接、请求资源、接收响应、呈现内容。

请求报文从请求行开始，包含方法、资源标识与版本，后面是首部、空行和可选实体；响应从状态行开始，包含版本、状态码与说明，再跟首部、空行和可选实体。空行是结构分界，不能把正文第一行当成首部。

请求片段（换行按协议报文的行结束规则理解）：

```http
GET /notes/start.html HTTP/1.1
Host: notes.lab.example

```

HTTP 无状态指交互本身不自动保留用户业务状态，不是说底层 TCP 没有连接。非持续连接与持续连接描述 TCP 连接是否复用；不能把“每个请求都新建 TCP”当成 HTTP 的永恒规则。正文含图片等其他资源时，浏览器还可能需要发起更多资源请求，不能把一个网页概括成一个文件或一个数据包。

## 6 Cookie 与 Session 的状态位置 {#s6}

**必背：** Cookie 把信息存在客户端、服务器用 Set-cookie 下发标识；Session 把信息存在服务器端、以 Session ID 为索引；二者最根本的不同是用户信息文件的保存位置，标识可经 Cookie 或 URL 重写传递。

Cookie 机制让服务器通过响应的 Set-Cookie 首部向浏览器设置有关数据，浏览器在符合相应范围的后续请求中携带，服务器借此关联访问。Session 把主要会话状态保存在服务器侧，再用会话标识关联不同请求；标识也可以借助 Cookie 传递。二者可以配合，并不是只能二选一。

购物车：服务器记录“会话甲有资料包 A、B”，浏览器只持有会话甲的标识。再次请求时，服务器凭标识找记录。删除浏览器标识与删除服务器记录是不同动作，分析故障时分别查客户端携带了什么、服务器保存了什么。

Cookie 内容不因为名称或看似乱码就自动获得加密。状态关联也不自动证明使用者身份可信，标识泄露可能带来风险；不要把密码明文保存作为本节演示。

## 7 用 HTML 组织一个资料页 {#s7}

**必背：** HTML 用标记指示浏览器以何种方式显示文本信息，标记成对出现并忽略大小写；head 是头部、body 是主体实际内容，title 显示在标题栏，hn 有 6 个层次，超链接用 a 标记的 href，图像用 img 标记的 src。

HTML 用标记说明文档结构：head 放置文档相关信息，title 指定标题，body 承载页面内容；标题、段落、链接和图像各有相应标记。网页源文本与浏览器呈现结果不是同一对象，HTTP 负责传送，HTML 负责描述内容结构。

下面的结构练习用假设的页面与资源名，只为读懂标签嵌套和属性，这些路径不需要真实存在。

```html
<html>
<head><title>资料目录</title></head>
<body>
  <h1>网络复习</h1>
  <p>先阅读讲解，再核对自己的推导。</p>
  <a href="chapter.html">打开章节</a>
  <img src="topology.png" alt="本组设计的拓扑图">
</body>
</html>
```

链接的 href 指向目标，图像的 src 指向图像资源，不能用图像文件名替代链接文字。标题层次、正文段落与文件标题各有用途；排版看起来相似，不代表标记含义相同。

## 8 电子商务的业务与平台 {#s8}

**必背：** 电子商务按交易对象分 B2C、B2B、C2C、O2O，按交易内容分间接电子商务与直接电子商务；完整过程分交易前、交易中、交易后 3 阶段。

电子商务把信息发布、选购、支付、交付和售后等商务环节与网络服务结合。按交易对象可辨 B2B、B2C、C2C；O2O 联系线上业务与线下服务。按内容还可分有形货物的间接交易与可在线交付内容的直接交易，不能只因通过网页支付就认为物流已经完成。

交易前有信息查询、比较与准备，交易中确认对象、数量及权利义务并形成订单，交易后处理交付跟踪、确认和售后。系统从网络平台、信息传输平台到商务平台与应用层层配合，数据库、安全和账户服务都可能参与；技术标准及规则也是业务运行条件，不能把商城网页当成整个商务系统。

## 本章小结

- 客户与服务器是具体通信中的进程角色。DNS 解析定位，FTP 分离控制与数据，SMTP 发送邮件，POP3/IMAP 读取邮件；一条路径成功不代表全部应用环节正常。
- HTTP 请求响应、业务状态及底层连接复用是不同问题；Session 可保存服务器状态，Cookie 可回传标识，二者可以配合。
- HTML 描述文档结构和资源引用，电子商务还包括订购、交付及售后；页面能打开或支付已成功，不足以证明完整业务完成。

## 练习

**1. 同一台机器先向别人请求资料，再向其他节点提供已有资料。它是否只能固定叫客户机？浏览器作为界面又属于什么模式？**

考点：第 1 节；层次：识记。

**答案：** 角色应按具体交互区分：请求时是客户，提供服务时是服务器；P2P 可同时具有两种能力。浏览器作为客户端与服务器交互属于 B/S，可按 C/S 的请求与响应关系理解。

**2. 本地无缓存，查询 notes.lab.example，根服务器返回下一层位置。这个回答是否失败？请给出后续角色顺序，并区分递归与迭代。**

考点：第 2 节；层次：领会。

**答案：** 给出下一层位置是迭代查询的正常转介，不等于失败。本地继续询问相应顶级、权限服务器，再把结果返回主机；递归强调代为取得最终结果，迭代可逐步返回下一查询位置，后续相同查询还可能命中缓存。

**3. FTP 已能登录并接受传输命令，但文件未开始传送。为什么不能仅凭登录成功排除连接问题？**

考点：第 3 节；层次：领会。

**答案：** FTP 把控制连接与数据连接分开，登录和命令主要走控制路径，实际文件走数据路径。控制正常不能证明数据连接已建立并可传输，应单独检查后者的建立条件与可达性。

**4. 一封邮件从编辑到对方读取，分别何时涉及用户代理、SMTP、POP3 或 IMAP？发信服务器在向收信服务器交付时是什么角色？**

考点：第 4 节；层次：领会。

**答案：** 编辑和阅读由用户代理提供界面，发送到服务器及服务器间交付使用 SMTP，收取或管理已到达邮箱的邮件用 POP3 或 IMAP 等读取机制。发信服务器在这次交付中主动请求，是 SMTP 客户，角色不由机器名称永久固定。

**5. 浏览器取得正文后继续请求图片，记录中写着“HTTP 无状态，所以它只能把每张图片放进一条全新的 TCP 连接”。指出两个概念怎样分开。**

考点：第 5 节；层次：综合应用。

**答案：** 无状态说的是请求交互不自动维持业务会话状态；持续连接说的是多个 HTTP 交互是否复用 TCP。二者不同。图片等独立资源可需要额外请求，但不能由无状态推出每次必新建连接。

**6. 购物车内容在服务器，浏览器只保存会话标识。分别归到 Session 与 Cookie 的哪种职责？把标识编码得不易读能否自动保证保密？**

考点：第 6 节；层次：综合应用。

**答案：** 服务器记录购物车是会话状态，Cookie 可以承担浏览器保存并带回标识的职责，二者可协作。难以直接阅读不等于加密或安全认证，标识泄露仍可能让其他人关联该会话。

**7. 资料页需要标签栏标题“学习入口”、正文标题“网络实验”和一个到 next.html 的链接。给出相应 HTML，并解释它与 HTTP 的分工。**

考点：第 5、7 节；层次：综合应用。

**答案：** 可在 head 内写 `<title>学习入口</title>`，body 内写 `<h1>网络实验</h1>` 和 `<a href="next.html">下一节</a>`。HTML 描述内容结构，HTTP 传送请求和响应；把链接写入文档不等于已向目标请求成功。

**8. 书店在线接单后邮寄纸书，培训机构在线售卖到店服务。按交易内容与 O2O 思路各怎样分析？支付成功为何不能代替交付确认？**

考点：第 8 节；层次：识记。

**答案：** 纸书仍需实体物流，属于有形货物的间接电子商务；线上购买、线下到店使用体现 O2O。交易包含准备、订购和后续交付及售后，支付只是其中环节，不能直接证明用户已取得商品或服务。
