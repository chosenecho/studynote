### 必背名词

| 术语 | 必背一句话 | 常考 |
| --- | --- | --- |
| 网络管理 | 采用计算机软硬件技术对由计算机、服务器、存储器、交换机和路由器等网络设备及相关软件组成的网络进行管理的工作 | 填空、简答 |
| 被管对象 | 网络环境下资源的一种抽象表示，系统中的所有资源包括管理软件本身都可以是被管对象 | 填空、单选 |
| 管理信息库 MIB | 被管对象的集合，是一个概念上的数据库，其数据分布在网络各处 | 填空 |
| 管理信息结构 SMI | 规定如何识别管理对象以及如何组织管理对象信息结构的规则，可理解为描述 MIB 中被管对象的语言 | 简答 |
| 网络管理站 | 也称管理进程，是负责发出管理操作指令的逻辑概念，通常由软件实现 | 单选 |
| 管理代理 | 位于被管理设备内部、负责执行管理指令并以通知形式报告事件的实体，基本功能是读取和修改 MIB 中的变量值 | 填空 |
| 网络管理协议 | 用于管理站和管理代理之间完成信息交换的通信规约，规定通信方法、MIB 存储结构、关键词含义与事件处理方法 | 简答 |
| 委托代理 | 能提供其他系统或其他设备信息的管理代理，起协议转换作用，使管理站可以管理不支持 SNMP 的设备 | 单选 |
| 轮询 | 管理站向代理发出请求、代理从 MIB 中取值返回的请求响应式通信机制 | 简答 |
| 事件报告 | 代理主动向管理站发送消息的通信机制，可按要求定时发送或在特定事件发生时发送 | 简答 |
| 对象标识符 OID | 从对象命名树的树根到树叶的编号串联起来、用圆点隔开形成的被管对象全局标识 | 填空 |
| 简单网络管理协议 SNMP | 工作在应用层、面向无连接、基于 UDP 的网络管理协议，是 SNMP 协议与管理信息库与管理信息结构的规范集合 | 简答 |
| 共同体 | 代理与某些管理站建立的信任关系，共同体名是全局标识符，是一种简单的身份认证手段 | 填空 |
| 网络管理系统 NMS | 实现管理网络功能、保障网络正常运行的软硬件组成的综合系统 | 填空 |
| MIB 浏览器 | 界面友好的图形化 SNMP 工具，指定主机名或地址后读取 MIB 对象及其值 | 单选 |
| Sniff 工具 | 捕获穿过网段的 SNMP 数据包并存储以便后续分析的工具 | 单选 |

### 必背清单

**第 1 节**

1. 【考纲 1.1】网络管理的主要任务有两个：对网络的状态进行监测，对网络的运行进行控制。
2. 【考纲 1.1】网络管理的根本目标是最大限度地满足管理者和用户对网络的有效性、可靠性、开放性、综合性、安全性和经济性的要求。
3. 【考纲 1.1】网络管理还需要做三件事：调整运行配置使性能最优化、预知潜在故障与安全风险并预防处理、依据网络模型理论指导扩充和规划。
4. 【考纲 1.2】网络管理对象按形式分两大类：硬件资源和软件资源；硬件含物理介质、计算机设备和网络互连设备，软件含操作系统、应用软件和通信软件。
5. 【考纲 1.2】被管对象是从 OSI 角度所看到的 OSI 环境下的资源，一个资源可以表示为一个或多个被管对象。
6. 【考纲 1.3】网络管理的标准与参考模型主要有 OSI 参考模型、TCP/IP 参考模型、TMN 参考模型、IEEE LAN/VAN 以及基于 Web 的管理模型。
7. 【考纲 1.3】TCP/IP 参考模型在 Internet 中占统治地位，其管理协议 SNMP 发展最快、应用最广。

**第 2 节**

8. 【考纲 2.1】网络管理体系结构是定义网络管理系统结构及系统成员间相互关系的一套规范，是建立网络管理系统的基础。
9. 【考纲 2.1】ISO 提出的基于远程监控的管理框架是现代网络管理体系结构的核心，目标是建立统一的综合网络管理系统，把现场物理操作变为远程逻辑操作。
10. 【考纲 2.1】完整的网络管理系统包括 4 部分：网络管理站、管理代理、网络管理协议和管理信息库。
11. 【考纲 2.2】管理站与管理代理通过交换管理信息工作，交换过程通过协议数据单元 PDU 进行；通常是管理站发送请求 PDU，代理以 PDU 回答。
12. 【考纲 2.2】管理代理具有两个基本功能：从 MIB 中读取各种变量值和在 MIB 中修改各种变量值，分别对应网络监测和网络控制。
13. 【考纲 2.2】管理站角色与代理角色不是固定的，而由每次通信的性质决定；一个管理站可与多个代理交换信息，一个代理也可接受多个管理站的操作。
14. 【考纲 2.2】管理站与代理之间的信息交换分两种：从管理站到代理的管理操作（命令），从代理到管理站的事件通知（报告）。
15. 【考纲 2.2】网络管理协议的主要任务是定义双方的通信方法、规定管理信息库的存储结构、规定信息库中关键词的含义以及各种事件的处理方法。
16. 【考纲 2.2】MIB 的数据分 3 类：结构数据是静态信息，动态数据是测量到的网络状态数据，控制数据是网络可调整参数的设置。
17. 【考纲 2.3】网络管理模式分集中式、分布式和混合管理模式 3 种。
18. 【考纲 2.3】集中式的优点是管理集中、有专人负责、便于从全局实施管理；缺点是信息集中易拥塞、功能固定不灵活、管理站故障则全网管理系统崩溃、中间结点故障会破坏管理。
19. 【考纲 2.3】集中式适合于结点不多、覆盖范围有限的小型局域网以及管理方式明确、组织结构简单的专用网络。
20. 【考纲 2.3】基于平台的形式把唯一的网络管理站分为管理平台与管理应用两部分，通过公共应用程序接口通信，仍是集中式管理，应用增多后平台成为瓶颈。
21. 【考纲 2.3】分布式的核心思想是把管理信息合理分布到网络各处，在最靠近问题源的地方做出基本决策，结构上是对等式、有多个各管一个域的管理站。
22. 【考纲 2.3】分布式能容纳网络的增长和变化，扩展性好、降低管理复杂性、减少通信与计算开销；混合模式把集中与分布结合，取长补短。

**第 3 节**

23. 【考纲 3.1】网络管理功能有 5 个方面：故障管理、配置管理、安全管理、性能管理和计费管理。
24. 【考纲 3.1】故障管理是对网络中的问题或故障进行定位的过程，含故障检测和报警、故障预测、故障诊断和定位 3 个模块。
25. 【考纲 3.1】配置管理用于实现网络设备的配置和管理，主要含设备初始化、维护和关闭网络设备或子系统等操作。
26. 【考纲 3.1】安全管理是网络管理中最复杂的部分，目的是确保网络资源不被非法使用，需要维护保密性、数据完整性和可用性 3 方面性能。
27. 【考纲 3.1】性能管理持续测评网络运行的主要性能指标，分性能监测与网络控制两部分。
28. 【考纲 3.1】常用性能测评指标有可用性、响应时间、吞吐量、延迟、丢包率和利用率；前两项面向服务，后四项面向效率。
29. 【考纲 3.1】计费管理按计费策略记录用户使用网络资源的情况并核算费用，常用方式有基于流量、基于使用时间和基于网络服务计费。

**第 4 节**

30. 【考纲 4.1】SNMP 不是单一协议，而是包括 SNMP 协议、管理信息数据库 MIB 和管理信息结构 SMI 共 3 部分的规范集合。
31. 【考纲 4.1】SNMP 采用管理站与管理代理模型，管理站与代理之间的操作有 3 种：Get 读取、Set 设置、Trap 通报重要事件。
32. 【考纲 4.1】Get 和 Set 由管理站发起，Trap 由管理代理发起；使用 Trap 是为了及时有效监视被管设备而又不过分增加通信负载。
33. 【考纲 4.1】SNMP 是应用层协议，实际使用 UDP 数据报服务，原因是 UDP 效率较高、不会过多增加网络负载，代价是报文容易丢失。
34. 【考纲 4.1】为减少 UDP 不可靠的影响，每个管理信息装配成单独数据报独立发送，报文尽量短，每个报文不超过 484 个字节。
35. 【考纲 4.1】SNMP 有 3 个版本：v1、v2、v3，其中 v3 在先前版本基础上增加了安全和远程配置能力。
36. 【考纲 4.2】SMI 的 3 个作用是规定被管对象的命名法则、规定被管对象的数据类型、规定被管对象数据的编码方法。
37. 【考纲 4.2】所有被管对象都位于对象命名树上，树的根结点没有名字，根下 3 个结点为 ccitt 与 iso 与 joint-iso-ccitt，标号分别为 0、1、2。
38. 【考纲 4.2】OID 有数字形式和名字形式两种写法，SNMP 报文采用数字形式；mgmt 的标识符是 1.3.6.1.2，mib-2 的标识符是 1.3.6.1.2.1。
39. 【考纲 4.2】SMI 用 ASN.1 定义数据类型，分简单类型和结构化类型；结构化类型有 sequence 与 sequence of 两种。
40. 【考纲 4.2】SMI 用 BER 编码，BER 把数据元素表示为 T、L、V 三个字段；T 字段的类别段占 2 bit、格式段占 1 bit、编号段占 5 bit。
41. 【考纲 4.2】MIB 中的对象位于 mib-2 结点下，mib-2 下 11 个子结点表示 11 个被管对象组，例如 ip 组的 OID 前缀为 1.3.6.1.2.1.4。
42. 【考纲 4.3】SNMP 报文由版本号、首部、安全参数和 SNMP 报文数据 4 部分组成；首部含报文标识、最大报文长度和报文标志。
43. 【考纲 4.3】SNMP 报文数据部分含加密字段、PDU 类型字段、请求标识符、差错状态、差错索引和变量绑定。
44. 【考纲 4.3】请求标识符是管理站设置的 4 字节整数，代理在响应中返回它，使管理站能识别响应报文对应哪一个请求报文。
45. 【考纲 4.3】变量绑定字段用于指明一个或多个变量的名和对应的值，在请求报文中变量的值应忽略。
46. 【考纲 4.3】SNMP 定义了 8 种 PDU：GetRequest、GetNextRequest、SetRequest、Response、GetBulkRequest、InformRequest、SNMPv2Trap 和 Report。
47. 【考纲 4.4】SNMP 工具分 3 类：MIB 浏览器是图形化工具，命令行工具基于 v1 设计含 Get 与 Get-next 等方法，Sniff 工具捕获网段上的管理报文供分析。

**第 5 节**

48. 【考纲 5.1】网络管理系统是实现管理网络功能、保障网络正常运行的软硬件组成的综合系统，一般由支持管理协议的管理软件和网络设备组成。
49. 【考纲 5.1】NMS 应具备 5 个特点：全面监控网络性能、主动和预警管理、支持全网联动、有效管理资源、服务质量管理。
50. 【考纲 5.1】网络管理技术的发展趋势是开放性、综合性、智能化、安全性和基于 B/S 结构的管理。
51. 【考纲 5.2】常用商业 NMS 有 HP 的 OpenView、IBM 的 Tivoli NetView 和 Cisco 的 CiscoWorks；开源的还有 Cacti、Nagios 和 Icinga。
52. 【考纲 5.2】Cacti 是基于 PHP 与 MySQL 与 SNMP 与 RRDTool 的网络流量监测图形分析工具，通过 SNMP 的 Get 方式取数据，用 RRDtool 绘图。

### 易混对照

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 管理站与管理代理 | 管理站发出管理操作指令，代理执行指令并报告事件 | 指令从哪一侧发出 |
| MIB 与 SMI | MIB 是被管对象的集合，SMI 是规定命名、类型与编码的描述规则 | 说的是对象本身还是描述方式 |
| 被管对象与 MIB | 被管对象是资源某一方面的抽象，MIB 是这些对象的集合 | 单数还是集合 |
| 轮询与事件报告 | 轮询由管理站发起请求、代理响应，事件报告由代理主动发送 | 谁先发出报文 |
| Get 与 Set | Get 读取对象值，Set 设置对象值，二者都由管理站发起 | 报文目的是读还是改 |
| 一般代理与委托代理 | 一般代理返回本身的信息，委托代理返回其他系统或设备的信息并起协议转换作用 | 被管设备自己支不支持 SNMP |
| 集中式与分布式 | 集中式由一个管理站负责全网，分布式把管理任务分到各域管理站 | 局部决策在哪一层做 |
| 故障管理与性能管理 | 故障管理定位并排除问题，性能管理持续测量指标并找瓶颈 | 目标是恢复正常还是评估水平 |
| 可用性与利用率 | 可用性面向服务，反映可服务时间比例；利用率面向效率，反映资源使用频度 | 指标服务对象不同 |
| 结构数据与动态数据 | 结构数据是静态配置信息，动态数据是测量到的状态数据 | 数据是配置来的还是测出来的 |
| 结构数据与控制数据 | 结构数据描述网络构成，控制数据是可调整参数的设置 | 数据用于配置管理还是性能管理 |
| OID 数字形式与名字形式 | 数字形式便于存储处理且 SNMP 报文采用，名字形式便于人读 | 报文里写的是哪一种 |
| MIB 浏览器与 Sniff | MIB 浏览器读对象值，Sniff 抓报文看交互过程 | 要看值还是要看报文 |

### 简答答题模板

**网络管理的主要任务和目标**

任务两条：对网络状态进行监测以了解是否存在问题，对网络运行进行控制以调配资源、优化性能、提高服务质量。目标 6 项各一句：有效性是准确及时传递信息，可靠性是持续稳定运行并有抵御与自愈能力，开放性是兼容不同厂商设备与新技术，综合性是提供多种综合业务，安全性是保护信息并防止误操作致瘫，经济性是减少运行费用、节能环保。

**完整的网络管理系统由哪几部分组成，各部分作用是什么**

4 部分：网络管理站发出管理操作指令、收集状态与性能数据、接收告警并实施控制；管理代理位于被管设备内部，读取和修改 MIB 变量值，把命令转换为本设备指令并主动报告事件；网络管理协议规定双方交换信息的方法、MIB 存储结构、关键词含义与事件处理；管理信息库是被管对象的集合，管理站与代理的信息分别驻留其中。

**三种网络管理模式的特点**

集中式由一个管理站负责全网，结构简单、价格低、易维护，适合小型局域网；但信息集中易拥塞、功能固定不灵活、管理站故障则系统崩溃。分布式把管理功能分布到被管设备，就近决策、扩展性好、开销小，采用对等结构、多个管理站各管一个域。混合模式把二者结合，取长补短，是大系统管理的基本方向。

**SNMP 的基本工作原理**

SNMP 是含 SNMP 协议与 MIB 与 SMI 的规范集合，采用管理站与管理代理模型。操作 3 种：Get 由管理站读取对象值，Set 由管理站设置对象值，Trap 由代理通报重要事件。管理站启动后先轮询取关键数据，之后由代理在异常时用 Trap 报告，管理站再按需用 Get 追问、必要时用 Set 控制。SNMP 用 UDP 承载以免过多增加负载，报文不超过 484 字节。

**网络管理的五类功能**

故障管理负责发现、告警、定位和处理异常；配置管理维护设备参数与资源关系；安全管理控制非法使用、保护信息并维护保密性与完整性与可用性；性能管理持续测量指标、找瓶颈并报告趋势；计费管理记录资源使用并按策略核算费用。写答案时每项补一句职责，同一事件可跨多类功能，不必强行唯一归类。

## 1 管理任务、对象与标准 {#s1}

**必背：** 网络管理的主要任务是监测网络状态与控制网络运行，根本目标是满足有效性、可靠性、开放性、综合性、安全性和经济性 6 项要求；管理对象分硬件资源与软件资源，资源用被管对象表示。

网络管理不仅在故障发生后“修网络”，还包括配置优化、监测状态、预防风险和规划扩展。有效性、可靠性、安全性、开放兼容与经济性可能同时成为目标，管理动作需要围绕这些目标评估效果。

被管对象是对资源某方面的抽象，可涵盖链路、接口、主机、路由器等硬件，也涵盖操作系统、应用和通信软件。一个物理设备可对应多个被管对象，管理软件本身也可能是对象。教材比较 OSI、TCP/IP、TMN 和基于 Web 等管理标准或模型；共同规范使不同厂商的管理站与代理可以理解彼此，不能把一个厂商控制台等同全部管理标准。

## 2 管理站、代理、协议与信息 {#s2}

**必背：** 完整的管理系统由管理站、管理代理、网络管理协议和管理信息库 4 部分组成；代理的两个基本功能是读取和修改 MIB 中的变量值；SMI 规定命名与类型与编码，MIB 是被管对象的集合。

管理站组织采集与控制，管理代理接近被管资源，读取状态并处理允许的设置操作。管理协议规定双方交换信息的方法，MIB 表示对象与有关值的集合，SMI 规定这些对象的命名、类型和表示规则。区分这五项时，可以分别问“谁决策、谁执行、怎样通信、管理什么、怎样描述”。

![接口监测链：管理站读取状态，代理报告事件](figures/management-loop.svg)

MIB 是逻辑上的管理信息集合，不应一律想成管理站硬盘上的一个集中数据库文件。界面读出一项变量也不说明可以写它，代理能力和权限约束仍需核对；监测与控制是不同的操作目的。

## 3 集中、分布与混合管理 {#s3}

**必背：** 管理模式分集中式、分布式、混合 3 种；集中式便于统一观察与决策但易拥塞且管理站故障即全网崩溃，分布式把管理功能分布到被管设备、就近决策，混合式取长补短。

集中式由中心管理站组织全网管理，便于统一观察和决策，但中心负担、通信集中和故障影响需要考虑。分布式把部分管理职责靠近资源或问题来源，减少事事依赖中心，却需要协调信息与动作。混合方式把两者结合，不是简单把两套软件同时启动。

场景：三个园区各自采集接口状态，本地处理简单故障，总部汇总趋势并统一调整策略。分析时分别画采集、局部处理与统一决策的位置，可以辨认为分布与集中结合。只看管理窗口有几个，无法判断整个体系结构。

## 4 五类管理功能与排障证据 {#s4}

**必背：** 五类功能是故障、配置、安全、性能和计费管理；故障管理含检测和报警与预测与诊断定位 3 个模块，性能指标中可用性与响应时间面向服务、吞吐量与延迟与丢包率与利用率面向效率。

故障管理发现、告警、定位和处理异常；配置管理维护设备参数与资源关系；安全管理控制非法使用和保护信息；性能管理持续测量并分析瓶颈；计费管理记录资源使用并按策略核算。相同事件可以触发多类工作，不必强行只归一类。

记录：某接口差错计数上升，是监测证据；确认链路故障并定位属于故障管理；调整参数属于配置管理；比较吞吐量变化属于性能管理；检查未授权修改属于安全管理；根据使用量核算费用属于计费管理。先保留时间、对象、观测值和动作，再作判断，不能把一个计数上涨直接写成唯一故障原因。

## 5 SNMP、对象标识与报文 {#s5}

**必背：** SNMP 由 SNMP 协议与管理信息库与管理信息结构 3 部分构成，操作只有 Get、Set、Trap 三种，前两者由管理站发起；它用 UDP 承载、报文不超过 484 字节；mib-2 的 OID 为 1.3.6.1.2.1，其下有 11 个对象组。

SNMP 体系结合协议、SMI 和 MIB。Get 由管理站发起读取，Set 由管理站发起设置，Trap 由代理报告事件。轮询是管理站周期读取；事件通报是代理发起。两种方式可以配合，不能把 Trap 本身解释成管理站发起的一次轮询。

SMI 按对象树命名，以 OID 标识对象，并规定数据类型与编码。MIB 把这些可管理对象组织起来；例如书中 mib-2 的 OID 为 `1.3.6.1.2.1`，其下继续按功能分支。背出一串数字不等于已知道某对象的类型、含义或读写权限。

读报文重点看 PDU 类型、请求标识、差错状态/索引和变量绑定。请求标识帮助把响应对应到请求，变量绑定携带对象名及有关值；SetRequest 请求修改，GetRequest 请求读取，GetBulkRequest 用于批量读取，Trap 类报文报告事件。教材并列介绍了不同版本的机制，不能把版本字段、安全参数和所有 PDU 都拼成一个通用于各版的固定格式。

本书 SNMP 使用 UDP 承载；没有收到响应要区分网络、代理、权限和请求本身的问题，不能以“UDP 高效”推导管理命令必达。共同体名属于教材中的一种简易认证安排，不把它当成任何网络中的充分安全方案。

## 6 网络管理系统与工具选择 {#s6}

**必背：** NMS 是保障网络正常运行的软硬件综合系统，特点是全面监控性能、主动预警、全网联动、有效管理资源、服务质量管理，趋势是开放性、综合性、智能化、安全性和基于 B/S 结构；常见产品有 OpenView、Tivoli NetView、CiscoWorks 与 Cacti。

NMS 把发现、采集、显示、告警和管理应用组织成可操作系统，作用不止画设备图。MIB 浏览器便于查看对象树及变量，命令行便于明确执行读取或设置，Sniff 类工具观察管理报文；三个角度相互补充，不是互相替代。

本版教材列举 OpenView、Tivoli NetView、CiscoWorks 和 Cacti，并讨论开放、综合、智能、安全以及 B/S 管理的发展方向。这里用于识别产品定位与系统能力，不把书中介绍当成当前购买建议。选择条件应先明确对象范围、所需协议、采集和告警、图表或配置能力，再判断工具是否适合，而不是只看产品名称是否熟悉。

## 本章小结

- 管理站、代理、协议、MIB、SMI 分别对应管理者、执行端、通信规则、对象信息和描述规则，不能把逻辑集合等同某个数据库产品。
- Get 轮询由管理站发起，Trap 由代理报告；解析回复还要核对请求标识、变量绑定和差错信息，不能只看到达顺序。
- 故障、配置、安全、性能和计费可能同时参与一次处置。先记录时间、对象、观测与动作，再判断原因；历史 NMS 举例不是当前采购结论。

## 练习

**1. 管理员每天只看设备是否在线，自称已完成全部网络管理。列出至少三项还需要围绕目标检查的工作，以及它们可能涉及的软件对象。**

考点：第 1、4 节；层次：识记、领会。

**答案：** 还需性能测量与瓶颈分析、配置维护、权限和安全检查、故障定位或使用量核算等。对象不仅有硬件，也可有操作系统、应用与通信软件；“在线”只是某一观察，不能替代各类管理目标。

**2. 一次接口读取中，谁发请求、谁返回变量值？MIB 与 SMI 是否分别等同“数据库软件”和“采集软件”？**

考点：第 2、5 节；层次：领会。

**答案：** 管理站发起读取，代理返回相应对象值。MIB 是管理对象信息的逻辑集合，SMI 规定命名、类型与表示；二者不能直接等同具体数据库和采集程序。协议负责把操作在双方间表达和传输。

**3. 三个园区本地处置简单故障，总部汇总趋势并制定统一策略。解释这种管理模式的分工及需要协调的事情。**

考点：第 3 节；层次：领会。

**答案：** 该场景将局部处理分布到园区，把全局分析与策略集中在总部，可按混合模式理解。需要协调对象标识、观测时间、告警汇总与配置动作，否则局部独立决策可能与统一策略冲突。

**4. 一组记录依次为“发现丢包”“定位接口故障”“修改配置”“比较吞吐变化”“核算用量费用”。分别映射功能，并补一个安全管理动作。**

考点：第 4 节；层次：领会。

**答案：** 前两步主要属于故障发现与定位，修改属于配置管理，比较吞吐属于性能管理，核算属于计费管理；检查该修改是否获授权可属于安全管理。同一事件可跨功能处理，不需要强制唯一分类。

**5. 管理站周期 Get，与代理主动 Trap，方向有何不同？请求标识与变量绑定各帮助解释报文的哪一部分？**

考点：第 5 节；层次：领会。

**答案：** 周期 Get 由管理站发起读取，Trap 由代理发起事件通报。请求标识关联响应和相应请求，变量绑定说明被操作的对象名及相关值；不能把返回了某个请求标识理解成被管对象名称。

**6. 发现两个回复乱序到达，为什么不能按到达先后当成同一请求的结果？若还要观察异常 PDU，可选哪类工具？**

考点：第 5、6 节；层次：领会、识记。

**答案：** 应核对请求标识、对象和差错信息，不能把网络到达顺序当成请求配对依据。MIB 浏览器适合查看对象，Sniff 类工具适合观察报文，命令行可明确重现某个读取；选择随所需证据而变。

**7. 拟选 NMS 时只因教材出现某产品名就直接采用，缺少了哪些判断？**

考点：第 1、6 节；层次：识记。

**答案：** 需要先列被管对象、协议及权限、采集频率、告警、配置与展示需求，并比较适用范围和管理成本。教材产品举例属于所列版本的学习材料，不能自动成为当前产品能力和采购结论。
