### 必背名词

| 术语 | 必背一句话 | 常考 |

| 不可抵赖性 | 防止通信实体在发生通信行为后否认其通信行为，也称防止抵赖 | 单选 |

| 非对称密钥密码体制 | 又称双密钥密码体制，加密密钥和解密密钥不同且难以从一个推出另一个，公钥公开、私钥保密 | 简答 |

| 证书 | 每一个用户与其公钥的绑定，由 CA 颁发 | 填空 |

| 端到端加密 | 在信息的源点加密、在信息的终点解密，中间结点与链路中始终是密文的方式 | 简答 |
| 数字签名 | 用于证明网络中所传文件数据真实性的技术，可实现验证身份、发送方不能否认、接收方不能编造三个功能 | 简答 |
| 报文鉴别 | 接收者收到报文后能确认该报文由发送者所发且未经他人篡改的鉴别方式 | 简答 |

| 鉴别首部 AH | 提供源站点鉴别和数据完整性服务、但不能进行数据加密的安全控制机制 | 简答 |

| 计算机病毒 | 编制或者在计算机程序中插入的破坏计算机功能或毁坏数据、影响计算机使用并能自我复制的一组计算机指令或程序代码 | 简答、填空 |

### 必背清单

**第 1 节**

1. 【考纲 1.1】计算机网络面临的威胁分三方面：网络实体面临的威胁、网络系统面临的威胁和恶意程序的威胁。
2. 【考纲 1.1】网络实体包括工作站与服务器等计算机设备、交换机与路由器与集线器等网络设备、磁带与磁盘与光盘等存储设备、通信线路、供电设备以及防护设备。
3. 【考纲 1.1】典型的网络系统威胁有窃听、重传、伪造、篡改、非授权访问、拒绝服务攻击、行为否认、电磁截获和人员疏忽。
4. 【考纲 1.1】恶意程序又称恶意代码，指以危害信息安全等不良意图为目的的程序，包括计算机病毒、网络蠕虫、特洛伊木马和逻辑炸弹等类型。
5. 【考纲 1.1】恶意程序的主要特点是由人编制而非自生、对系统具有破坏性或威胁性；按种类不同具有潜伏性、传染性和依附性。
6. 【考纲 1.2】网络安全是利用管理控制和技术措施，保证在计算机网络环境中数据信息的机密性、完整性和可用性受到保护。
7. 【考纲 1.2】个人或单位用户希望隐私与商业信息受机密性、完整性和不可否认性保护；运营管理者希望非授权使用被发现和阻止；安全保密部门还要制定行为准则与规范。
8. 【考纲 1.3】网络安全的基本目标有 5 个：机密性、完整性、可用性、不可抵赖性和可控性。
9. 【考纲 1.3】可用性主要通过提供备份、提升设备冗余和进行访问控制等方式实现；机密性通过技术的（如加密、干扰等）和非技术的（如权限控制等）手段实现保护与隔离。
10. 【考纲 1.4】网络安全分 4 个层次：物理安全、逻辑安全、操作系统安全和联网安全。
11. 【考纲 1.4】物理安全是整个网络安全的基础，范畴含机房环境安全、通信线路安全、设备安全和电源安全。
12. 【考纲 1.4】逻辑安全主要通过口令密码、软件加密和权限控制等方法实现；操作系统安全主要包括用户权限控制和安全漏洞修复；联网安全针对访问和传输行为进行防护。
13. 【考纲 1.5】典型网络安全技术有 7 项：加密技术、鉴别技术、防火墙技术、访问控制技术、防病毒技术、监控审计技术和备份技术。
14. 【考纲 1.6】常用安全措施有 7 项：物理隔离、逻辑隔离、加密通信、采用专用网或虚拟专用网、病毒防御、身份认证和网络管理与审计。
15. 【考纲 1.6】物理隔离彻底去除与外部网络的线路连接，可彻底防范来自网络的攻击但失去互联；逻辑隔离保持连接而在逻辑上控制某些业务，主要方法是使用防火墙。
16. 【考纲 1.6】专用网租用通信线路、安全程度高但费用昂贵；虚拟专用网 VPN 利用公用 Internet 作为传输通道，用 IP 隧道技术和加密技术在逻辑上实现数据业务独享通信链路。

**第 2 节**

17. 【考纲 2.1】信息加密的要素：明文是输入的原始信息，密文是加密变换后的结果，密钥是参与密码变换的参数，加密算法把明文变换为密文，解密算法把密文恢复为明文。
18. 【考纲 2.1】信息加密的要求是 $P=D_k(E_k(P))$，即用加密算法得到的密文总是能用一定的解密算法恢复出原始明文。
19. 【考纲 2.1】无条件安全或理论上不可破译指无论攻击者获取多少密文都无法唯一确定对应明文；实际更关心在一定时间和计算资源限制下密码体制是否可被破译。
20. 【考纲 2.2】对称密钥体制的保密性主要取决于对密钥的保密，加密和解密算法是公开的；密钥由发送方产生并经保密信道传递给接收方，或由可信第三方生成后分别发送。
21. 【考纲 2.2】DES 是最有影响的对称密钥密码体制，1977 年由美国国家标准局颁布；把明文分成若干组、每组 64 位二进制数据，加密后产生 64 位密文。
22. 【考纲 2.2】DES 采用 64 位密钥，其中有效密钥 56 位、8 位用于奇偶校验，密钥空间为 $2^{56}$；因 56 位已不够安全，出现了使用 128 位密钥的 IDEA。
23. 【考纲 2.2】非对称密钥体制每次生成一对密钥，公钥作为加密密钥向公众公开，私钥作为解密密钥由用户自己保密，算法公开；产生原因一是解决密钥管理与分配问题，二是满足数字签名需求。
24. 【考纲 2.2】最著名的非对称密钥密码体制是 1978 年由 Rivest、Shamir 和 Adleman 发表的 RSA 密码体制。
25. 【考纲 2.3】n 个用户中任意两人加密通信且密钥相同，共需 $n(n-1)$ 个密钥；若每两个用户共享一个密钥，则需 $n(n-1)/2$ 个。
26. 【考纲 2.3】KDC 为每次加密通信分配只使用一次的密钥；用户先在 KDC 登记并取得与 KDC 通信的主密钥，KDC 用随机数产生会话密钥并连票据一起用请求方主密钥加密回送。
27. 【考纲 2.3】票据中含双方在 KDC 登记的身份和会话密钥，并用接收方主密钥加密；接收方用自己主密钥解密后即知会话密钥。
28. 【考纲 2.3】应用最广泛的对称密钥分配协议是 MIT 开发的 Kerberos，设鉴别服务器 AS 和票据授予服务器 TGS，AS 具备 KDC 功能并保存登记身份与主密钥。
29. 【考纲 2.3】公钥体制下发送方可冒充他人发送自己的公钥，因此需认证中心 CA 把公钥与真实身份标识绑定并颁发证书；公钥分配遵循 ITU-T 的 X.509 协议，以此为基础形成公钥基础结构 PKI。
30. 【考纲 2.4】信息加密方式有 3 种：链路加密、结点加密和端到端加密。
31. 【考纲 2.4】链路加密每条链路独立加密，某条链路被攻破不影响其他链路，且整报文解密再加密可隐藏源地址与目的地址与报文长度；最大问题是各结点上信息以明文存在。
32. 【考纲 2.4】链路加密不适用于广播网络，且单密钥体制下每个结点都要保存相邻结点的密钥，增加密钥管理复杂度。
33. 【考纲 2.4】结点加密是对链路加密的补充，在结点采用不同密钥加密保存明文，使结点中不出现明文。
34. 【考纲 2.4】端到端加密在源点加密、终点解密，中间结点与链路中始终是密文，价格便宜、管理维护方便；但源地址与目的地址与路由等控制信息不能加密，易被业务分析。
35. 【考纲 2.5】数字签名必须实现 3 个功能：接收方可以验证发送方所宣称的身份、发送方发出数据后不能否认、接收方不可能自己编造信息。
36. 【考纲 2.5】数字签名的实现方法分对称密钥签名和公钥签名两种；公钥签名时发送方用自己的私钥做 D 运算，接收方用发送方公钥做 E 运算。
37. 【考纲 2.5】公钥签名可证明报文来源并可发现篡改，但这样的过程只能对报文签名而不能进行加密。
38. 【考纲 2.5】鉴别是参加通信的实体验证对方是自己所要通信的对象；最常用的鉴别技术是报文鉴别，进行数字签名是报文鉴别的主要手段。
39. 【考纲 2.5】报文摘要用单向哈希函数把任意长度输入算出固定位数输出，单向指从输出推回输入不可实现；最常用的报文摘要算法是 RFC 1321 提出的 MD5，输出固定长度 128 位。
40. 【考纲 2.5】MD5 的运算先把报文按模 $2^{64}$ 取余追加在报文后，再填充使总长度为 512 的倍数，然后分成 512 位数据块并每块分 4 个 128 位子块做 4 轮运算；SHA 原理相似但摘要为 160 位。

**第 3 节**

41. 【考纲 3.1】IPsec 由 IETF 设计、工作在网络层，主要功能是对 IP 数据报加密并确保目的站点确信报文来自源 IP 地址主机。
42. 【考纲 3.1】IPsec 在源与目的主机之间建立安全关联 SA，SA 是单工连接、带安全标识符，每个分组携带该标识符供目的主机查询密钥等信息。
43. 【考纲 3.1】IPsec 的两种安全控制机制是鉴别首部 AH 和封装安全有效载荷 ESP；AH 只提供鉴别与完整性而不加密，ESP 还提供数据加密，二者可单独或嵌套使用。
44. 【考纲 3.1】IPsec 有传输模式和隧道模式两种工作模式：传输模式保护 IP 数据报的上层协议数据，隧道模式对整个 IP 数据报进行保护。
45. 【考纲 3.1】AH 用报文摘要验证 IP 数据报以发现篡改，其字段含下一首部 8 bit、有效载荷长度 8 bit、保留 15 bit、安全参数索引 32 bit、序号 32 bit 和可变长报文鉴别码；IP 首部协议字段置为 51。
46. 【考纲 3.1】AH 工作在传输模式时插在 IP 首部之后、被保护的上层协议之前；隧道模式时把原数据报完全封装并在 AH 之前另加新的 IP 首部。
47. 【考纲 3.1】ESP 字段中 SPI 与序列号构成 ESP 首部，填充与填充长度与下一个首部构成 ESP 尾部，填充长度是 8 bit 字段、范围 0 至 255；IP 首部协议字段置为 50。
48. 【考纲 3.1】ESP 的工作过程是先加尾部并加密有效载荷与尾部，再加 ESP 首部（隧道模式还要加新 IP 首部），最后对首部与载荷与尾部做摘要生成 MAC 附在尾部之后。
49. 【考纲 3.1】因 AH 的功能都包含在 ESP 中且 ESP 还能加密，AH 在 IPsec 中已很少使用；隧道方式常用来实现虚拟专用网 VPN，IPsec 体系还包括 SAD、SPD 和 IKE。
50. 【考纲 3.2】SSL 由 Netscape 公司于 1994 年推出，作用在应用层 HTTP 和传输层之间，在 TCP 上建立安全通道；从 3.1 版起由 IETF 接管并标准化更名为 TLS。
51. 【考纲 3.2】SSL/TLS 的安全目标有 4 个：认证性、机密性、完整性和重放保护。
52. 【考纲 3.2】SSL/TLS 用公钥加密方法，服务器把公钥放在数字证书中传给客户端以保证公钥不被篡改，双方再协商生成对称的对话密钥以降低公钥运算量。
53. 【考纲 3.2】SSL/TLS 的基本过程 3 步：客户端向服务器索要并验证公钥、双方协商生成对话密钥、双方用对话密钥加密通信；前两步合称握手阶段。
54. 【考纲 3.2】浏览器访问过程：询问双方支持的算法、请求并回应证书、浏览器产生会话对称密钥并用服务器公钥加密后传给服务器、双方用该对称密钥加解密 HTTP 请求与响应。

**第 4 节**

55. 【考纲 4.1】防火墙是位于被保护网络或主机与外部网络之间执行访问控制策略的一个或一组系统，基本思想是把内部网络和外部网络有目的地隔离和控制。
56. 【考纲 4.1】防火墙的基本防护功能：过滤进出网络的数据、管理进出网络的行为、封堵需要禁止的业务、记录进出网络的信息和动作、对网络攻击进行检测和警告。
57. 【考纲 4.1】按工作原理防火墙技术分包过滤技术、代理服务技术、状态监测技术和 NAT 技术。
58. 【考纲 4.1】包过滤按源地址与目的地址与源端口与目的端口及协议状态选择是否放行，过滤逻辑的集合称访问控制列表 ACL；逻辑简单、价格便宜、对用户透明。
59. 【考纲 4.1】包过滤的缺点：多数基于 IP 地址而地址容易被假冒，只能鉴别网络层和传输层的有限信息、不能识别具体应用，安全防护性能较差。
60. 【考纲 4.1】代理服务器代表客户端处理连接请求，在内外网之间起中间转接和隔离作用，工作在应用层，可分析应用层协议发现不安全因素；分应用层网关防火墙和电路层网关防火墙。
61. 【考纲 4.1】应用层网关防火墙安全性高、可记录控制流量，但处理速度慢且对用户不透明、需在客户端安装配置。
62. 【考纲 4.1】状态检测防火墙在网关处设检测引擎，把同一连接的数据报作为整体数据流看待构成连接状态表，比包过滤更灵活更安全。
63. 【考纲 4.1】NAT 把内部私有地址转换成合法公用地址，使外部无法了解内部地址分布、通信只能由内部发起，从而提高安全性；但地址转换不等于内容加密或完整授权。
64. 【考纲 4.2】个人防火墙以软件形式安装在个人计算机上，位于操作系统和网卡之间，可看作一个虚拟网络接口，按预设规则允许或禁止与外部网络的连接。
65. 【考纲 4.2】个人防火墙的 7 项功能：IP 数据报过滤、安全规则设定、网络攻击拦截、网络访问控制、日志记录、网络快速切断与恢复和更新升级。
66. 【考纲 4.2】防火墙规则是描述语句，每条规则对应一种行为判断，按端口与协议类型等条件对报文拦截或放行；配置需兼顾安全与效率，通常由厂商预置并通过升级更新。

**第 5 节**

67. 【考纲 5.1】计算机病毒的定义：编制或者在计算机程序中插入的破坏计算机功能或毁坏数据、影响计算机使用并且能够自我复制的一组计算机指令或程序代码。
68. 【考纲 5.1】木马通过把自身伪装成其他正常软件吸引用户下载执行，一旦被植入，攻击者可利用其远程控制功能控制计算机并窃取信息。
69. 【考纲 5.1】网络蠕虫是可以自我复制、传播不需要借助被感染主机中其他程序、无须人工干预即可运行的完全独立程序，通常利用系统漏洞和设置缺陷自动传播。
70. 【考纲 5.1】计算机病毒的主要传播途径是互联网中的数据和软件下载、电子邮件附件的打开以及移动存储设备的交叉使用。
71. 【考纲 5.1】杀毒软件的基本工作原理是分析病毒程序提取特征代码形成病毒特征数据库，扫描内存和磁盘并把文件逐一与特征代码比较，从而发现并清除感染文件。
72. 【考纲 5.1】全盘扫描对整个磁盘空间扫描、用时较长，快速扫描只对容易被感染的区域扫描、用时较短；病毒特征库需及时更新升级。

**第 6 节**

73. 【考纲 6.1】良好的操作使用习惯主要包括及时安装系统补丁和及时进行数据备份。
74. 【考纲 6.1】补丁是为解决软件投入使用后发现的缺陷而编写的更新小程序，安装方式有利用系统自带的更新程序和使用第三方软件两种。
75. 【考纲 6.1】个人数据备份按位置分本地备份和异地备份，手段有人工备份和使用专门软件工具备份；备份到本机硬盘最简便但安全系数最低，应尽量与原始数据分开保存。
76. 【考纲 6.1】个人用户需备份的数据按重要性分三类：个人制作和编辑的文件、常用软件和驱动程序、系统自动生成或用户添加形成的个人信息。
77. 【考纲 6.1】备份需要有效管理：介质妥善保存并贴标签注明内容、每次备份标明时间并按统一方式命名、按需要确定保留时间。
78. 【考纲 6.2】使用互联网首先要遵守国家计算机和互联网的相关法律法规，自觉维护健康文明有序的互联网环境。
79. 【考纲 6.2】普通用户应遵守的规定：不侵犯软件著作权、不利用信息系统从事危害国家利益与集体利益与公民合法利益的活动、不制作查阅复制传播妨碍社会治安和淫秽色情的信息、不擅自进入未经许可的计算机系统或篡改他人信息、不制造和传播计算机病毒。

### 易混对照

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 机密性与完整性 | 机密性限制谁能获知，完整性关注是否被不当改变 | 内容有没有泄露还是有没有被改 |
| 可用性与机密性 | 可用性关注需要时能否获得资源，机密性关注谁能读取 | 系统瘫痪但未泄密仍属可用性问题 |
| 不可抵赖性与可控性 | 不可抵赖性提供行为证据，可控性强调管理与约束能力 | 是否需要事后举证 |
| 对称与非对称体制 | 对称双方共享同一密钥，非对称公钥公开、私钥保密 | 加密与解密用的是不是同一把密钥 |
| 公钥加密与私钥签名 | 保密发送用接收方公钥加密，签名用发送方私钥 | 目标对象是对方还是自己 |
| 数字签名与加密 | 签名证明来源与不可否认但不隐藏内容，加密限制谁能阅读 | 目标是真实性还是保密性 |
| 报文摘要与报文鉴别码 | 摘要只是固定位数的运算结果，MAC 是用私钥对摘要签名后的数据 | 有没有可信的签名保护 |
| 链路加密与端到端加密 | 链路加密逐段保护、结点出现明文；端到端从源点到终点、控制信息仍需可见 | 明文出现在哪一层 |
| 结点加密与链路加密 | 结点加密在链路加密基础上使结点内不出现明文 | 中间结点是否保存明文 |
| AH 与 ESP | AH 只鉴别与完整性，ESP 还可加密 | 内容是否被加密 |
| 传输模式与隧道模式 | 传输模式保护上层协议数据，隧道模式保护整个 IP 数据报并另加新 IP 首部 | 被保护的范围有多大 |
| IPsec 与 SSL/TLS | IPsec 在网络层、SSL/TLS 在应用与传输之间 | 保护发生在哪一层 |
| 包过滤与状态检测 | 包过滤孤立判断单个报文，状态检测把同一连接作为整体并结合状态表 | 是否参考前后报文 |
| 包过滤与代理 | 包过滤在网络层透明且快，代理在应用层分析但慢且不透明 | 用户是否需要在客户端配置 |
| 物理隔离与逻辑隔离 | 物理隔离断开线路，逻辑隔离保持连接而控制业务 | 线路是否断开 |
| 病毒与木马 | 病毒能自我复制并破坏功能或数据，木马靠伪装吸引执行并提供远程控制 | 传播方式与目的不同 |
| 木马与蠕虫 | 木马需要用户执行伪装程序，蠕虫可独立自动传播 | 是否需要人工干预 |
| 全盘扫描与快速扫描 | 全盘扫描整个磁盘、用时较长，快速扫描只查易感染区域、用时较短 | 覆盖范围不同 |
| 补丁与备份 | 补丁修补软件缺陷，备份用于数据损坏或丢失后的恢复 | 解决的是缺陷还是数据 |
| 本地备份与异地备份 | 本地备份在同一台机器的硬盘或分区，异地备份放在相隔离的介质 | 与原始数据是否物理分离 |

### 简答答题模板

**计算机网络安全的基本目标**

5 项各一句：机密性使信息不泄露给非授权用户，在存储与传输各环节用加密和权限控制保护；完整性保证信息准确有效、在存储和传输中不被修改破坏或丢弃；可用性保证资源和数据在需要时能顺畅获得，靠备份与冗余与访问控制实现；不可抵赖性防止通信实体事后否认行为，需要有可核验的证据与审计记录；可控性保证管理者对系统与所传播信息的范围和内容有控制能力。

**对称密钥体制与非对称密钥体制的比较**

对称体制加密密钥与解密密钥相同，算法公开、保密性取决于密钥保密，密钥需通过保密信道传递，密钥数量随用户增长而迅速膨胀，典型是 DES 与 IDEA。非对称体制用一对密钥，公钥公开作加密密钥、私钥保密作解密密钥，算法也公开，无需传递私钥，简化了密钥管理与传输并能支持数字签名，典型是 RSA；代价是运算量大，且仍需解决公钥与身份的绑定问题，故需 CA 与证书。

**链路加密、结点加密与端到端加密的区别**

链路加密对相邻结点间数据加密，每条链路独立，可隐藏源地址与目的地址与报文长度，但各结点上信息以明文存在，且不适用于广播网络。结点加密在链路加密基础上于结点用不同密钥加密保存明文，使结点不出现明文。端到端加密在源点加密、终点解密，中间结点和链路始终是密文，便宜且易维护，但源地址与目的地址与路由等控制信息不能加密，容易被业务分析。

**数字签名的功能与实现方法**

3 个功能：接收方能验证发送方身份、发送方发出后不能否认、接收方不能自己编造信息。实现有两种：对称密钥签名依靠可信权威机构 S 中转，S 用与发送方共享的密钥确认来源并用自己的密钥对明文与发送方标识签名，再加密发给接收方；公钥签名由发送方用自己的私钥做 D 运算，接收方用发送方公钥做 E 运算还原明文，篡改会使还原结果不可读，争议时可由第三方用公钥验证。该过程只签名不加密。

**IPsec 的 AH 与 ESP 有何区别，两种模式各保护什么**

AH 提供源站点鉴别和数据完整性，用报文摘要发现篡改，但不进行数据加密，IP 首部协议字段置 51。ESP 除鉴别与完整性外还提供加密，协议字段置 50，其工作过程是先加密载荷与尾部、再加首部、最后生成 MAC。传输模式保护 IP 数据报的上层协议数据，主机到主机通信时使用；隧道模式对整个 IP 数据报加封装并另加新 IP 首部，只需路由器运行 IPsec，常用于构建 VPN。

**防火墙技术的分类与个人防火墙的功能**

按工作原理分包过滤、代理服务、状态监测和 NAT 四类：包过滤按地址与端口与协议查 ACL，简单透明但只能看有限首部信息；代理在应用层代为转接，安全但慢且不透明；状态检测把同一连接作为整体并结合状态表判断；NAT 隐藏内部地址分布但不等同加密与授权。个人防火墙 7 项功能：数据报过滤、安全规则设定、攻击拦截、访问控制、日志记录、快速切断与恢复、更新升级。

## 1 威胁、目标与判断对象 {#s1}

**必背：** 威胁分实体、系统、恶意程序三方面；安全目标 5 个：机密性、完整性、可用性、不可抵赖性、可控性；异常不必都来自外部攻击，加密不能直接解决可用性问题。

安全分析先说保护什么、面对什么威胁。设备可受环境事故或人为破坏，系统可遭窃听、伪造、非授权访问与拒绝服务，人员疏忽和恶意代码也会造成损害。异常不必都来自外部攻击，故障和误操作同样需要防范。

机密性限制谁能获知信息，完整性关注信息不被不当改变，可用性关注需要时能否获得资源；不可抵赖性强调对行为提供可核验的证据，可控性强调管理和约束能力。加密主要解决保密等问题，不能直接令服务永不停机。判断中，“内容没泄露但系统瘫痪”仍有可用性问题。

## 2 安全层次与组合防护 {#s2}

**必背：** 安全层次 4 个：物理安全、逻辑安全、操作系统安全、联网安全；主要技术 7 项，常用措施 7 项，其中物理隔离断开线路、逻辑隔离靠防火墙保持连接而控制业务。

物理安全关注设施与环境，逻辑安全关注访问规则；安全层次还覆盖操作系统和联网行为。防火墙不能代替机房防火与供电保护，机房门禁也不能代替账户和权限管理。防护要联系不同入口与失效方式，而不是只采购一种软件。

物理隔离去除相应外部连接，逻辑隔离保持连接但限制业务；加密通信保护有关数据，专用网或 VPN 服务于相应连接需求，病毒防御、身份认证、管理和审计又各补充不同方面。每种措施有适用条件和代价。教材范围中的技术名称用于辨别机制，不把“已使用 VPN”解释成端点、账户和应用都已安全。

## 3 对称与非对称密码体制 {#s3}

**必背：** 对称体制的加密与解密密钥相同、算法公开、保密性取决于密钥；非对称体制的公钥公开作加密密钥、私钥保密作解密密钥；保密发送给 B 用 B 的公钥，签名用 A 自己的私钥；DES 分组 64 位、有效密钥 56 位，IDEA 用 128 位密钥。

加密把明文按算法和密钥变成密文，解密按相应条件还原。算法可以公开，不能把安全性只寄托在别人不知道算法名称。密钥产生、传递、保存和使用，都是体制的一部分。

对称体制使用相同或相应共享秘密进行加解密，通信双方要安全获得并保护密钥。非对称体制使用公钥与私钥的配对关系，私钥由持有者保密。需要让 A 向 B 保密发送时，按本书公钥加密模型使用 B 的公钥加密、B 的私钥解密；不是把发送方私钥当成任何加密任务的万能答案。加密与签名目的不同，密钥方向也要随任务辨认。

## 4 密钥分配与保护位置 {#s4}

**必背：** 对称密钥数有方向为 $n(n-1)$、每对一把为 $n(n-1)/2$；KDC 分配会话密钥与票据，CA 把公钥与身份绑定并颁发证书，遵循 X.509；加密方式分链路、结点、端到端，判断依据是明文在何处出现。

共享密钥若逐对独立安排，会随用户数量增长而增加管理负担。条件：6 人任意两人共享一把不同密钥，共需 6×5÷2=15 把；这是无方向区分、每对一把的模型。KDC 通过可信分配中心帮助安排会话密钥，公钥体系则还要解决所取公钥是否确实属于目标身份，CA 和证书承担相应身份绑定与验证。

链路加密逐段保护，相邻节点处可能解密后再加密；结点加密补充节点内部保护；端到端加密从源点保护到终点，中间节点仍需读取完成转发所必需的控制信息。比较方案时明确哪些地方出现明文、谁持有什么密钥，不只比较名字听起来是否安全。

## 5 签名、摘要与鉴别 {#s5}

**必背：** 数字签名的 3 个功能是验证身份、发送方不能否认、接收方不能编造；公钥签名用发送方私钥做 D 运算、用发送方公钥做 E 运算；MD5 输出 128 位摘要、SHA 输出 160 位；摘要没有可信保护时不能独自建立身份。

数字签名用于验证来源和内容关联，并为不可抵赖性提供技术依据；在公钥签名模型中，发送者用自己的私钥签名，接收者用发送者公钥验证。保密发送则使用接收者的公钥，两个方向对应两个任务。签名本身不自动隐藏明文内容。

摘要把报文映射为较短的固定长度值，便于参与完整性检查；鉴别还需要核对身份、密钥或可信签名等条件。只收到一个没有可信保护的摘要，不能由它认定发送者身份，也不能把“摘要相同”说成任何条件下都绝无碰撞。教材对具体摘要算法的安全性有时点性论述，本节保留作用与边界，不据该版措辞给出现行算法选型结论。

## 6 IPsec 与 SSL/TLS 的位置 {#s6}

**必背：** IPsec 在网络层，AH 只鉴别不加密（协议号 51），ESP 可加密（协议号 50），传输模式保护上层协议数据、隧道模式保护整个 IP 数据报；SSL/TLS 位于应用与传输之间，安全目标是认证性、机密性、完整性、重放保护，握手只用公钥换对话密钥。

IPsec 在网络层组织安全机制，不是一个单独的“加密命令”。按教材范围，AH 提供鉴别、完整性等保护而不负责内容加密，ESP 可在相应安排下提供保密并结合鉴别等能力；传输模式和隧道模式涉及保护与封装范围的区别。不能因出现 AH 就断定内容已被加密。

SSL/TLS 位于应用与其传输服务之间组织安全通信，教材介绍其协商、身份验证及后续保护数据的过程。握手用于建立相关安全参数和条件，后续记录传送不是把每个应用字节都重复握手。这里学习两类机制处于何处、保护什么，不把书中 SSL 示例视为现行安全配置推荐，也不声称只开某个名称便已正确验证对方身份。

## 7 防火墙规则与边界 {#s7}

**必背：** 防火墙位于被保护网络与外部网络之间执行访问控制策略，技术分包过滤、代理服务、状态监测和 NAT 四类；规则要写清方向、源、目的、协议、端口和允许或拒绝；NAT 转换地址不等于加密或授权。

防火墙在网络或主机边界按策略控制通信。包过滤检查地址、端口和协议等条件，规则集合可表示为 ACL；代理在客户与服务之间代为处理有关请求；状态检测结合连接状态，而不是只孤立检查一个包。教材也讨论 NAT 对隐藏内部地址的作用，但地址转换不等于内容加密或完整授权。

个人防火墙还涉及规则、告警、应用访问控制、日志与更新。规则任务应写清方向、源、目的、协议、端口和允许/拒绝的条件，再观察日志及实际业务。遇到连接问题直接关闭全部防护，会失去所需的边界控制；更好的分析是定位具体被拒绝的业务并核对其必要性。

防火墙不能消除所有风险：被允许的通信中仍可能含恶意内容，内部误操作和设备故障也不因边界过滤而消失。是否需要放行与是否已经可信，不能用同一个判断替代。

## 8 病毒、木马、蠕虫与防范 {#s8}

**必背：** 计算机病毒是能自我复制、破坏功能或毁坏数据的一组指令或程序代码；木马靠伪装吸引执行并提供远程控制，蠕虫可独立自动传播；杀毒软件靠特征代码比对，特征库要及时更新，全盘扫描与快速扫描覆盖不同。

计算机病毒具有破坏和自我复制等特征，木马以伪装吸引执行并可能提供恶意控制，蠕虫可作为独立程序利用网络传播。它们有共同的恶意性，也有传播和运行方式差别；不能把所有可疑程序都按同一条传播链推断。

防范结合来源核对、补丁、扫描与更新、处理可疑附件和介质等措施。特征库检测依赖已掌握的信息，快速扫描与全盘扫描覆盖不同；扫描未发现不等于任何恶意行为绝不可能存在。处置练习先隔离可疑传播与保留必要记录，再按环境安排检查和恢复，不能为了观察效果运行未知附件。

## 9 操作习惯、备份与责任 {#s9}

**必背：** 良好习惯主要是及时安装系统补丁和及时进行数据备份；补丁修补缺陷、备份用于恢复，二者不能互相替代；备份分本地与异地并标明内容与时间；操作要遵守授权与法律法规，明确范围与记录责任。

系统补丁用于修补发现的问题，备份帮助在数据损坏或丢失后恢复，二者不能互相替代。不随意打开未知附件、不下载来历不明程序、核对介质和权限，有助于减少风险来源。备份应标明内容与时间，保存到与原数据风险适当分离的位置，不能只因同一磁盘多了一个目录就认定所有故障均可恢复。

遵守授权和有关法律法规是安全活动的前提。练习只在本人有权操作的环境及明确范围内进行，不因掌握了工具便扩大扫描或访问对象。本书所列法规则属于该版学习背景，本节不据此列出现行条文或作法律适用判断；重点是把权限、操作边界与记录责任落实到任务中。

## 本章小结

- 先明确机密性、完整性、可用性等目标，再选组合防护；加密、备份、防火墙与身份认证不能互相替代。
- 按本章公钥模型，保密发送给 B 用 B 公钥，A 签名用 A 私钥；摘要没有可信保护时不能独自建立身份关系，AH 也不负责内容加密。
- 把规则落实到方向、源、目的、协议和端口，再核对记录及实际业务。未知附件、检测遗漏和备份同盘风险需分别处理，所有操作限于授权范围。

## 练习

**1. 系统中的文件未泄露，但合法用户连续无法获取服务。影响哪个安全目标？为什么加密不能独自解决该问题？**

考点：第 1、2 节；层次：识记。

**答案：** 主要涉及可用性。加密可保护有关内容，却不直接解决供电、硬件故障、负载或拒绝服务等全部原因；需要结合物理环境、系统、网络控制和恢复安排分析，不能只看是否泄密。

**2. A 给 B 发送保密资料，同时要让 B 核验资料由 A 签署。按本章公钥模型，分别使用谁的什么密钥？**

考点：第 3、5 节；层次：领会。

**答案：** 保密发送用 B 的公钥加密，由 B 私钥解密；签署用 A 私钥签名，由 A 公钥验证。两个任务的对象与方向不同，签名本身不隐藏内容，仍需可信地取得相应公钥。

**3. 6 人每对共享一把不同密钥且不区分方向，共多少把？如果陌生人把自己的公钥冒称他人，公钥“可公开”能否消除这个问题？**

考点：第 4 节；层次：领会。

**答案：** 每人可配对另外 5 人，得到 6×5 个有方向计数；每对被数两次，故需 6×5/2=15 把。公钥可公开只说明不必保密，并不说明身份绑定已可信；仍需证书等相应验证机制。KDC 与 CA 处理的分配和信任问题也要区分。

**4. 管理员声称“每段链路加密，所以中间节点绝不会出现明文”。按本书模型指出缺口，并与端到端保护比较。**

考点：第 2、4 节；层次：识记、领会。

**答案：** 链路加密在相邻节点间保护，节点可能先解密再用下一链路密钥加密，中间处的明文需要另行保护。端到端保护贯穿源到终点，但转发必需的控制信息仍有可见性要求；安全层次不能只看线路。

**5. 收到报文及一个未受可信保护的摘要，就能认定发送人身份吗？把摘要或签名叫作“内容加密”又有什么问题？**

考点：第 3、5 节；层次：领会。

**答案：** 不能。摘要有完整性检查用途，但单独传来的值没有建立可信身份关系。签名联系签署密钥和内容，保密加密限制谁能阅读；这些目标不同，不能把一个机制名称代替全部安全目标。

**6. 抓到使用 AH 的分组便认定其内容加密；在网页中看到 TLS 名称便认定已正确验证对方。两处判断缺少什么？**

考点：第 6 节；层次：领会。

**答案：** AH 本身不提供内容加密，应核对实际保护机制与范围；TLS 还要核对协商和身份验证是否按预期完成。协议名称不能替代具体条件，教材中的历史示例也不直接给出现行配置结论。

**7. 资料服务只需特定方向的一种连接，却把防火墙全部关闭以解决故障。给出更可核对的规则设计信息，并说明 NAT 为何不够。**

考点：第 7 节；层次：简单应用。

**答案：** 先明确业务的方向、源、目的、协议和端口，按必要条件设置规则，再结合日志和实际连接核对。NAT 转换地址，不直接证明内容可信，也不替代按业务需求授权的访问控制。

**8. 未知邮件附件提示关闭杀毒后再运行，并声称“快速扫描没问题”。应如何围绕传播、检测边界和记录安排处理？**

考点：第 8、9 节；层次：简单应用、领会。

**答案：** 不要因附件要求就解除防护并执行；核对来源、隔离可疑对象、保留定位信息，并按环境安排扫描与更新。快速扫描覆盖范围有限，未发现不能当成绝对安全证明；处理和恢复还应在授权范围内。

**9. 唯一备份与原件同在一块磁盘，只是目录不同。它能否覆盖磁盘损坏？补丁、备份和行为授权分别解决什么问题？**

考点：第 1、9 节；层次：识记、领会。

**答案：** 不能以此覆盖整块磁盘损坏。补丁修补系统问题，备份服务于数据恢复，授权限制可实施的行为范围；它们相互补充，不能因有其中一项便跳过另外两项。备份还需能辨认内容与时间。
