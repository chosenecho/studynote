## 1 硬件组成与信息流 {#s1}

**必背：** 冯·诺依曼结构采用存储程序工作方式，由运算器、控制器、存储器、输入设备、输出设备五个基本部件组成，内部以二进制表示指令和数据，每条指令由操作码和地址码组成。

运算器管算，控制器管发号令。存储器把指令和数据一起收着，因为存储程序的意思就是让程序本身也变成一趟能存进去的编码。输入设备把外界信息翻成机器认得的 0 和 1，输出设备反过来，把结果交出去。

跟一条加法指令走一遍：PC 指哪儿就从哪儿取指，取来的指令进 IR，译码后去取操作数，进 ALU 算，结果写回寄存器或内存，最后按顺序或分支改 PC。这一路上地址、数据、控制信息都靠总线送。CPU 里就两样东西，数据通路和控制器；数据通路里最重要的是 ALU，ALU 里最要紧的又是加法器。存储器按离 CPU 远近分内存和外存，外设要先过设备控制器才能挂到总线上。

## 2 软件的职责 {#s2}

**必背：** 按用途软件只分系统软件与应用软件两大类；系统软件含操作系统、语言处理系统、数据库管理系统和实用程序；翻译程序分汇编程序、解释程序、编译程序三类。

系统软件干的是垫底的活：操作系统、编译器、链接器都在这一层，管硬件怎么用、程序怎么开发和跑起来。应用软件只对具体任务。分哪一类看它干什么，别看文件后缀；一个库也可能两边都用得上。

汇编语言拿助记符写机器操作，高级语言再往上抬一层。编译和解释只是两种实现策略，同一门语言可以两种都用，别把语言名字跟唯一一种执行方式绑死。三种翻译程序的分工要分清：汇编程序把汇编语言源程序翻成机器语言目标程序；编译程序把高级语言源程序翻成汇编语言或机器语言目标程序；解释程序按执行顺序逐条解释，最后变成机器指令去执行。

## 3 层次与接口 {#s3}

**必背：** ISA 处在硬件与软件交界面上，是软件可见部分；用户分最终用户、系统管理员、应用程序员、系统程序员四类；系统程序员的机器级概念对高级语言程序员是透明的。

一层压一层。数字逻辑给出状态和运算，微体系结构把它拼成寄存器和数据通路，指令集规定外面看得见什么行为，操作系统在上面提供受控服务，语言和应用再往上搭。同一套指令集配不同流水线和 Cache 完全正常。

ISA 只承诺指令算出什么结果、什么时候报异常；用几个周期、走哪条通路、发什么控制信号，都是微体系结构的事。四类用户站的高度不一样，越往下看到的机器细节越多。透明说的就是这中间看得见和看不见的差别。

## 4 开发、链接与执行 {#s4}

**必背：** 源程序经预处理、编译、汇编、链接生成可执行文件；PC 存下一条指令地址，IR 存现行指令，标志寄存器存 ALU 运算的状态信息，MAR 存主存地址，MDR 存交换的数据。

源文件过一遍预处理、编译、汇编，得到目标文件；链接器把跨模块的符号对上，交出可装入的产物；装入程序再搭运行环境。动态库可以装入时解析，也可以拖到运行时。编译通过不等于链接得上，符号没定义照样过不去。

跑起来之后，PC 指着执行位置，IR 暂存取来的指令，通用寄存器存数据或地址，ALU 只管算。结果的性质（有没有进位、是不是零）记在条件标志里，前提是这套 ISA 有全局标志寄存器；经典 MIPS 就没有，它的条件判断大多靠寄存器比较加分支。

一条指令的执行分取指、译码、取操作数、执行、回写五步，五步由时钟信号定时。定长指令字系统在取指时就把 PC 加上指令长度，变长指令字系统要译码后才知道加多少，两者都以“执行结束时 PC 指向下条指令”为准则。

## 5 性能评价 {#s5}

**必背：** CPU 执行时间等于指令条数乘 CPI 再除以主频；吞吐率与响应时间是两个基本指标；时钟周期、指令条数、CPI 三个因素相互制约。

同一任务的 CPU 时间可写成 $T=I×CPI/f$：I 是动态执行指令数，CPI 是平均每条指令的周期数，f 是频率。平均 CPI 依指令混合加权，频率高并不保证时间短。吞吐率、响应时间与 CPU 时间也要分开。

算例：处理器甲以 2 GHz 执行 $2×10^8$ 条指令，平均 CPI=1.5，用时 0.15 s；处理器乙执行相同条数，3 GHz、CPI=2.4，用时 0.16 s。对该任务甲快，性能比为 $0.16/0.15=16/15$。不同指令集或编译结果可能改变 I，不能只比 MIPS。

若原时间中有比例 a 的部分加速 s 倍，新旧时间比为 $(1-a)+a/s$。仅加速占比一半的部分，即便该部分无限快，整体加速比也最多趋近 2；这要求其余工作量与开销保持题设所述。

例 1.1 的套路是固定的：原时间乘原频率得原机器的时钟周期数，乘倍数得新机器的时钟周期数，除以目标时间就是要的新频率。频率涨了 CPI 也会涨，两者一抵，频率翻倍换不来速度翻倍。

## 本章小结

- 信息流里的分工要分清：存储器供指令和数据，控制器译码发信号，ALU 只负责算，寄存器存中间的地址和数。
- ISA 是软件唯一摸得着的那一层。同一套 ISA 换一茬微体系结构，程序照跑。
- 编译过了却链接不上，问题在符号，不在调度算法。CPU 时间是指令数×CPI÷主频，工作量变了必须重算，单看 GHz 或 CPI 容易比错。

## 练习

**1. 追踪一条从内存读数并相加的指令，分别说明控制器、存储器、ALU 与寄存器的职责。**

考点：第 1、4 节；层次：领会。

**答案：** 存储器提供指令与数据，控制器解释指令并安排读写，寄存器保存地址、操作数和中间状态，ALU 做加法。执行中还要按 ISA 规则更新 PC，并处理可能的异常。

**2. 一个程序编译成功，链接时报符号未定义，能否通过更换操作系统调度算法解决？**

考点：第 2、4 节；层次：识记、领会。

**答案：** 不能。应检查定义、目标模块和库的链接关系；调度解决运行任务的处理器分配，不负责补齐链接符号。

**3. 两台机器使用同一指令集，但 Cache 容量和流水级数不同。应在哪些层次描述相同与不同？**

考点：第 3 节；层次：领会。

**答案：** 指令可见行为可按同一 ISA 描述，内部微体系结构不同。软件兼容仍需满足 ABI、操作系统等条件，不能仅凭 ISA 名称推断全部环境兼容。

**4. 甲：2 GHz、CPI=1.5；乙：3 GHz、CPI=2.4。各执行两亿条指令，谁先完成？若乙编译后只需一亿条，结论如何？**

考点：第 5 节；层次：简单应用。

**答案：** 由指令数×CPI÷主频，甲为 2×10⁸×1.5/(2×10⁹)=0.15 s，乙为 2×10⁸×2.4/(3×10⁹)=0.16 s，甲更快；乙只需一亿条时为 1×10⁸×2.4/(3×10⁹)=0.08 s，结论反转。
