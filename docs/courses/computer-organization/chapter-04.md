### 必背清单

**第 1 节**

1. 【考纲 1】指令执行的大致六个步骤：取指令；对指令译码；计算源操作数地址并取操作数；执行数据操作；计算目的操作数地址并存结果；计算下条指令地址并将其送 PC。
2. 【考纲 1】取指与译码两步所有指令的操作都一样，第 3 到第 5 步不同指令的操作可能不同且完全由译码得到的控制信号控制。
3. 【考纲 1】下条指令地址的两种形成方式：顺序执行时把 PC 加上当前指令长度，定长指令字系统在取指令时就同时算出；需要改变执行顺序时根据转移类指令提供的信息生成转移目标地址并送 PC。
4. 【考纲 1】CPU 八个组成部件：程序计数器 PC、指令寄存器 IR、指令译码器 ID、启停控制逻辑、时序信号产生部件、操作控制信号形成部件、总线控制逻辑（含 MDR 与 MAR）、中断机构。
5. 【考纲 1】程序计数器的作用与初值：存放即将执行指令的地址，取指令时总是先把 PC 内容送到地址线；每个程序开始执行前总把第一条指令的地址送到 PC。
6. 【考纲 1】脉冲源产生一定频率的脉冲信号作为整机时钟脉冲，是 CPU 时序的基准信号；启停控制逻辑负责开放或封锁时钟脉冲，实现启动与停机。
7. 【考纲 1】可能打断程序正常执行的内部事件：译码时发现非法操作码；访问的指令或数据不在主存；ALU 运算结果溢出或整数除法除数为 0。
8. 【考纲 1】异常与中断的划分：异常是由 CPU 内部引起的意外事件，分硬故障中断和程序性异常；中断是与执行的指令无关、由 CPU 外部 I/O 硬件发出的事件，需通过外部中断请求线向 CPU 请求。

**第 2 节**

9. 【考纲 2】指令执行用到的两类元件：组合逻辑元件也称操作元件，时序逻辑元件也称状态元件或存储元件；连接方式有总线方式和分散连接方式两种。
10. 【考纲 2】常用组合逻辑元件：多路选择器、加法器、算术逻辑部件、译码器；多路选择器需要 Select 控制信号，加法器不需要控制信号，ALU 需要操作控制信号 OP，译码器无需控制信号。
11. 【考纲 2】最简单的状态单元是 D 触发器，有时钟输入 Clk、状态输入端 D 和状态输出端 Q；n 个 D 触发器可构成一个 n 位寄存器。
12. 【考纲 2】D 触发器的三个时间参数：建立时间是时钟边沿到来前输入端 D 必须稳定有效的时间；保持时间是时钟边沿到来后输入端 D 必须继续保持稳定的时间；Clk-to-Q 时间也称锁存延迟，是从触发边沿到输出 Q 改变的时间。
13. 【考纲 2】早期计算机的三级时序：机器周期、节拍、工作脉冲；机器周期指取指令、读操作数、执行并写结果等基本工作周期，其宽度通常以主存工作周期为基础确定。
14. 【考纲 2】现代计算机的定时：整个数据通路的定时信号就是时钟信号，一个时钟周期就是一个节拍，CPU 的主频就是时钟信号的频率，机器周期的概念已不再使用。
15. 【考纲 3】数据通路的基本结构可抽象为状态元件与操作元件交替组合，只有状态元件能存储信息，所有操作元件都从状态元件接收输入并把输出写入状态元件。
16. 【考纲 2】时钟周期的构成：$Cycle\ Time=$ Clk-to-Q 时间 $+$ 最长操作延迟 $+$ 建立时间 $+$ 时钟偏移。

**第 3 节**

17. 【考纲 3】通用寄存器与内部寄存器的区别：R0 到 R(n−1) 是程序员可见的通用寄存器；Y 和 Z 是对程序员透明的内部寄存器，仅用于存放指令执行期间的中间结果。
18. 【考纲 3】寄存器与内总线之间的两个控制信号：$R_{in}=1$ 时把内总线上的信息存入寄存器 R；$R_{out}=1$ 时把寄存器 R 的信息送到内总线上；描述时只写取值为 1 的有效控制信号。
19. 【考纲 3】单总线数据通路做一次寄存器加法需要三个时钟周期，因为任何时刻只能有一个寄存器把内容送到内总线，且每步结果要送到某个寄存器输入端。
20. 【考纲 3】用单总线从内存读一个字的三步信号序列：先 $R1_{out}$ 与 $MAR_{in}$ 送地址；再 read 与 WMFC 启动读并等待；最后 $MDR_{out}$ 与 $R2_{in}$ 取数。
21. 【考纲 3】异步与同步访存的差别：异步方式下 CPU 发出 read 后要等主存回送 MFC 信号，需用 WMFC 使 CPU 转入等待；主存采用 SDRAM 后与 CPU 同步通信，存储器总在 read 后固定几个时钟周期内备好数据，因而不需要 WMFC。
22. 【考纲 3】单周期数据通路的特点与代价：所有操作在一个时钟周期内完成，故时钟周期须以最复杂指令的指令周期为准，周期特别长、指令执行速度很慢。
23. 【考纲 3】单周期数据通路中 lw 指令的五步：取指令并 PC 加 4；译码并取操作数同时送立即数到扩展器；在 ALU 中计算操作数地址；按地址读数据存储器；选择读出的数据写回目的寄存器。

**第 4 节**

24. 【考纲 4】五段流水线各段的操作：取指段根据 PC 从存储器取出指令并更新 PC；指令译码段产生指令执行所需的控制信号；取操作数段读取存储器操作数或寄存器操作数；执行段对操作数完成指定操作；写回段将操作结果写入存储器或寄存器。
25. 【考纲 4】MIPS 五段流水线常用的另一种命名：取指 Ifetch、译码取数 Reg/Dec、执行 Exec、访存 Mem、写回 Write，两套命名对应不同的阶段划分。
26. 【考纲 4】理想情况下每个时钟都有一条指令进入流水线，从第 6 个时钟周期开始每个时钟周期都有一条指令完成，流水线处理器的 CPI 为 1。
27. 【考纲 4】流水线数据通路的两条设计原则：指令流水段个数以最复杂指令所用的功能段个数为准；流水段的长度以最复杂功能段的操作所用时间为准。
28. 【考纲 4】MIPS 中最复杂的指令是 lw，它有五个功能段；其他指令通过加入空功能段向 lw 靠齐，例如 R 型与 I 型运算类在 Write 前加一个空的 Mem 段，sw 与 beq 在第 4 段后加一个空的 Write 段，j 后面加 Mem 与 Write 两个空段。
29. 【考纲 4】流水线的实际效果：流水线方式不能缩短一条指令的执行时间，因为每段后增加了写流水段寄存器的开销；但能大大提高程序执行的指令吞吐率，且流水线划分得越均匀越好而不是越细越好。
30. 【考纲 4】适合流水线的指令集特征：指令长度应尽量一致；指令格式应尽量规整、源寄存器位置相同；采用 Load/Store 型指令风格；数据和指令在存储器中要按边界对齐存放。

**第 5 节**

31. 【考纲 5】控制器的作用：对指令进行译码，把译码结果与状态标志信号、时序信号组合，产生指令执行所需的控制信号；控制信号送到 CPU 内部或通过系统总线送到主存或 I/O 模块。
32. 【考纲 5】根据不同的控制描述方式，有硬连线控制器和微程序控制器两种实现方式。
33. 【考纲 5】硬连线控制器的设计四步：根据指令功能确定执行步骤并画出流程图；给出每条指令每步各控制信号的取值并列成表；写出每个控制信号的逻辑表达式；按表达式画出控制器逻辑电路。
34. 【考纲 5】硬连线控制器的特点：用组合逻辑电路生成控制信号、用状态寄存器记录状态转换，本质是有限状态机；速度快，适合实现简单规整的指令系统如 MIPS；对复杂指令系统实现困难且维护扩充不易。
35. 【考纲 5】微程序控制器的基本思路：把每条指令的执行过程用一个微程序表示，把每个时钟周期所包含的控制信号取值看成由多个微命令组成的一条微指令，每个控制信号对应一个微命令。
36. 【考纲 5】微程序与微指令的存放：每条指令对应的微程序事先存放在只读存储器中，这个只读存储器称为控制存储器，简称控存；微指令所在存储单元的地址称为微地址。
37. 【考纲 5】微程序定序的两种方法：计数器法使用专门的微程序计数器，下条微指令地址隐含在计数器里，转移时需插入转移微指令；断定法在微指令中增加下地址字段直接给出下条微指令地址，也称下址字段法。
38. 【考纲 5】两种控制器的适用场合：CISC 指令系统大多用微程序控制器实现，因为采用软件设计思想可以处理任意复杂的指令，但每个时钟都要访问控存因而速度较慢；硬连线控制器速度快，适合 RISC 这类规整指令系统。

**第 6 节**

39. 【考纲 6】流水线冒险分三类：结构冒险、数据冒险、控制冒险；统称引起流水线阻塞或停顿的现象为流水线冒险。
40. 【考纲 6】结构冒险的成因与两种解决策略：同一部件同时被不同指令所用即硬件资源竞争；可规定一个部件每条指令只能使用一次且只能在特定阶段使用，或设置多个独立部件，例如把指令存储器与数据存储器分开。
41. 【考纲 6】数据冒险的四种解决策略：由编译器在相关指令之间插入若干空操作指令；采用数据转发把刚产生的结果通过旁路直接送到后续指令的 ALU 输入端；对 load-use 数据冒险用插入空操作或硬件阻塞即插入气泡；对通用寄存器读写操作做特殊处理，保证前半周期写后半周期读。
42. 【考纲 6】load-use 数据冒险不能用转发解决的原因：load 指令要到 Mem 阶段结束才取到数据，而紧随的指令在 Exec 阶段开始就需要该操作数，数据来不及转发。
43. 【考纲 6】控制冒险与分支冒险：由于指令执行顺序改变而引起的阻塞称控制冒险，由分支指令引起的称分支冒险；延迟损失时间片为 C 时可在分支指令后插入 C 个气泡或 C 条空操作指令，还可用分支预测与延迟分支降低损失。

**第 7 节**

44. 【考纲 7】增加指令级并行的两种策略：超流水线通过增加流水线级数使更多指令同时重叠执行，并不改变 CPI 仍为 1；多发射流水线通过同时启动多条指令独立运行来提高并行性，前提是数据通路中有多个执行部件。
45. 【考纲 7】多发射必须完成的两个任务是指令打包和冒险处理，决策依赖于推测，因此需要推测错误检测和回退机制。
46. 【考纲 7】静态多发射与动态多发射的划分：按推测打包主要由编译器静态完成还是由处理器动态执行来分；静态多发射的最初代表是超长指令字 VLIW，动态多发射的代表是超标量处理器。
47. 【考纲 7】IPC 的含义：每个时钟周期内完成的指令条数，是 CPI 的倒数；4 路多发射流水线的理想 IPC 为 4。
48. 【考纲 7】乱序执行：多数超标量处理器结合动态流水线调度，通过指令相关性检测和动态分支预测投机性地不按顺序执行，在流水线阻塞时到后面找没有依赖关系的指令提前执行。

**第 8 节**

49. 【考纲 8】异常与中断的区别：中断是由 I/O 设备触发的、与当前正在执行的指令无关的异步事件；异常是处理器执行一条指令时在其内部检测到的、与正在执行的指令相关的同步事件。
50. 【考纲 8】Intel 将内部异常分为三类：故障、陷阱和终止。
51. 【考纲 8】故障的典型例子与可恢复性：非法操作码、页故障、除数为 0 等；有些可通过异常处理程序恢复，溢出和非法操作码等无法恢复因而终止当前进程。
52. 【考纲 8】陷阱的用途：是预先安排的异常事件，执行到陷阱指令时调出特定程序处理，处理结束后返回陷阱指令的下一条指令；重要用途之一是在用户程序与内核之间提供系统调用接口，还可实现断点与单步跟踪。
53. 【考纲 8】终止的成因：执行指令过程中发生控制器出错、访问存储器校验错等严重错误，程序无法继续执行，只能调用 abort 例程终止进程，严重时要重启系统。
54. 【考纲 8】外部中断分为可屏蔽中断与不可屏蔽中断：可屏蔽中断通过 INTR 请求，CPU 可通过中断控制器设置屏蔽字屏蔽；不可屏蔽中断通过 NMI 请求，通常是电源掉电、硬件线路故障等紧急事件，任何情况下不可屏蔽。
55. 【考纲 8】异常和中断响应的三个步骤：保护断点和程序状态；关中断；识别异常和中断事件并转相应处理程序执行。
56. 【考纲 8】断点与异常类型有关：缺页故障的断点是发生故障的当前指令地址；陷阱的断点是陷阱指令后面一条指令的地址。
57. 【考纲 8】关中断的实现：通过设置中断允许位或中断允许触发器，置 1 为开中断、清 0 为关中断；这样可保证在保存断点与现场的过程中不被新的中断破坏。

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 操作元件与状态元件 | 操作元件是组合逻辑，输出只取决于当前输入且不受时钟控制；状态元件在时钟控制下写入并保持 | 是否有存储功能、是否受时钟边沿控制 |
| 建立时间与保持时间 | 建立时间在时钟边沿之前，保持时间在时钟边沿之后 | 相对时钟边沿的先后 |
| 单周期与多周期数据通路 | 单周期所有操作在一个时钟内完成、周期特别长；多周期把一个指令周期分成多个时钟周期、可复用部件 | 一条指令占几个时钟周期 |
| 硬连线控制器与微程序控制器 | 前者用组合逻辑直接生成控制信号、速度快；后者把控制信号存成微指令放在控存、可处理复杂指令但速度慢 | 控制信号是从逻辑门产生还是从控存取出 |
| 微指令与机器指令 | 微指令是控制信号取值的组合，一条机器指令可由多条微指令实现 | 处在控制器内部还是对程序员可见 |
| 微程序与程序 | 微程序存放在控制存储器中由硬件执行；程序存放在主存中由 CPU 执行 | 存放位置与执行者不同 |
| 流水线与单周期 | 流水线缩短程序总时间、不缩短单条指令时间；单周期每条指令一个周期但周期很长 | 比较的是吞吐率还是单条延迟 |
| 结构冒险与数据冒险 | 结构冒险源于硬件资源竞争；数据冒险源于后续指令要用尚未写回的结果 | 是抢同一个部件还是等同一个数据 |
| 数据冒险与 load-use | 一般数据冒险可用转发解决；load-use 数据冒险必须停顿或插入空操作 | 数据是否在紧随的一条指令就要用到 |
| 控制冒险与数据冒险 | 控制冒险源于执行顺序未定；数据冒险源于值未就绪 | 卡住的是转移目标还是操作数 |
| 超流水线与多发射 | 超流水线增加级数、CPI 仍为 1；多发射同时启动多条指令、CPI 可小于 1 | 是细分阶段还是并行发射 |
| 静态多发射与动态多发射 | 静态由编译器静态推测打包，代表 VLIW；动态由硬件动态调度，代表超标量 | 打包决策由软件还是硬件做 |
| 异常与中断 | 异常是 CPU 内部的同步事件、与指令相关；中断是外部异步事件、与指令无关 | 事件来源与是否与当前指令相关 |
| 故障与陷阱 | 故障在指令执行中被检测到，有些不可恢复；陷阱是预先安排的，处理后返回下条指令 | 断点取当前指令还是下条指令 |
| 可屏蔽与不可屏蔽中断 | 可屏蔽中断可用屏蔽字屏蔽；不可屏蔽中断任何情况下都送到 CPU | 是否有屏蔽字控制 |

### 简答答题模板

**五段指令流水线每一段执行的操作**

取指段根据 PC 的值从存储器取出指令并更新 PC；指令译码段对指令操作码译码，产生指令执行所需的控制信号；取操作数段读取存储器操作数或寄存器操作数；执行段对操作数完成指定的算术或逻辑操作；写回段把操作结果写入存储器或寄存器。MIPS 五段常写作 Ifetch、Reg/Dec、Exec、Mem、Write，前两段是所有指令公共的。

**执行指令时如何形成下一条指令地址**

分两种情形。顺序执行时，把 PC 加上当前指令的长度即得下条指令地址；定长指令字系统在取指令时就把 PC 加指令长度并送 PC，变长指令字系统要先译码再决定加多少。需要改变执行顺序时，由转移类指令（无条件转移、条件转移、调用、返回）提供的信息生成转移目标地址，条件转移还要看条件标志是否满足，满足才把目标地址送 PC。无论哪种情形，一条指令执行结束时 PC 中一定是下条指令的地址。

**硬连线控制器与微程序控制器的区别**

硬连线控制器把每个时钟周期的控制信号取值看成一个状态，用组合逻辑电路生成控制信号、用状态寄存器记录状态转换，本质是有限状态机，速度快、适合简单规整的指令系统，但复杂指令系统难以实现且不易修改。微程序控制器仿照程序设计方法，把每条指令的执行过程用一个微程序表示，微指令事先存放在控制存储器中，每个时钟取出一条微指令执行，能处理任意复杂的指令但每个时钟都要访问控存因而速度较慢。CISC 多用微程序控制器，RISC 多用硬连线控制器。

**内部异常的分类**

Intel 将内部异常分为三类。故障是在引起故障的指令被启动后但未执行结束时检测到的一类与指令执行相关的意外事件，如非法操作码、页故障、除数为 0，有些可恢复有些不能。陷阱是预先安排的异常事件，执行到陷阱指令时调出特定程序处理，结束后返回下一条指令，可用于实现系统调用和程序调试。终止是执行指令过程中发生严重错误、程序无法继续执行时调用 abort 例程的处理，严重时要重启系统。

**异常和中断的响应过程**

三个步骤。一、保护断点和程序状态：把计算出的断点地址送 PC 后保存到栈或特定寄存器，同时把程序状态字保存起来。二、关中断：把中断允许位清 0，避免在保存断点与现场的过程中响应新的中断而破坏已保存信息。三、识别异常和中断事件并转相应处理程序：内部异常只需把异常类型号记录到内部寄存器；外部中断要在每条指令执行完后、取下条指令前采样中断请求引脚，再由中断控制器判优并送出中断类型号。

## 1 指令执行与状态 {#s1}

**必背：** 指令执行分取指、译码、计算源操作数地址并取数、执行、存结果、计算下条指令地址六步；下条指令地址由 PC 加指令长度得到，改变顺序时才由转移指令给出；CPU 的基本部件是数据通路和控制部件。

取指、译码、读取操作数、执行、访存和写回，是描述指令执行的通用功能阶段；阶段是否合并、如何命名取决于处理器模型。通用五段常写作 IF、ID、OF、EX、WB，其中 OF 表示获得操作数；以 MIPS 五段实现为例，常写作 Ifetch、Reg/Dec、Exec、Mem、Write，Mem 是单独的访存流水段，算术指令即使不访问数据存储器也可能在该段空操作。两套名称对应不同的阶段划分，逐段对换会把含义搅乱。不是每条指令都需要全部步骤；分支改变执行位置，存储指令改变内存，算术指令通常产生寄存器结果。指令周期、机器周期和时钟周期的定义层次不同，不能不看模型直接互换。

控制器应在正确时刻使能正确状态单元。组合逻辑产生候选结果，寄存器在规定时钟边界保存结果。

CPU 的八个基本组成部件各有分工：PC 送地址并指向下条指令，IR 寄存现行指令，指令译码器解释操作码，启停控制逻辑与脉冲源提供时钟基准，时序信号产生部件生成周期节拍，操作控制信号形成部件综合各类信号产生控制信号，总线控制逻辑含 MDR 与 MAR，中断机构处理异常与外部请求。取指与译码两步所有指令都一样，后面各步由译码得到的控制信号决定。

## 2 数据通路与定时 {#s2}

**必背：** 数据通路由操作元件与状态元件通过总线或分散方式连接而成；D 触发器要满足建立时间与保持时间；时钟周期等于 Clk-to-Q 加最长操作延迟加建立时间加时钟偏移。

数据通路包含寄存器堆、ALU、选择器、扩展器和存储接口。单周期方案要求最长指令路径在一个周期完成，时钟由关键路径约束；多周期方案可让不同步骤复用部件，但要保存中间值并安排状态。

并行分支的延迟通常取较长者，即 max(路径甲, 路径乙)，随后串行段才相加。不能把互不依赖、同时进行的寄存器读取与立即数扩展一律累加。还应计入时钟到输出、建立时间和必要余量。

组合逻辑元件的输出只取决于当前输入，输入信号到达后经逻辑门延迟输出被改变并保持到输入再变；状态元件则在时钟边沿把输入写入并保持。两者交替组成“…状态元件—操作元件—状态元件…”的结构，只有状态元件存信息。早期计算机采用机器周期、节拍、工作脉冲三级时序，现代计算机只用统一的时钟信号。

## 3 逐条追踪数据通路 {#s3}

**必背：** 单总线数据通路每个时钟只允许一个寄存器送出内容，故一次寄存器加法要三个节拍；从内存读一个字要送地址、发读命令并等待、取数三步；描述时只写取值为 1 的信号。

Load/Store 模型中，加载由基址与扩展位移形成地址，读数据存储器后选择内存结果写寄存器；存储把寄存器值写到目标地址；寄存器运算由 ALU 产生写回值。写寄存器使能、内存写使能与结果选择不能混用。

分支路径先准备比较与目标，再决定 PC 的候选来源。默认顺序 PC、条件分支与无条件跳转需要选择规则。给控制表填值时，先写指令造成的状态变化，再决定哪些控制位相关；无关位不是随意开启写入的理由。

![原创示意：Load/Store 的数据来源与写入目标](figures/load-store-path.svg)

教材例 4.1 的写法值得照抄：取指阶段固定为四拍，分别是 $MAR\leftarrow(PC)$、$MDR\leftarrow M(MAR)$ 同时 PC 加 1、$IR\leftarrow(MDR)$、指令译码；执行阶段从第五拍开始按指令语义拆，先把源地址送 MAR，再读存储器，再把读出的内容送 ALU 的一个输入，然后做运算、把结果写 MDR、最后写回存储器。相邻两拍若能共用不同物理通道就可以合并，合并后节拍数减少。单周期数据通路的 lw 指令则在同一个周期内顺序完成取指、译码、算地址、读数据、写回五件事。

## 4 流水线与时间 {#s4}

**必背：** 五段为取指、译码、取操作数、执行、写回；理想 CPI 为 1；流水段个数以最复杂指令为准、段长以最复杂功能段用时为准；流水线提高吞吐率但不缩短单条指令时间。

流水线把多条指令的不同阶段重叠，主要提高连续任务吞吐，单条延迟不必缩短。理想 k 级流水线执行 n 条指令需要 k+n-1 个周期，还要满足无停顿、阶段单周期且资源足够等条件。

定时模型：4 阶段组合延迟为 120、180、150、100 ps，每级额外寄存开销 20 ps，则周期取 200 ps。6 条无冒险指令需要 9 周期，即 1800 ps；若对比不分级、每条 550 ps 的串行模型，时间为 3300 ps，加速比 $11/6$。对比双方的寄存及控制开销必须按题设一致处理。

![原创示意：四阶段六指令的填充与排空](figures/pipeline-timeline.svg)

流水线会增加每条指令的延时，因为每段后多了一个写流水段寄存器的开销，段分得越细开销越大；但程序的总执行时间因吞吐率提高而大幅缩短。划分得均匀比划分得细更重要，否则某些段只能空等。MIPS 中最复杂的是 lw，占五段，其余指令用空段补齐。适合流水线的指令集要求长度一致、格式规整、采用 Load/Store 风格并且数据与指令按边界对齐。

## 5 控制器 {#s5}

**必背：** 控制器有两种实现方式：硬连线控制器用组合逻辑生成控制信号、速度快；微程序控制器把微指令存放在控制存储器中、可处理复杂指令但速度慢。

硬布线控制用状态、指令字段和条件信号产生控制输出；微程序控制把控制序列组织为微指令，并由微地址机制选择下一条。微指令不等于用户机器指令，微操作则描述寄存器传送等更细动作。

水平微指令可用较多字段直接控制并行微操作，垂直编码更紧凑但需译码。两者在控制存储容量、译码开销和可修改性上有所取舍。

硬连线控制器的设计按四步走：定步骤画流程、列表填控制信号取值、写每个控制信号的逻辑表达式、画逻辑电路。它本质是有限状态机。微程序控制器则把每条指令写成一个微程序，微指令存放在控存里，微地址由计数器法或断定法产生；计数器法要在连续执行之间插入转移微指令，断定法直接在微指令中给下址字段，因而更灵活。CISC 指令复杂，通常用微程序控制器；RISC 指令规整，通常用硬连线控制器。

## 6 冒险与处理 {#s6}

**必背：** 冒险三类：结构、数据、控制；转发能送已产生的结果但救不了 load-use；分支冒险的损失可用插入气泡或空操作指令填补。

结构冒险源于资源冲突，数据冒险源于值的依赖与可用时间，控制冒险源于下一执行位置尚未确定。转发可把已生成的结果送给后继阶段，但不能提前产生尚未读出的数据；经典五级模型中的紧邻 load-use 可能仍需停顿。

追踪：加载产生 r2，下一条用 r2 加到 r5。若加载到 MEM 结束才可提供数据、后继在 EX 开始就需要它，即便存在常规转发，也需让后继推迟一个周期。条件改变时停顿数也会改变，不要把固定气泡数当成 ISA 规定。

![原创示意：MEM 结果转发与 load-use 停顿](figures/load-use.svg)

结构冒险的两个解法是限制部件使用次数与阶段，或把指令存储器与数据存储器分开，现代处理器把一级 cache 分成数据 cache 与代码 cache 正是后者。数据冒险的第四个办法是对通用寄存器做写在前半周期、读在后半周期的安排，使写入与读出在同一时钟内错开。

## 7 高级流水线 {#s7}

**必背：** 超流水线靠增加级数、CPI 仍为 1；多发射靠同时启动多条指令、CPI 可小于 1；静态多发射代表 VLIW，动态多发射代表超标量。

超标量允许每周期发射多条合适指令，超流水把工作划成更多较短阶段，乱序执行按依赖与资源选择可执行操作。重命名可消除部分名字相关，不能消除真正的数据依赖。

预测与推测提高利用机会，但错误时要丢弃不应生效的结果。指令级并行受依赖链、分支、访存及提交规则约束，发射宽度扩大不保证程序按比例加速。

多发射必须先做指令打包和冒险处理，两者都依赖推测，所以要有推测错误检测和回退机制。静态多发射把同时发射的多条指令看成一个发射包，最初称超长指令字；动态多发射由硬件做动态流水线调度，即超标量，配合相关性检测与动态分支预测就形成乱序执行。衡量指标是 IPC，即每周期完成的指令条数。

## 8 异常、中断与精确状态 {#s8}

**必背：** 异常是 CPU 内部与指令相关的同步事件，中断是外部与指令无关的异步事件；异常分故障、陷阱、终止三类；响应三步骤是保护断点和程序状态、关中断、识别并转处理程序。

异常与当前指令执行条件相关，外部中断通常由外部事件触发；分类名称随体系结构有所不同。处理器要保存足够的返回信息，转到处理入口，必要时控制屏蔽与优先级，再按规则返回或终止。

精确异常要求架构状态能解释为较早指令已完成、触发点及之后指令尚未错误提交的边界。流水线可在内部乱序处理，但不能让错误路径上的存储随意成为不可撤销结果。

外部中断按能否屏蔽分可屏蔽与不可屏蔽两类，后者是电源掉电、线路故障等紧急事件。断点取哪一条指令由异常类型决定：缺页故障取当前指令地址，陷阱取下一条指令地址。关中断靠中断允许位，只有在保存断点与现场期间关中断，才能保证返回时状态完整。

## 本章小结

- 先列出指令读取什么、计算什么、写回哪里，再设控制信号；load 写寄存器，store 写存储器，PC 按规则更新。
- 并行组合路径汇合时取最长延迟；理想 k 级流水执行 n 条指令需 k+n−1 周期，周期还含最慢级和寄存开销。条件不含停顿时才可直接套算。
- 流水重叠改善吞吐，不保证单条延迟缩短。转发、停顿与重命名处理不同相关；真依赖仍须等数据产生，异常恢复还须维护顺序可见状态。

## 练习

**1. 加载、存储与寄存器加法分别改变哪些状态？设计控制信号时为什么要先确认写入目标？**

考点：第 1、3 节；层次：领会。

**答案：** 加载主要写目标寄存器，存储写内存，加法写寄存器结果，三者还按规则推进 PC。错误的使能会改变本不该变化的状态，不能只看 ALU 算得是否正确。

**2. 两条并行准备路径为 45 ps 和 70 ps，汇合后再经过 80 ps，忽略其他开销。组合关键路径是多少？**

考点：第 2 节；层次：领会。

**答案：** max(45,70)+80=150 ps。不能把同时进行的两条准备路径相加为 195 ps；若还有时钟相关开销需另计。

**3. 四阶段延迟为 120、180、150、100 ps，各级寄存开销 20 ps。六条无停顿指令需要多长时间？为何不是六个周期？**

考点：第 4 节；层次：简单应用。

**答案：** 周期为 max(120,180,150,100)+20=200 ps，填充和排空计入后需要 4+6-1=9 周期，即 1800 ps。每周期完成一条只适用于充满后的理想稳态。

**4. 微程序中一条微指令同时使能多个寄存器传送，是否表示用户程序也同时执行多条机器指令？**

考点：第 5 节；层次：识记、领会。

**答案：** 不必然。微指令与机器指令是不同层次，一条机器指令可以由多条微指令实现，每条微指令可安排多个互不冲突的微操作。

**5. 增加发射宽度和寄存器重命名，能否让紧邻加载的真依赖使用者永不等待？**

考点：第 6、7 节；层次：识记、领会。

**答案：** 不能。真依赖要求等到数据可用，重命名只消除部分名字相关；若加载结果尚未产生，宽发射与转发都不能凭空给出正确值。

**6. 推测执行的较晚存储在较早指令发生异常前已对外永久可见，为什么会破坏精确异常？**

考点：第 8 节；层次：领会。

**答案：** 状态无法还原为异常边界之前的顺序执行结果。应推迟不可撤销提交或采用相应恢复机制，保证错误路径与尚未提交操作不污染架构状态。
