## 1 设备与控制器 {#s1}

**必背：** I/O 系统由设备、控制器、通道和总线构成；设备按速率、信息交换单位、共享属性三种维度分类，速率与共享属性的代表设备是单选常考点；设备控制器有六项功能、三部分结构。

I/O 系统由设备、控制器、互连和软件拼起来。设备干实际的输入输出，控制器负责把控制、状态、数据这些能力摆到处理器面前。按块或字符、共享或独占去分类，挑接口和定调度时用得上；可分类毕竟只是分类，说明不了硬件内部怎么搭。

应用递上去的是一个逻辑请求，驱动把它翻成控制器认得的命令，完成的事件再一层层往上报。设备忙、控制器缓冲还没备好、进程在等这次传输结束，这是三个层次上的状态，别混。

## 2 查询、中断与 DMA {#s2}

**必背：** 轮询让 CPU 循环检测状态、浪费大；中断由设备发请求唤醒进程；DMA 由控制器搬数据，靠 CR、MAR、DR、DC 四个寄存器，DC 减为 0 时发中断。

程序查询是 CPU 自己转圈查状态、自己搬数据。中断控制让 CPU 先去干别的，设备有动静了再转过来处理。DMA 初始化之后，主存和设备之间的搬运交给控制器，CPU 只管开头配置和收尾。

| 比较项 | 程序查询 | 中断控制 | DMA |
| --- | --- | --- | --- |
| 就绪通知 | CPU 反复读状态 | 事件引发中断 | 控制器按传送协议工作 |
| 常规模型中的数据搬运者 | CPU | CPU | DMA 控制器或设备 DMA 引擎 |
| CPU 的准备工作 | 设置命令和缓冲 | 设置命令、缓冲和中断 | 设置地址、长度、方向与描述符 |
| 等待期间 CPU | 查询占用执行机会 | 可执行其他任务 | 可执行其他任务 |
| 完成处理 | 查询发现完成 | 中断服务处理 | 常以完成中断通知 |
| 共享资源影响 | 指令与访存开销 | 服务程序和切换开销 | 总线或内存竞争及一致性维护 |

DMA 周期挪用说的是老式共享总线上插进传送周期，把 CPU 的部分访存往后推一推，可不是整个 I/O 期间 CPU 都停着。现代系统还得管 IOMMU、设备地址、Cache 一致性，要不要软件同步得看平台。

## 3 缓冲与重叠 {#s3}

**必背：** 缓冲的两点原因是缓和速度差异、协调数据大小不一致；循环缓冲用 R、G、C 三种缓冲区和 Nexti、Nextg、Current 三个指针，缓冲池有 3 种缓冲区、3 个队列、4 种工作缓冲区。

缓冲挡在设备和处理器中间，吸收两边的速度差，也顺手把传输粒度对齐。单缓冲里，设备填和 CPU 取用的是同一块，谁占着必须说清。双缓冲能让一块给设备填、另一块给 CPU 处理，可得防着把还没消费的数据盖掉。

看时序：4 块数据，设备每块输入 3 ms，CPU 每块处理 5 ms，复制不计开销。完全串行要 32 ms。双缓冲够用、输入和处理能重叠时，第一块输入 3 ms，接着 4 次处理共 20 ms，23 ms 收工。

## 4 分配与等待 {#s4}

**必背：** 设备分配用 DCT、COCT、CHCT、SDT 四张表，考虑固有属性、分配算法、安全性三个因素；安全分配摒弃请求和保持条件，不安全分配可能死锁。

设备分配会牵到设备表、控制器表、通道表、系统设备表，记的是谁占着、什么状态、谁在等谁。独占设备要协调申请和释放，共享设备靠请求队列排队。安全分配还得往下想一层：这个任务手上已经拿着别的资源，再开口要设备，会不会绕成一个等待圈。

等待有两种：一种是还没分到能用的设备，一种是设备接了请求、等这次 I/O 做完。进程会不会阻塞，看接口是同步还是异步，光瞅设备忙不忙推不出来。

## 5 设备独立性 {#s5}

**必背：** 设备独立性指应用程序独立于具体使用的物理设备，好处三条：换设备不改程序、易处理故障、提高可靠性与分配灵活性；靠逻辑设备表完成逻辑名到物理名的转换。

逻辑名和物理设备一分开，应用就不必把某个控制器写死在代码里。系统拿逻辑请求去找合适的驱动，命名、保护、错误报告也统一起来。不过换物理设备还是要看能力、性能和驱动配不配，独立性不等于什么设备都能随便替换。

逻辑设备表记的就是逻辑名对到哪个物理设备，以及它们之间的访问关系。

## 6 SPOOLing {#s6}

**必背：** SPOOLing 是在联机情况下实现的同时外围操作，由输入井输出井、输入输出缓冲区、输入输出进程、请求 I/O 队列组成，三个特点是提高速度、把独占设备变共享、实现虚拟设备。

SPOOLing 先把输入输出任务堆到磁盘队列里，再由服务程序按顺序去碰那些原本只能独占的设备。几个应用各自提交打印作业就行，谁也不用一直占着打印机；打印服务从队列里取，一份一份送过去。

队列本身还得管容量、权限、失败重试和取消。它把“提交”和“真正服务”解开了，可提交成功不等于纸已经出来了。

## 7 软件层次 {#s7}

**必背：** 设备管理软件分用户层软件、与设备无关的软件层、设备驱动程序、中断处理程序四层；驱动程序转换请求并回传信号，中断处理程序唤醒被阻塞的进程。

应用库给出调用入口，与设备无关的软件管通用规则，驱动去解释具体命令，中断处理应答完成或异常，最后控制器和设备把传输做掉。一次读请求走下来：先验参数，经缓冲和驱动递下去，等事件回来填结果，再把任务叫醒。

错误一路往上，应该越变越好懂。中断处理一般只做最急的那部分，长活留给合适的上下文去做。

## 8 磁盘访问时间 {#s8}

**必背：** 磁盘访问时间分寻道时间、旋转延迟时间、传输时间三部分；前两项与读写数据量基本无关且占大头，6000 转每分的平均旋转延迟为 5 ms。

机械盘靠磁道、扇区组织数据，一次访问的时间里有排队、控制器开销、寻道、旋转等待、传输。低级格式化定的是物理扇区结构，分区、建文件系统是另两层的事。固态盘没有机械寻道，磁头那套模型不能照搬。

套个模型：转速 6000 rpm，每转 10 ms，随机到达时平均旋转等待算半转，5 ms；寻道给 4 ms、传输 0.2 ms，其他开销不计，合起来 9.2 ms。这个半转是有前提的，旋转相位得大致均匀。

## 9 磁盘调度 {#s9}

**必背：** 磁盘调度目标是平均寻道时间最少；FCFS 公平但不优化寻道，SSTF 每次最近却会饥饿，SCAN 按方向扫又称电梯算法，CSCAN 单向，NStepSCAN 与 FSCAN 分队列防磁臂粘着。

FCFS 按请求先后走。SSTF 每次挑离当前磁道最近的。SCAN 顺着一个方向扫到物理端点再折返，LOOK 扫到该方向最后一个请求就折返；C-SCAN 和 C-LOOK 只单向服务，到另一头再回来。同一队列、同一起始方向，端点不同，结果就不同：SCAN 哪怕端点没请求，也要把空扫的距离算进去，LOOK 不算。回程算不算进总移动量、扫描期间新到的请求是并进本轮还是留到下一轮，都会改结果。教材里的 FSCAN、NStepSCAN 就是用分队列把新请求留给后面的扫描。

算一遍：磁头在 40，请求队列 10、55、20、70 不动。FCFS 逐步累加 $30+45+35+50=160$；SSTF 依次走 55、70、20、10，总移动 $15+15+50+10=90$。本例里向高地址的 LOOK 也是 90；SCAN 要是规定到 99 才折返，就是 $59+89=148$。

## 10 加速与约束 {#s10}

**必背：** 提高磁盘速度的五种方法是提前读、延迟写、优化物理块分布、虚拟盘、磁盘高速缓存；虚拟盘内容由用户控制，高速缓存由操作系统控制。

缓存和预读吃的是局部性，布局摆得合理能少走几趟寻道，相邻请求合并起来能降调度开销，延迟写则可以攒一批一起提交。这些手段都受容量和一致性约束。写操作返回了，得说清是进了缓存，还是已经落到盘上。

RAID 用条带、镜像或校验把多块盘组织起来，图的是并行或者冗余，可它替代不了备份。误删、误写、勒索，一样会顺着冗余复制过去。

## 本章小结

- 查询、中断、DMA，数据谁搬、完成谁通知，得分开看。被阻塞的是等待的进程，CPU 照样可以跑别的就绪任务。
- 缓冲让设备和处理能重叠，可缓冲有限，别当成无限队列使。SPOOLing 管暂存和排队，设备命令归驱动。
- 算机械盘的访问时间，寻道、旋转、传输三笔成本都得先声明。SSTF、SCAN、LOOK 挑法不同，端点规则也不同。易失写缓存、RAID、独立备份，三样各管一段，谁也替不了谁。

## 练习

**1. 某采集程序采用 DMA，却仍收到完成中断。两者矛盾吗？CPU 等待设备分配与等待 I/O 完成又有何区别？**

考点：第 1、2、4 节；层次：领会。

**答案：** 不矛盾，DMA 负责数据搬运，完成中断可负责通知 CPU。分配等待发生在尚未取得使用条件时，完成等待发生在请求已提交后；同步接口可能阻塞，异步接口可先返回。

**2. 四块数据各输入 3 ms、处理 5 ms，双缓冲足够且无复制代价。画出处理起点并求最终时间。**

考点：第 3 节；层次：领会。

**答案：** 第一次输入在 3 ms 完成，CPU 在 3、8、13、18 ms 开始各块处理，23 ms 完成。设备在 0–3、3–6、8–11、13–16 ms 填充可用缓冲；两块缓冲不能被假设成无限队列。

**3. 以逻辑名提交打印后，应用立即退出，打印服务稍后输出。解释设备独立性、SPOOLing 和驱动的不同职责。**

考点：第 5、6、7 节；层次：识记、领会。

**答案：** 逻辑名由系统映射到实际设备；SPOOLing 保存并调度作业；驱动把请求变成控制器命令。作业提交与物理打印完成是两个事件，失败与取消仍须处理。

**4. 6000 rpm 的机械盘，平均寻道 4 ms、传输 0.2 ms，按随机相位模型求一次平均访问时间。能否原样用于 SSD？**

考点：第 8 节；层次：识记、简单应用。

**答案：** 每转 60÷6000=0.01 s=10 ms，随机相位下平均旋转等待为 10÷2=5 ms，合计 4+5+0.2=9.2 ms，未计排队等开销。SSD 没有这两项机械运动，需要另外建立延迟模型。

**5. 从磁道 40 开始处理队列 10、55、20、70，求 FCFS 与 SSTF 移动量，并说明 SCAN 为什么还需要磁盘边界条件。**

考点：第 9 节；层次：领会。

**答案：** FCFS 路线 40→10→55→20→70，移动量 30+45+35+50=160；SSTF 路线 40→55→70→20→10，移动量 15+15+50+10=90。SCAN 可能继续走到边界而不是最后一个请求，因此缺少端点不能确定完整移动量；LOOK 才按最外侧待服务请求折返。

**6. 系统把写请求放入易失缓存后返回成功，再用 RAID 镜像保存。为什么仍需要持久化规则与备份？**

考点：第 10 节；层次：识记、领会。

**答案：** 易失缓存可能随断电丢失，镜像不能恢复已经同步复制的误删除。必须说明刷新与持久化语义，并另有可恢复的历史副本。
