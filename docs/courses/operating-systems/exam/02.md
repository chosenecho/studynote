## 必背清单

**第 1 节**

1. 【考纲 1.1】程序顺序执行的三个特点：顺序性（处理机操作严格按程序规定的顺序执行）、封闭性（程序运行时独占全机资源，结果不受外界影响）、可再现性（环境和初始条件相同，多次执行结果相同）。
2. 【考纲 1.2】程序并发执行指在同一时间间隔内运行多个程序；宏观上多个程序同时向前推进，微观上任意时刻一个 CPU 上只有一个程序在执行。
3. 【考纲 1.2】程序并发执行的三个特点：间断性、失去封闭性、不可再现性。
4. 【考纲 1.2】不可再现性的典型例子：counter 初值为 0，p1、p2 各执行一次加 1，交错执行后 counter 等于 1 而不是 2。

**第 2 节**

5. 【考纲 2.1】进程定义一：进程是允许并发执行的程序在某个数据集合上的运行过程；定义二：进程是由正文段、用户数据段及进程控制块共同组成的执行环境。
6. 【考纲 2.1】进程的五个特征：并发性、动态性、独立性、异步性、结构特征。
7. 【考纲 2.1】进程与程序的区别三条：程序静态、进程动态；程序永久、进程暂时；存在实体不同，程序是指令的集合，进程是正文段、用户数据段和进程控制块的实体。
8. 【考纲 2.1】进程与程序的联系两条：进程是程序的一次执行；一个程序可以对应多个进程。
9. 【考纲 2.2】进程控制块是进程实体的一部分，是操作系统中最重要的数据结构，其中包含用于描述进程情况及控制进程运行所需的全部信息。
10. 【考纲 2.2】每个进程有唯一的进程控制块，进程控制块是系统感知进程存在的唯一标志。
11. 【考纲 2.2】进程控制块中的四类信息：进程标识符信息、处理机状态信息、进程调度信息、进程控制信息。
12. 【考纲 2.2】处理机状态信息四项：通用寄存器、指令计数器、程序状态字 PSW、用户栈指针。

**第 3 节**

13. 【考纲 2.3】三种基本状态：就绪态、执行态、阻塞态；单 CPU 系统中任意时刻只能有一个进程处于执行态，N 个 CPU 最多 N 个。
14. 【考纲 2.3】状态转换四条：就绪转执行由分配到 CPU 引起；执行转就绪由时间片递减为 0 引起；执行转阻塞由申请资源或等待事件引起；阻塞转就绪由事件发生或申请到资源引起。
15. 【考纲 2.3】阻塞态不能直接变为执行态；阻塞转就绪称唤醒过程，执行转阻塞称阻塞过程。
16. 【考纲 2.4】进程组织的链接方式把相同状态的 PCB 用链接字链接成队列；索引方式按状态建立索引表，表项指向 PCB 的物理块。
17. 【考纲 2.4】就绪态进程构成就绪队列，阻塞态进程构成阻塞队列，还可按优先权和阻塞原因分成多个队列。

**第 4 节**

18. 【考纲 3.1】需要创建新进程的四种情况：用户登录、作业调度、提供服务、应用请求。
19. 【考纲 3.2】进程创建四步：申请空白 PCB、为新进程分配资源、初始化进程控制块、将新进程插入就绪队列。
20. 【考纲 3.3】进程阻塞的四种情况：请求系统服务、启动某种操作、新数据尚未到达、无新工作可做。
21. 【考纲 3.4】进程阻塞三步：把进程的状态改为阻塞态、插入相应的阻塞队列、转进程调度程序。
22. 【考纲 3.4】进程唤醒三步：从阻塞队列中移出、状态由阻塞态改为就绪态、插入就绪队列。
23. 【考纲 3.2】进程终止五步：从 PCB 读出进程状态、终止进程的执行、终止子孙进程、释放资源、将终止进程的 PCB 移出。
24. 【考纲 3.2】级联终止指父进程终止时其所有子进程也被终止；UNIX 系统中父进程终止后，子进程以 init 进程为新的父进程。

**第 5 节**

25. 【考纲 4.1】操作系统内核是计算机硬件的第一次扩充，执行与硬件关系密切、执行频率高的模块，常驻内存。
26. 【考纲 4.1】内核的支撑功能三项：中断处理、时钟管理、原语操作；资源管理功能三项：进程管理、存储器管理、设备管理。
27. 【考纲 4.2】中断是改变处理器执行指令顺序的一种事件，与 CPU 芯片内外部硬件电路产生的电信号相对应。
28. 【考纲 4.2】中断分同步中断（内部中断或异常）与异步中断（外部中断）；异步中断再分外部可屏蔽中断与外部不可屏蔽中断。
29. 【考纲 4.2】引起中断的五种原因：人为设置中断、程序性事故、硬件故障、I/O 设备、外部事件。
30. 【考纲 4.3】单重中断处理四步：关闭中断并保护断点、转中断处理程序保护现场、按中断向量找到入口执行中断处理子例程、恢复现场并开中断返回断点。

**第 6 节**

31. 【考纲 4.4】用户态执行是 CPU 执行用户空间的代码；系统态执行是 CPU 执行系统核心代码。
32. 【考纲 4.4】系统调用与一般函数调用的三点区别：运行态不同、执行过程不同、多一层中断处理开销。
33. 【考纲 4.5】系统调用执行过程：系统调用号送入寄存器、执行 int 0x80 指令进入内核态、转 system_call、按分派表找到实现程序、结果返回用户态。
34. 【考纲 4.5】系统调用分派表 sys_call_table 的第 n 个表项存放系统调用号为 n 的实现程序地址。
35. 【考纲 4.4】系统调用的五种类型：进程控制类、文件操纵类、设备管理类、通信类、信息维护类。

**第 7 节**

36. 【考纲 4.6】两个时钟源：RTC 实时时钟也称 CMOS 时钟，靠电池供电，提供最原始的计时标准；OS 时钟由主板的定时/计数芯片产生，开机时有效，由操作系统控制。
37. 【考纲 4.6】可编程间隔定时器 PIT 按指定时间间隔产生时钟中断，由晶振、计数器、保持寄存器三部分构成。
38. 【考纲 4.7】时钟驱动程序四项功能：维护日期和时间、递减当前进程时间片的剩余执行时间并检查是否为零、对 CPU 的使用情况记账、递减报警计数器。
39. 【考纲 4.6】Linux 2.4 把一个时钟滴答定义为 10 ms，即每秒产生 100 次时钟中断；时间基准是 1970 年 1 月 1 日凌晨 0 点。

**第 8 节**

40. 【考纲 5.1】线程是进程中的一个实体，是被系统独立调度和分派的基本单位，只拥有运行中必需的资源，包括程序计数器、一组寄存器和栈。
41. 【考纲 5.1】引入线程的原因：进程既是独立执行的基本单位又是资源的拥有者，创建、撤销和切换的开销大，使进程数和进程切换的频率受到限制。
42. 【考纲 5.1】线程分用户级线程与内核级线程：前者创建、撤销、切换都与内核无关，后者由内核创建并为线程建立线程控制块。
43. 【考纲 5.1】两类线程的三点比较：调度与切换速度、系统调用阻塞的范围、CPU 时间分配的单位。
44. 【考纲 5.1】线程与进程关系的五个角度：资源和调度、地址空间资源、通信关系、并发性、系统开销。
45. 【考纲 5.2】用户线程被阻塞时整个进程都必须等待；内核线程被阻塞时内核可以调度同一进程中的另一个内核线程运行。
46. 【考纲 5.2】线程控制块包含线程标识符信息、处理机状态信息、线程调度信息和记账信息。

**第 9 节**

47. 【考纲 6.1】进程同步的两个任务：对具有资源共享关系的进程保证以互斥方式访问临界资源；对具有相互合作关系的进程保证协调执行。
48. 【考纲 6.1】临界资源是必须以互斥方式访问的共享资源；临界区是进程中访问临界资源的那段代码。
49. 【考纲 6.1】互斥访问的模式是进入区、临界区、退出区；进入区检查能否进入并对临界区加锁，退出区释放临界区的访问权。
50. 【考纲 6.1】同步机制的四条准则：空闲让进、忙则等待、有限等待、让权等待。

**第 10 节**

51. 【考纲 6.2】整型信号量是表示共享资源状态且只能由特殊的原子操作改变的整型量；值大于 0 说明有可用资源，值小于等于 0 说明资源忙，进程必须等待。
52. 【考纲 6.2】整型信号量的值只能由 wait 和 signal 两个原子操作改变，原子操作可以通过关中断来实现。
53. 【考纲 6.2】整型信号量存在忙等，在关中断条件下等待还会死循环，只适合单 CPU 系统的简单互斥。
54. 【考纲 6.3】记录型信号量由资源数量 value 和阻塞队列 L 组成；wait 使 value 减 1，value 小于 0 时调用 block 自我阻塞，signal 使 value 加 1，value 小于等于 0 时调用 wakeup 唤醒一个进程。
55. 【考纲 6.3】value 大于等于 0 时表示资源数量，小于 0 时其绝对值等于阻塞队列中阻塞进程的数量。
56. 【考纲 6.3】记录型信号量不存在忙等，采取让权等待策略；value 初值为 1 时转化为互斥信号量。

**第 11 节**

57. 【考纲 6.4】生产者—消费者问题中缓冲池有 n 个缓冲区，任意两个进程必须以互斥方式访问；缓冲池空时消费者阻塞，装满时生产者阻塞。
58. 【考纲 6.4】三个信号量：互斥信号量 mutex 初值为 1，empty 表示空缓冲区数初值为 n，full 表示装有消息的缓冲区数初值为 0。
59. 【考纲 6.4】wait 操作的顺序不能颠倒，必须先对资源信号量 empty 或 full 做 wait，再对互斥信号量 mutex 做 wait；wait 与 signal 必须成对出现。
60. 【考纲 6.4】读者—写者问题允许多个进程同时读 D 区，仅允许一个进程写 D 区，有进程写时不能有任何其他进程读或写。
61. 【考纲 6.4】读者—写者设三个量：readcount 为读进程计数，rmutex 保护 readcount，wmutex 实现读写与写写的互斥；第一个读者执行 wait(wmutex)，最后一个读者执行 signal(wmutex)。

**第 12 节**

62. 【考纲 6.5】管程是描述共享资源的数据结构和在数据结构上的共享资源管理程序的集合，含变量定义、初始化代码和管理共享资源的过程。
63. 【考纲 6.5】管程的三点说明：是可供程序员调用的软件包；任意时刻管程中只能有一个活跃进程；是编程语言的构件，由编译器特殊处理。
64. 【考纲 6.5】条件变量只能在管程中访问；在其上执行 wait 把调用进程阻塞并插入该条件的阻塞队列，signal 唤醒阻塞进程，队列为空时 signal 不产生任何结果。
65. 【考纲 6.5】用管程解决生产者—消费者问题：count 记缓冲池中的消息数，count 等于 N 时 wait(full)，count 等于 0 时 wait(empty)，操作完成后再 signal 对方条件的队列。

**第 13 节**

66. 【考纲 6.6】进程之间的三种高级通信机制：共享存储器系统、消息传递系统和管道通信系统。
67. 【考纲 6.6】共享存储器系统分基于共享数据结构的通信方式与基于共享存储区的通信方式两类。
68. 【考纲 6.6】消息传递系统分直接通信与间接通信；间接通信借助信箱等暂存消息的共享数据结构，既能实现实时通信，又能实现非实时通信。
69. 【考纲 6.6】管道是连接读写进程的一个特殊文件，存在于外存，其中的消息没有固定长度，发送进程以字符流形式写入，接收进程从管道读出。
70. 【考纲 6.6】消息缓冲队列由数据结构、发送原语和接收原语构成；消息缓冲区包括发送进程标志符、消息长度、消息正文和指向下一个消息缓冲区的指针。

## 易混对照

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 进程与程序 | 程序静态、永久、是指令的集合；进程动态、暂时、是正文段加用户数据段加进程控制块的实体 | 有没有进程控制块，会不会随执行变化 |
| 顺序执行与并发执行 | 顺序执行有封闭性和可再现性；并发执行失去封闭性、不可再现性，多一条间断性 | 同一输入多次执行结果是否唯一 |
| 就绪态与阻塞态 | 就绪只差 CPU；阻塞还差等待的事件或资源 | 得到 CPU 后能不能立刻运行 |
| 阻塞与唤醒 | 阻塞是执行态转阻塞态；唤醒是阻塞态转就绪态 | 进程在等事件还是在事件已到 |
| 用户态与系统态 | 用户态执行用户空间的代码；系统态执行系统核心代码 | 代码位于哪个地址空间 |
| 系统调用与一般函数调用 | 运行态不同、执行过程不同、多一层中断处理开销 | 是否切换执行态 |
| 同步中断与异步中断 | 同步中断由 CPU 控制单元在指令执行时产生；异步中断由其他硬件设备随机产生 | 与当前执行的指令有没有关系 |
| 外部可屏蔽与不可屏蔽中断 | 可屏蔽中断由 I/O 设备产生，可用 IF 标志或对中断控制器编程屏蔽；不可屏蔽中断由硬件故障等紧急事件引起 | 关中断能不能屏蔽它 |
| RTC 与 OS 时钟 | RTC 是电池供电的时钟芯片，提供最原始的计时标准；OS 时钟由主板定时/计数芯片产生，开机有效，由操作系统控制 | 关机断电后还走不走 |
| 用户级线程与内核级线程 | 调度者、切换速度、系统调用阻塞范围、CPU 时间分配单位都不同 | 内核是否感知线程的存在 |
| 进程与线程 | 进程是拥有资源的基本单位；线程是独立调度和分派的基本单位，只拥有少量必需资源 | 谁拥有资源，谁被调度 |
| 整型信号量与记录型信号量 | 整型信号量靠循环空转，存在忙等；记录型信号量用阻塞队列和 block、wakeup，实现让权等待 | 申请不到资源时是否占着 CPU |
| 互斥与同步 | 互斥约束同一时刻只能有一个执行者进入临界区；同步约束进程之间的先后次序 | 争同一资源还是讲执行次序 |
| 临界资源与临界区 | 临界资源是必须以互斥方式访问的共享资源；临界区是访问它的那段代码 | 说的是资源还是代码 |
| 管程的 signal 与信号量的 signal | 管程的条件变量队列为空时 signal 不产生任何结果；信号量的 signal 一定给 value 加 1 | 有没有计数值 |
| 直接通信与间接通信 | 直接通信由发送程序把消息直接发送给目标进程；间接通信经信箱等共享数据结构暂存消息 | 中间有没有信箱一类的实体 |

## 简答答题模板

**线程与进程的关系**

五个角度各一句：资源和调度上线程是程序执行的基本单位、进程是拥有资源的基本单位；地址空间上不同进程相互独立、同一进程的各线程共享同一地址空间；通信上进程间必须用操作系统的通信机制、同一进程的线程可直接读写全局变量；并发性上多进程、多线程以及同一进程内的多个线程都可并发执行；系统开销上进程的创建撤销与上下文切换开销远大于线程。

**多道环境下进程的两种关系与进程同步的两个任务**

两种关系：资源共享关系和相互合作关系，合作进程也可能同时存在资源共享关系。两个任务：对资源共享关系的进程保证以互斥方式访问临界资源；对合作关系的进程保证协调执行。

**进程与程序的区别和联系**

区别三条：程序静态、进程动态；程序永久、进程暂时；存在实体不同。联系两条：进程是程序的一次执行，总对应至少一个程序；一个程序可以对应多个进程。

**进程的特征**

五条各一句：并发性、动态性、独立性、异步性、结构特征。

**什么是线程，为什么引入线程**

线程是进程中的一个实体，是被系统独立调度和分派的基本单位，只拥有程序计数器、一组寄存器和栈。引入原因是进程既是独立执行的基本单位又是资源拥有者，创建、撤销和切换开销大，限制了进程数与切换频率。

**实现进程互斥的基本原理**

把访问临界资源的那段代码划为临界区，在临界区前加进入区、后加退出区；进入区检查能否进入并对临界区加锁，退出区释放访问权；用同步机制保证任一时刻只有一个进程进入临界区。

**单重中断的处理过程**

四步按顺序：关闭中断并保护断点；转中断处理程序保护现场；按中断向量查表得到入口地址并执行中断处理子例程；恢复现场、开中断，返回断点继续执行。

**时钟中断信号如何产生，时钟驱动程序的功能**

产生：晶振产生固定频率脉冲，每来一个脉冲计数器减 1，减到 0 时产生一次时钟中断信号，保持寄存器的值再次送计数器。功能四项：维护日期和时间；递减当前进程时间片的剩余执行时间并检查是否为零；对 CPU 使用情况记账；递减报警计数器。

**操作系统在什么时候创建进程，如何创建**

时机四种：用户登录、作业调度、提供服务、应用请求。步骤四步：申请空白 PCB、分配资源、初始化进程控制块、插入就绪队列。
