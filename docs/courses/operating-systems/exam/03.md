## 必背名词

| 术语 | 必背一句话 | 常考 |
| --- | --- | --- |
| 进程调度 | 按照某种策略和算法从就绪态进程中为当前空闲的 CPU 选择在其上运行的新进程 | 单选、简答 |
| 周转时间 | 从作业被提交给系统开始到作业完成为止的时间间隔，包括外存后备队列等待、就绪队列等待、CPU 执行、等待 I/O 四部分 | 综合、简答 |
| 带权周转时间 | 作业的周转时间 $T$ 与系统为它提供的服务时间 $T_s$ 之比，即 $W=T/T_s$ | 综合 |
| 服务时间 | 一个作业在 CPU 上执行的总时间 | 综合 |
| 响应时间 | 从用户提交一个请求开始直至系统首次产生响应为止的时间，包括输入传送、处理机处理、响应回送三部分 | 单选、简答 |
| 截止时间 | 某个任务必须开始执行的最迟时间，或必须完成的最迟时间 | 单选 |
| 吞吐量 | 单位时间内完成的作业数 | 单选、填空 |
| 时间片 | 一个较小的时间元，通常为 $10 \sim 100\ ms$ | 单选 |
| 静态优先权 | 在创建时确定，在进程的整个运行期间保持不变 | 单选 |
| 动态优先权 | 进程创建时被赋予的优先权，随进程的推进或随其等待时间的增加而改变 | 单选 |
| 饥饿 | 就绪态进程因得不到 CPU 而等待的状态，优先权调度下低优先权进程可能无穷等待 | 单选 |
| 老化 | 逐渐增加在系统中等待时间很长的进程的优先权，使低优先权进程获得 CPU | 单选、简答 |
| 松弛度 | $L=D-t-R$，用来表示一个实时进程的紧迫程度 | 单选 |
| 死锁 | 由于多个进程竞争共享资源而引起的进程不能向前推进的僵死状态 | 简答、填空 |
| 安全状态 | 系统能找到一个进程执行序列，按此序列为每个进程分配资源都能顺利完成 | 简答 |
| 资源分配图 | 圆圈代表进程，方框代表一类资源，方框中的小圆圈代表一个资源，请求边由进程指向方框 | 单选 |
| 死锁定理 | S 为死锁状态的充分条件是当且仅当 S 状态的资源分配图是不可完全简化的 | 填空、单选 |

## 必背清单

**第 1 节**

1. 【考纲 1.1】进程调度功能由操作系统内核的进程调度程序完成，功能是按照某种策略和算法从就绪态进程中为当前空闲的 CPU 选择在其上运行的新进程。
2. 【考纲 1.2】引起进程调度的五个时机：进程运行结束、进程阻塞、中断返回、支持抢占式调度的系统中有比当前运行进程优先级更高的进程到来、当前运行进程的时间片用完。

**第 2 节**

3. 【考纲 2.1】选择调度方式和算法的五条准则：周转时间短、响应时间快、截止时间的保证、系统吞吐量高、处理机利用率好。
4. 【考纲 2.1】周转时间包括四部分：作业在外存后备队列上等待调度、进程在就绪队列上等待进程调度、进程在 CPU 上执行、进程等待 I/O 操作完成。
5. 【考纲 2.1】响应时间包括三部分：请求信息从输入设备传送到处理机、处理机对请求信息进行处理、响应信息回送到终端显示器。

**第 3 节**

6. 【考纲 2.2】平均周转时间 $T=\frac{1}{n}\sum_{i=1}^{n}T_i$；带权周转时间 $W=T/T_s$，平均带权周转时间 $W=\frac{1}{n}\sum_{i=1}^{n}\frac{T_i}{T_s}$。
7. 【考纲 2.2】算例：3 个进程在 0、1、2 时刻进入、运行时间为 24、3、3。FCFS 与不可抢占的短进程优先同解：0 时刻只有 P1 就绪，仍先执行 P1[0,24)，再 P2[24,27)、P3[27,30)，周转时间为 24、26、28，平均 26，平均带权周转时间约 6.33。若允许抢占（剩余时间最短优先），执行顺序变为 P1[0,1)、P2[1,4)、P3[4,7)、P1[7,30)，平均周转时间 12.67、平均带权周转时间 1.31。

**第 4 节**

8. 【考纲 2.3】FCFS 从就绪队列的队首选择最先到达就绪队列的进程；适合长进程和 CPU 繁忙型进程，不利于短进程和 I/O 繁忙型进程。
9. 【考纲 2.3】SPF 从就绪队列中选择估计运行时间最短的进程，能降低平均等待时间、提高系统吞吐量；三个缺陷是对长进程不利、不能保证紧迫进程的及时处理、长短由用户估计。
10. 【考纲 2.3】优先权的内部定义用时间极限、内存要求、打开文件的数量、平均 I/O 服务时间与平均 CPU 服务时间之比等可测量数据计算；外部优先权按进程的重要性、支付费用的数量等操作系统之外的准则设置。
11. 【考纲 2.3】非抢占式优先权调度中高优先权进程一旦得到处理机就一直运行到完成或主动放弃；抢占式调度在新到进程优先权更高时抢占 CPU，可采用立即抢占或基于时钟中断的抢占。
12. 【考纲 2.3】静态优先权在创建时确定且整个运行期间不变；动态优先权随进程的推进或等待时间的增加而改变。
13. 【考纲 2.3】优先权调度的主要问题是无穷阻塞即饥饿，解决方案之一是老化技术。
14. 【考纲 2.3】时间片轮转把所有就绪进程按先来先服务排成一个队列，每次把 CPU 分配给队首进程并令其执行一个时间片，用完送到队尾。
15. 【考纲 2.3】时间片大小的三个决定因素：系统对响应时间的要求、就绪队列中进程的数目、系统的处理能力；响应时间 $T$、进程数 $N$、时间片 $q$ 满足 $T=Nq$。
16. 【考纲 2.3】多级队列把就绪队列分成多个独立队列，进程按内存大小、优先权或类型被永久分配到一个队列，各队列优先权与调度算法都可能不同，进程在被撤销前不会移动；优点是开销低，缺点是不够灵活、低优先权进程会饥饿。
17. 【考纲 2.3】多级反馈队列设多个优先权不同的队列、时间片成倍增长，队列优先权越高时间片越短；新进程先插入最高优先权队列，仅当高优先权队列空时才调度次之的队列，同一队列内用时间片轮转，用 CPU 过多的进程降到低队列、等待过长的进程升到高队列，靠老化阻止饥饿。

**第 5 节**

18. 【考纲 2.4】实现实时调度应具备四个条件：提供必要的调度信息、系统处理能力强、采用抢占式调度机制、具有快速切换机制。
19. 【考纲 2.4】调度程序需要的五类信息：就绪时间、开始截止时间和完成截止时间、处理时间、资源要求、优先级；系统中实时进程的优先权不能动态降低。
20. 【考纲 2.4】单处理机情况下的可调度条件 $\sum_{i=1}^{m}\frac{C_i}{P_i} \leqslant 1$；n 个处理机时为 $\sum_{i=1}^{m}\frac{C_i}{P_i} \leqslant n$。
21. 【考纲 2.4】EDF 根据开始截止时间确定优先级，截止时间越早优先级越高，既可用于抢占式调度，也可用于非抢占式调度。
22. 【考纲 2.4】LLF 每次选择松弛度 $L=D-t-R$ 最小的进程；松弛度表示实时进程的紧迫程度。

**第 6 节**

23. 【考纲 2.5】按耦合程度分为紧密耦合与松弛耦合多处理器系统；按结构是否相同分为对称与非对称多处理器系统，非对称系统中只有一个主处理器和有多个从处理器。
24. 【考纲 2.5】对称多处理器的静态分配为每个处理器建专门的就绪队列、进程每次都分到同一处理器，优点是开销小，缺点是不能动态平衡负载；动态分配设公共就绪队列，每次可分配到当时空闲的处理器。
25. 【考纲 2.5】非对称多处理器多采用主—从式，只有主机执行调度程序，从机空闲时向主机发送请求分配进程的信号，主机从就绪队列队首摘下一个进程分配给它。
26. 【考纲 2.5】自调度设公共就绪队列，任一空闲处理器自行选取一个进程或线程运行；优点是易移植、有利于提高 CPU 利用率，缺点是瓶颈问题、低效、线程切换频繁。
27. 【考纲 2.5】成组调度把一组相互合作的进程或线程同时分配到一组处理器上，进程或线程与处理器一一对应；优点是减少线程切换、减少调度开销。
28. 【考纲 2.5】专用处理器分配由 Tucker 于 1989 年提出，在应用程序执行期间专门分配一组处理器、每个线程一个，会造成处理器资源严重浪费，优点是加速运行、避免进程切换。

**第 7 节**

29. 【考纲 3.1】死锁是由于多个进程竞争共享资源而引起的进程不能向前推进的僵死状态。
30. 【考纲 3.2】产生死锁的原因：竞争共享资源且分配资源的顺序不当。
31. 【考纲 3.3】四个必要条件：互斥条件、请求和保持条件、不剥夺条件、环路等待条件，只有四个条件同时满足时才会发生死锁。
32. 【考纲 3.3】互斥条件指一个进程在访问资源的过程中其他进程不能访问该资源，请求者必须被阻塞到资源被释放。
33. 【考纲 3.3】请求和保持条件指进程已保持了至少一个资源又提出新的资源要求，新资源被其他进程占有而阻塞，但对已经获得的资源保持不放。
34. 【考纲 3.3】不剥夺条件指进程已经获得的资源不能被剥夺，只能由进程自己释放。
35. 【考纲 3.3】环路等待条件指存在一个进程申请资源的环形链，链上每个进程都在等待下一个进程占用的资源。

**第 8 节**

36. 【考纲 4.1】处理死锁的四种基本方法：预防死锁、避免死锁、检测并解除死锁、忽略死锁问题。
37. 【考纲 4.1】预防是保证四个必要条件中至少一个不成立；互斥通常不能摒弃，可通过摒弃请求和保持、不剥夺、环路等待三个条件之一来实现。
38. 【考纲 4.1】摒弃请求和保持的两种做法：执行前一次申请整个运行过程所需的全部资源，申请不成功就阻塞；申请其他资源前必须先释放已经分配到的所有其他资源。
39. 【考纲 4.1】摒弃不剥夺的做法：已保持资源的进程再提出新要求而不能立即满足时，必须释放已经保持的所有资源。
40. 【考纲 4.1】摒弃环路等待的做法：给每种资源类型分配唯一整数，进程按编号递增顺序申请，只有 $F(R_j)>F(R_i)$ 时才可申请 $R_j$；缺点是限制新设备增加、造成资源浪费、给用户编程带来麻烦。

**第 9 节**

41. 【考纲 4.2】安全状态指系统能找到一个进程执行序列，只要按此序列为每个进程分配资源，就能保证进程的资源分配和执行顺利完成、不会发生死锁。
42. 【考纲 4.2】不安全状态不一定是死锁状态，但系统进入不安全状态后便可能进入死锁状态；只要处于安全状态就能避免死锁。
43. 【考纲 4.2】算例：3 个进程共有 12 个 R 类资源，最大需求为 10、4、9，已分配为 5、2、2、可用为 3 时存在安全序列 $\langle p2, p1, p3 \rangle$。

**第 10 节**

44. 【考纲 4.2】银行家算法由 Dijkstra 于 1965 年提出，思想是进程提出请求后先试分配，再检测试分配后系统是否处于安全状态，安全则按试分配方案分配，否则不分配。
45. 【考纲 4.2】四个数据结构：available 一维数组表示各类资源的可用数量，max 与 allocation、need 为二维数组，且 $Need=Max-Allocation$。
46. 【考纲 4.2】试分配的条件是 $request_i \leqslant need_i$ 且 $request_i \leqslant available$，三个式子是 $available=available-request_i$、$allocation_i=allocation_i+request_i$、$need_i=need_i-request_i$。
47. 【考纲 4.2】安全性检测把 work 初始化为当前的 available、finish 全部置为 false，反复找满足 $finish[i]=false$ 且 $need_i \leqslant work$ 的进程，令 $work=work+allocation_i$ 并置 $finish[i]=true$；所有 finish 都为 true 才安全。

**第 11 节**

48. 【考纲 4.3】何时调用检测算法取决于两个因素：死锁可能发生的频率、死锁发生时受影响的进程数量。
49. 【考纲 4.3】资源分配图用圆圈代表进程、方框代表一类资源、方框中的小圆圈代表一个资源，请求边由进程指向方框，分配边始于方框中的一个点。
50. 【考纲 4.3】死锁定理：S 为死锁状态的充分条件是当且仅当 S 状态的资源分配图是不可完全简化的。
51. 【考纲 4.3】解除死锁的两个途径：终止处于死锁状态的进程、抢占死锁进程占有的资源；终止可以一次终止全部，也可以一次只终止一个直到死锁解除，原则上选择终止代价最小的进程。

## 易混对照

| 对照项 | 区别 | 判断依据 |
| --- | --- | --- |
| 周转时间与响应时间 | 周转到作业完成为止，含四部分；响应到系统首次产生响应为止，含三部分 | 计时终点是完成还是首次响应 |
| 周转时间与带权周转时间 | 带权周转时间要除以服务时间做归一 | 是否除以 $T_s$ |
| 抢占式与非抢占式 | 新到高优先权进程能否立即剥夺当前进程的 CPU | 高优先权进程到来时是否立刻切换 |
| 立即抢占与基于时钟中断的抢占 | 前者一收到触发信号立刻剥夺，后者等最近一次时钟中断 | 切换发生在信号到达时还是时钟中断时 |
| 静态优先权与动态优先权 | 前者运行期间不变，后者随推进或等待时间改变 | 优先权值在运行中是否变化 |
| 多级队列与多级反馈队列 | 多级队列中进程被永久固定在一个队列，多级反馈队列可在队列间移动 | 进程会不会换队列 |
| 时间片过大与过小 | 过大退化为 FCFS，过小则切换开销大增 | 切换开销占 CPU 时间的比例 |
| EDF 与 LLF | EDF 比开始截止时间，LLF 比松弛度 | 比较的是截止时刻还是截止前余量 |
| 饥饿与死锁 | 饥饿可只涉及一个进程且不影响其他进程获得资源，死锁必涉及一组竞争资源的进程 | 是否存在等待环 |
| 预防与避免 | 预防静态地破坏必要条件，避免在分配前动态判断安全性 | 是否先试分配再检测安全状态 |
| 避免与检测 | 避免用最大需求判断试分配后的风险，检测查当前实际请求与已分配 | 依据最大需求还是当前请求 |
| 安全状态与不安全状态 | 安全必有安全序列；不安全只是无法保证，不等于已经死锁 | 能否找到安全序列 |

## 简答答题模板

**进程调度的功能是什么**

两点：由操作系统内核的进程调度程序完成；功能是按照某种策略和算法从就绪态进程中为当前空闲的 CPU 选择在其上运行的新进程。

**引起进程调度的时机有哪些**

五条并列：进程运行结束；进程阻塞；中断返回；支持抢占式调度的系统中有比当前运行进程优先级更高的进程到来；当前运行进程的时间片用完。

**什么是死锁，引起死锁的原因是什么**

先下定义：由于多个进程竞争共享资源而引起的进程不能向前推进的僵死状态。再写原因一句：竞争共享资源且分配资源的顺序不当。可按需补一句进程按申请、访问、释放的顺序使用资源。

**死锁的四个必要条件**

四条各一句：互斥条件是资源在被访问时其他进程不能访问；请求和保持条件是已保持至少一个资源又提出新请求而被阻塞，且对已获得资源保持不放；不剥夺条件是已获得的资源不能被剥夺、只能由进程自己释放；环路等待条件是存在一个进程申请资源的环形链。收尾点明四个条件必须同时满足。

**银行家算法怎样判断系统是否安全**

按步骤答：先算 $Need=Max-Allocation$；试分配要满足 $request_i \leqslant need_i$ 且 $request_i \leqslant available$；执行三式后令 $work=available$、finish 全为 false；反复找 $finish[i]=false$ 且 $need_i \leqslant work$ 的进程，令 $work=work+allocation_i$、$finish[i]=true$；全部 finish 为 true 则安全并给出安全序列，否则不安全、取消试分配。

**死锁的预防有哪几种做法**

先总述一句：预防就是让四个必要条件至少有一个不成立。然后分三条：摒弃请求和保持，执行前一次申请全部资源或申请前释放已有资源；摒弃不剥夺，新请求不能满足时释放已保持的全部资源；摒弃环路等待，按资源编号递增顺序申请。收尾补一句，互斥条件通常没法摒弃。

**解除死锁有哪些途径**

两个途径：终止处于死锁状态的进程，系统回收其占有的资源；抢占死锁进程占有的资源，直到死锁环被打破。终止可一次终止全部或一次终止一个；抢占要处理抢占对象、回滚和饥饿三个问题。

**时间片轮转调度算法的时间片大小怎样确定**

三个因素：系统对响应时间的要求，响应时间越短时间片取值越小；就绪队列中进程的数目，时间片与系统允许的最大进程数成反比；系统的处理能力，要保证基本命令能在一个时间片内执行完。可补一句极端情况：时间片过大退化为 FCFS，过小则切换开销过大。
