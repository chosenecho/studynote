**8. P2 逐章评审**

评审单元是一章三页：`chapter-NN.md`、`exam/NN.md`、索引卡。三页分开评会把"必背清单漏条目"这类缺陷切碎，合在一起看才能对上大纲条目、教材节次与真题命中。

每章一张评审卡，字段固定：

| 字段 | 内容 |
| --- | --- |
| 章节 | 课程、章号、标题、字节数与指纹 |
| 大纲条目 | `scope` 条数、`objectives` 条数、层次分布 |
| 教材依据 | 成书章/小节、页序或行范围、复制的快照路径与 SHA-256 |
| 真题命中 | 近五年题号数与分值合计、涉及考点标签数 |
| 六维评级 | D1 至 D6 各一级与一句理由 |
| 缺陷条目 | 编号、位置（文件与行）、描述、证据、级别（S1 至 S5）、处置 |
| 复算记录 | 算式清单、输入、脚本输出、是否一致 |
| 签核 | 核对日期、核对方（本人或脚本 + 人工确认） |

批次顺序按风险排，不按课程编号排：

| 批次 | 课程 | 章数 | 排序理由 |
| --- | --- | --- | --- |
| 1 | 多媒体技术及应用 | 9 | 草稿状态、软件未实测、真题只有一套，先暴露问题 |
| 2 | 计算机网络技术 | 9 | 大纲条目最细（50 条 `objectives`、68 节、67 题），覆盖矩阵最能检验口径 |
| 3 | 操作系统概论 | 6 | 无 `objectives`，需边补条目层边评；算式题多，依赖 `arithmetic.py` |
| 4 | 计算机组成原理 | 6 | 无 `objectives`，计算密集且与 OS 有跨课对照表，放最后用已校准的口径 |

批 1 开工前先把多媒体的 9 个 JSONL 记录读进来，按 `chapter_refs` 与题号排到各章，作为对照基线：站点第 N 章的练习与必背清单里，凡是与这 96 道题同考点的，逐条比较"记录里的状态"与"笔记里的表述"。记录标阻断的考点，笔记不得写成确定知识；记录标待审的答案，笔记的答案要注明自编。

每章动作顺序：读大纲条目与层次 → 对照成书定位事实与数值 → 核对应试导航的必背清单是否覆盖条目 → 复核练习条件与答案 → 查真题命中与声称锚点 → 按六维打级 → 写卡片。全量对教材，不抽样：30 章加 225 节是可以逐节做完的规模，抽样会把"某节整段无教材依据"这类缺陷漏掉。真题侧才抽样，见 P3。

证据放 `local/reviews/2026-11-16-content-eval/`（该目录整体被忽略提交）：`cards/<course>-<NN>.md`、`crosswalk/<course>-<NN>.json`、`arithmetic-log.json`。公开只发行统计与结论，卡片不发布。

复核方式：单人维护的项目不设第二评审人，用两件事替代。一切数值走脚本复算；一切事实走"成书 + 题库"双检索，检索不到就记缺口，不凭记忆补。写进卡片的每条判断都要带位置，位置写不出就降级为待核。

**9. P3 真题映射**

映射文件放 `config/exam-map.json`，公开可提交。它只含题号与标签，不含题干、选项、答案原文，符合[内容贡献规则](../content-policy.md) 对短考点标签的边界。

```json
{
  "version": 1,
  "basis": "题库 48 套试卷；题号取自 papers.question_numbers；只存题号与标签，不含题干与答案原文",
  "courses": [
    {
      "code": "02323",
      "library": "题库/02323_操作系统概论",
      "papers": [
        {
          "paper_id": "2021-04_02323_真题_49136",
          "period": "2021-04",
          "version_note": "出版后",
          "questions": [
            {
              "question_id": "02323-2021-04-Q01",
              "question_no": 1,
              "type": "单选",
              "points": 1,
              "chapter_refs": [1],
              "section_refs": [4],
              "topic_tags": ["内存管理功能"],
              "syllabus_level": "识记",
              "review_status": "source-checked"
            }
          ]
        }
      ]
    }
  ]
}
```

字段沿用前序台账的命名（`question_id`、`chapter_refs`、`review_status` 等），避免两套叫法。`review_status` 取 `source-checked`、`mapping-pending`、`blocked-pending-source` 三值，含义与多媒体台账一致。

打标四步：

1. 拆题。`papers.question_numbers` 已给出每卷题号数组，逐卷生成空记录，题型与分值按卷一、二的题干抄登。题号 ID 直接写成 `02323-2021-04-Q01` 形式。
2. 初判。用 `题库.sqlite3` 的 `search` 表（fts5 trigram）按术语检索，把候选题号与所在页缩小到个位数。
3. 定章定节。人工读候选题，落到本章的 `scope` 编号与 `objectives` 编号；跨章引用记 `chapter_refs` 数组，不重复计数。
4. 登记状态。按上列三值登记。两个 `source_pending` 题（02318-2024-04-Q07、02318-2024-10-Q28）照台账标注，不得用于自动判分，也不作为笔记答案的唯一依据。

多媒体不重做拆题：2023-04 福建卷的 33 题已有 29 条 `source-checked` 记录，直接导入，只补 Q6、Q16、Q19、Q25 的 `mapping-pending`。该卷没有 OCR 文本、只有 3 页原图，映射以原图页码为证据。

统计口径：

- 近五年指 2020-08 起，含 2020-08 与 2020-10 两个特殊考期；出版前卷与出版当年卷单列，不混入主线比例。
- 覆盖率 = 命中考点标签在必背清单或练习中出现的比例；同时报反向缺口 = 高频考点（近五年出现 3 次以上）未能覆盖的清单。
- 多媒体只有 2023-04 一套，结论写成"可能考"的标注，不写稳定考点，也不据此抬高覆盖率。
- 不做命题预测。真题只用来定侧重与校验覆盖，不在站点标作真题或官方答案。

交付：`artifacts/eval/exam-coverage.md`（可公开的数字与缺口清单）、`config/exam-map.json`、反向缺口的修复任务并入 P4。

**14. 开工条件与顺序**

1. 先把本计划合入（单独 doc 提交），再开始 P0。
2. P0 完成后立刻跑一次 `check:content` 的空转，确认新检查器在未修改内容时全绿，作为后续对比基线。
3. 批 1 先做多媒体第 1 章与第 4 章两章试评，校准卡片字段与评级尺度，再扩展到九章。
4. 试评若发现口径要改，先改本计划再继续，不在评审中途换标准。

本计划未估算工时，只给顺序与相对规模。每批的完成度以表格验收，不以章节数推算进度。
